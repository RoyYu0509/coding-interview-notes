01 · Hash Table / Counting

主线: Hash Table 用 O(n) 空间记住 "见过什么", 把 "内层循环里找一个东西" 换成一次 O(1) 的查表。用法只有四种: 查另一半、数频率、算 key 分组、用 set 查在不在。

概念链: Two Sum (查 complement) → Contains Duplicate II (dict 记最近下标) → Valid Anagram (频率表, [0]*26) → First Unique Character (先数完再按顺序查) → Group Anagrams (canonical key 分组) → Longest Consecutive Sequence (set 换排序, 只从起点数)

0. 第一性原理: brute force 在浪费什么

以 Two Sum 为例。brute force 是双层循环: 对每个 x, 把前面所有元素扫一遍, 看有没有 target − x。时间 O(n²), 空间 O(1)。

浪费在哪: 内层循环每次都在 重新找同一批东西。第 4 个数扫了前 4 个数, 第 5 个数又把这 4 个数扫了一遍, 前面看过的信息全丢了。Hash Table 的做法: 看过的东西存进 dict, 以后要找 "有没有 y" 就是一次 y in seen, 平均 O(1)。内层循环消失, 时间从 O(n²) 降到 O(n), 代价是 O(n) 额外空间。

模板只有 4 种。后面每一题都是其中一种加一个小变化:

# 模板 A: complement lookup —— 边走边查 "我要的另一半见过没"seen = {} # seen: 已经走过的东西 (key -> 需要的信息, 比如下标)for i, x in enumerate(nums): need = f(x) # 由当前 x 算出 "另一半" 长什么样 if need in seen: # O(1) 查表, 取代 O(n) 的内层扫描 ... # 命中: 用 seen[need] 和 i 算答案 seen[x] = i # 查完再存: 保证 seen 里只有 i 之前的元素# 模板 B: 频率表 —— 数一遍, 之后随便问 "x 出现几次"cnt = Counter(s) # 或 [0] * 26 (key 只有小写字母时)# 模板 C: canonical key 分组 —— 同一组的东西算出同一个 keygroups = defaultdict(list)for w in words: groups[key(w)].append(w) # key(w) 必须 hashable: str / tuple, 不能是 list# 模板 D: set 换掉排序 —— 只问 "在不在", 不关心顺序s = set(nums)if x - 1 in s: ... # O(1)

记:Hash Table = 拿空间换掉一层循环。看到 "在内层循环里找某个东西" 就问: 能不能把它提前存进 dict / set?

1. Two Sum: 边遍历边查 complement

题目: 数组 nums 和整数 target, 返回和为 target 的两个下标。例: nums = [3, 8, 5, 2, 7], target = 9 → [3, 4] (2 + 7)。

Brute force: 双层循环枚举所有 pair, O(n²) 时间, O(1) 空间。浪费: 对每个 x, 都在重新扫描前面的元素去找 target − x。

关键观察: 一个 pair (j, i) 且 j < i, 只要在轮到 i 时 "往回看" 就能发现。所以只需要保证: 轮到 i 时, seen 里恰好是 nums[0..i−1], 然后查 target − nums[i] 在不在 seen 里。

def two_sum(nums, target): seen = {} # seen: 值 -> 下标, 只装 nums[0..i-1] for i, x in enumerate(nums): need = target - x # 我需要的另一半 if need in seen: # 另一半之前见过 -> 答案 return [seen[need], i] seen[x] = i # 先查后存: 否则 x 会把自己当成另一半 return []

Time: O(n), 一次遍历, 每步 dict 查 / 写平均 O(1)。Space: O(n), seen 最多存 n − 1 个元素。

记:complement lookup: 先算出 "我要的另一半", 查表, 没有再把自己存进去。顺序是先查后存。

2. Contains Duplicate II: dict 记最近一次的下标

相比上一题: 不是找 "和为 target", 而是找 "值相同且下标差 ≤ k"。要查的 "另一半" 就是 同一个值, 而且还要知道它在哪儿, 所以 value 存下标 (Two Sum 就是这个形状)。多出来的一行: 命中判断加距离条件, 以及 每次都覆盖成最新下标。

题目: nums = [1, 2, 3, 1, 3], k = 2 → True (两个 3, 下标 2 和 4, 差 2)。

Brute force: 每个 i 往后看 k 个位置, O(n·k); 浪费: 又是在内层循环里找 "同一个值"。(只问 "有没有重复" 的 Contains Duplicate I 更简单: len(set(nums)) < len(nums)。)

关键观察: 对同一个值, 只有 最近的 那次出现可能满足距离 ≤ k, 更老的只会更远。所以 dict 每个值只留一个下标, 且必须覆盖更新。

def contains_nearby_duplicate(nums, k): last = {} # last: 值 -> 它最近一次出现的下标 for i, x in enumerate(nums): if x in last and i - last[x] <= k: # 最近的一次都不够近, 更老的更不行 return True last[x] = i # 不管有没有命中, 都覆盖成最新下标 return False

Time: O(n)。Space: O(n), last 存所有不同的值。如果把 "最近 k 个" 当滑动窗口, 用 set 装窗口里的值 (i > k 时删掉 nums[i − k − 1]), 空间可以降到 O(k)。

记:dict 里 value 存 "上次出现的下标", 每步都覆盖成最新的; 距离条件只和最近一次比。

3. Valid Anagram: 频率表比较, 小写字母用 [0] * 26

相比上一题: 不再查 "某个值在不在", 而是 数每个字符出现几次, 再比较两张表。key 只有 26 个小写字母, 所以 dict 可以换成 [0] * 26。

题目: s = "anagram", t = "nagaram" → True; s = "rat", t = "car" → False。

Brute force: sorted(s) == sorted(t), O(n log n)。浪费: 排序把字符排成同样的顺序再逐位比, 可是我们只关心 "每个字符有几个", 顺序是白排的。

关键观察: anagram ⇔ 频率表相同。s 的字符 +1, t 的字符 −1, 全部抵消成 0 就是 anagram, 只用一个数组、两个循环。

def is_anagram(s, t): if len(s) != len(t): # 长度不同, 一定不是 return False cnt = [0] * 26 # 小写字母: 下标 = ord(ch) - 97, 不需要 hash for ch in s: cnt[ord(ch) - 97] += 1 # s 里的字符 +1 for ch in t: cnt[ord(ch) - 97] -= 1 # t 里的字符 -1: 同样多就刚好抵消 return not any(cnt) # 全部抵消成 0 <=> 频率表相同# 字符集不固定 (Unicode / 任意 hashable): 换成 Counter# return Counter(s) == Counter(t)

Time: O(n)。Space: O(1), 数组固定 26 格, 和 n 无关 (字符集不固定时是 O(字符种类数))。

记:频率表比较: 顺序无关的问题 (anagram、multiset 相等) 都用计数代替 sort。key 范围小而固定 → 数组; 否则 Counter。

4. First Unique Character: 先数完, 再按原顺序查

相比上一题: 频率表还是那张表, 但问题变成 "按原顺序 第一个频率为 1 的"。多了一轮: 数完之后, 要回到原串按下标顺序再扫一遍。

题目: s = "aabc" → 2 (字符 b 只出现一次, 最靠前)。

Brute force: 对每个字符扫整个串数它出现几次, O(n²)。浪费: 同一个字符被重复数了很多次。

关键观察: 一遍扫描回答不了 "这个字符后面还会不会出现"。需要全局信息, 所以拆成两遍: pass 1 数频率, pass 2 按原顺序查表。

def first_uniq_char(s): cnt = Counter(s) # pass 1: 全局频率 (等价于逐字符 cnt[ch] += 1) for i, ch in enumerate(s): # pass 2: 必须按原顺序扫, 才能拿到 "第一个" if cnt[ch] == 1: return i return -1

Time: O(n), 两遍线性扫描。Space: O(1) (小写字母最多 26 种; 一般情况 O(字符种类数))。

记:"第一个 / 唯一 / 出现次数为 X" 且要保持原顺序: pass 1 建频率表, pass 2 按原顺序查。Ransom Note、Majority Element 也是同一张频率表。

5. Group Anagrams: canonical key 分组

相比上一题: 频率表不是拿来 "问" 的, 而是变成 dict 的 key。多出来的一行: 给每个元素算一个 key(w), 同组的元素算出同一个 key, groups[key].append(w)。

题目: ["eat", "tea", "tan", "ate", "nat", "bat"] → [["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]。

Brute force: 两两比较是不是 anagram, 再用并查集 / 标记合并: O(n² · k log k) (k = 词长)。浪费: 同组的词被反复比较。

关键观察: 与其比较 "两个词是不是同组", 不如给每个词一个 canonical key (规范形式): 同组的词 key 完全一样。key 一样就进同一个 dict 桶, 分组变成一次遍历。常用的 key 有两种: sorted(w), 或者 26 格计数转成 tuple。

def group_anagrams(strs): groups = defaultdict(list) # key -> 这一组的所有词 for w in strs: key = "".join(sorted(w)) # canonical key: anagram 排序后一定相同 groups[key].append(w) return list(groups.values())# key 的另一种写法, O(k) 而不是 O(k log k):# cnt = [0] * 26# for ch in w: cnt[ord(ch) - 97] += 1# key = tuple(cnt) # list 不能当 key, 转成 tuple

Time: O(n · k log k) (sorted 当 key), 换成计数 tuple 是 O(n · k)。Space: O(n · k), 要存下所有词。

记:"把相同本质的东西分到一组" → 设计 canonical key, 用 defaultdict(list) 分桶。key 必须 hashable: str 或 tuple, 不能是 list。

6. Longest Consecutive Sequence: set 换掉排序, 只从起点开始数

相比上一题: 不分组, 也不数频率, 只问 "某个数在不在", 所以 dict 退化成 set。多出来的一行: 只有 x − 1 不在 set 里的 x 才是序列起点, 只有起点才往右数。

题目: nums = [100, 4, 200, 1, 3, 2] → 4 (序列 1, 2, 3, 4), 要求 O(n)。

Brute force: 先排序再扫一遍是 O(n log n), 题目要求 O(n)。如果改用 set 但让每个数都往右数, 遇到 1..n 这种输入就是 n + (n−1) + … + 1 = O(n²)。浪费: 序列中间的数重复走了好几遍。

关键观察: 一段连续序列只需要从它的 起点 数一次。判断起点只要一次 O(1) 查询: x − 1 in s。这样每个数最多被数一次, 总共 O(n)。

def longest_consecutive(nums): s = set(nums) # O(1) membership, 取代排序 best = 0 for x in s: # 遍历 set 去重, 重复的数不会重复起步 if x - 1 in s: # x 前面还有数 -> x 不是序列起点, 交给起点去数 continue y = x # x 是起点: 一路往右数 while y + 1 in s: y += 1 best = max(best, y - x + 1) return best

Time: O(n)。for 循环 n 次判断; while 总共走的步数 = 每个序列只被起点走一遍 = 至多 n。Space: O(n), set。

记:set 的价值是 O(1) membership, 用它可以换掉 "排序 + 相邻比较"。加一个 "只从起点出发" 的剪枝, 就能把嵌套循环压成线性。

7. 什么时候用 Hash Table 换 Time, 什么时候用数组 [0] * 26

Hash Table 是拿空间换时间。 前面每一题的 "不用 hash" 版本都是下面几种之一:

题不用 hash用 hash
Two Sum双层循环 O(n²) 时间, O(1) 空间O(n) 时间, O(n) 空间
Valid Anagramsort O(n log n)计数 O(n), 26 格 O(1) 空间
Group Anagrams两两比较 O(n² · k log k)算 key + 分桶 O(n · k log k)
Longest Consecutivesort O(n log n)set + 只从起点数 O(n)

什么时候该用数组 [0] * 26 代替 dict:

情况用什么原因
key 是小写字母 / 数字 0-9 / ASCII (128)[0] * 26 等固定数组下标直接寻址, 不用算 hash, 常数更小; 空间固定 O(1)
key 是任意整数 / 字符串 / Unicode, 稀疏dict / Counter数组放不下, 或者绝大多数格子是空的
key 范围是 0..n 的下标 / 值域 (如 First Missing Positive)原数组本身当 hash省掉 O(n) 额外空间, 但会改动输入
只问 "在不在"set不需要 value

什么时候别用 Hash Table: 输入已经排序, 找 pair 用 two pointers 是 O(1) 空间; 需要 "最大 / 最小 / 有序" 用 heap 或排序, hash 不保序; 面试官明确限制额外空间时, 退回排序 + two pointers。

Python 里两个常见的坑: 1. defaultdict 读取不存在的 key 会 插入 它 (下面的例子); 只想查用 in 或 .get()。2. dict 的 key 必须 hashable: list 不行, 转成 tuple。

from collections import defaultdictd = defaultdict(int)if d["a"] == 0: # 只是 "读" 了一下... passprint(len(d)) # 1: 读取也把 "a" 插进去了!# 只想查、不想插: 用 "a" in d 或 d.get("a")

记:key 范围固定又小 → 数组 [0] * K; 其余 → dict。想用空间换时间之前先看: 有没有排序 / 双指针能做到 O(1) 空间。
