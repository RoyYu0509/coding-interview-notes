01 · Hash Table / Counting

这篇讲什么

很多题的 brute force 都长一个样: 外层循环看每个元素, 内层循环再去找某个东西。比如"前面有没有一个数和我加起来等于 target", "这个字符后面还会不会出现"。内层每次都要从头找, 所以是 O(n²)。

Hash Table (Python 里就是 dict 和 set) 能在平均 O(1) 时间里回答"某个 key 在不在, 对应的 value 是什么"。所以思路很简单: 把以后要找的东西提前存进 dict, 内层循环就变成一次查表。时间从 O(n²) 降到 O(n), 代价是 O(n) 的额外空间。

这篇的 6 道题覆盖了 Hash Table 的 4 种用法。区别只在于 key 存什么、value 存什么:

#题目考过的公司数用法 / 相比上一题多了什么
1Two Sum113查"另一半": key 是值, value 是下标。总榜第 1
2Contains Duplicate II12还是查值, 但多了距离条件, value 要随时更新
3Valid Anagram34不查在不在, 改成数次数
4First Unique Character in a String22数完次数, 还要按原来的顺序找
5Group Anagrams75把"本质相同"的东西算成同一个 key, 用来分组
6Longest Consecutive Sequence38只问在不在, 用 set 代替排序

每道题的顺序: 题目在问什么 → 看例子 → brute force → intuition → 算法 → 手动走一遍 → 复杂度。代码放在最后, 默认折叠。

前置知识: 知道 Python 的 dict 和 set 怎么用就够了。

1. Two Sum

题目在问什么

给一个整数数组 nums 和一个整数 target。在数组里找两个不同位置的数, 它们加起来等于 target, 返回这两个位置的下标。题目保证恰好有一个答案。

看例子

Example 2 是一个容易错的点: 3 + 3 = 6, 但数组里只有一个 3, 同一个位置不能用两次。

Brute force: 两两都试

最直接的做法: 每一对 (j, i) 都试一遍, 看 nums[j] + nums[i] 是不是 target。一共大约 n²/2 对, 所以是 O(n²)。

换个角度看这个双层循环: 外层轮到 x = nums[i] 的时候, 内层其实是在前面的数里找一个特定的值, 也就是 target - x。下面左边就是这个"一个一个比"的过程。

浪费在哪: 轮到第 5 个数时, 内层把前 4 个数扫了一遍。轮到第 6 个数时, 又把同样的这 4 个数 (加上第 5 个) 扫了一遍。前面看过的数, 每一轮都重新看。

Intuition: 看过的数存起来

  1. 内层循环要回答的问题是: "前面有没有 target - x?"。
  2. 如果把前面看过的数都存进一个 dict, 这个问题就是一次 need in seen, 平均 O(1)。
  3. 题目要返回下标, 所以 dict 的 key 存值, value 存它的下标。
  4. 每个数先查, 再把自己存进去。顺序不能反: 如果先存再查, x 可能会找到它自己 (Example 2 里 3 就会和自己配对)。

这样每一对 (j, i) 都会在轮到后面那个 i 时被发现。因为那时 j 已经在 dict 里了。

算法

  1. seen = {}。
  2. 从左到右看每个 x = nums[i]。算出 need = target - x。
  3. 如果 need 在 seen 里, 返回 [seen[need], i]。
  4. 否则把 seen[x] = i 存进去, 继续。

手动走一遍

复杂度

Time O(n): 只扫一遍, 每一步查一次、存一次 dict, 都是平均 O(1)。Space O(n): seen 最多存 n - 1 个数。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def two_sum(nums, target): seen = {} # seen: 值 -> 下标, 只装 nums[0..i-1] for i, x in enumerate(nums): need = target - x # 我需要的另一半 if need in seen: # 另一半之前见过 -> 答案 return [seen[need], i] seen[x] = i # 先查后存: 否则 x 会把自己当成另一半 return []

记:找"另一半": 先算出我需要什么, 查 dict; 没有, 再把自己存进去。先查后存。

把第 1 题抽象一下: 什么时候用 Hash Table

Two Sum 的做法可以总结成一句话: 如果你发现自己在循环里反复"找"某个东西, 就把它提前存进 dict 或 set。

剩下要想的只有两件事: key 存什么, value 存什么。后面 5 道题就是这两件事的不同答案:

  • key = 值, value = 下标: 找另一半 (第 1、2 题)
  • key = 字符, value = 出现次数: 数频率 (第 3、4 题)
  • key = 某种"规范形式", value = 一组元素: 分组 (第 5 题)
  • 只有 key, 没有 value (set): 只问在不在 (第 6 题)
四种用法的通用写法
# 模板 A: complement lookup —— 边走边查 "我要的另一半见过没"# seen: 已经走过的东西 (key -> 需要的信息, 比如下标)seen = {}for i, x in enumerate(nums): need = f(x) # 由当前 x 算出 "另一半" 长什么样 if need in seen: # O(1) 查表, 取代 O(n) 的内层扫描 ... # 命中: 用 seen[need] 和 i 算答案 seen[x] = i # 查完再存: 保证 seen 里只有 i 之前的元素# 模板 B: 频率表 —— 数一遍, 之后随便问 "x 出现几次"cnt = Counter(s) # 或 [0] * 26 (key 只有小写字母时)# 模板 C: canonical key 分组 —— 同一组的东西算出同一个 keygroups = defaultdict(list)for w in words: # key(w) 必须 hashable: str / tuple, 不能是 list groups[key(w)].append(w)# 模板 D: set 换掉排序 —— 只问 "在不在", 不关心顺序s = set(nums)if x - 1 in s: ... # O(1)

记:Hash Table = 用空间换掉一层循环。看到"在内层循环里找某个东西", 就问: 能不能把它提前存进 dict / set?

2. Contains Duplicate II

题目在问什么

给一个数组 nums 和一个整数 k。问: 有没有两个不同的位置 i 和 j, 满足 nums[i] == nums[j], 而且 |i - j| ≤ k。也就是: 有没有离得足够近的两个相同的数。

看例子

Example 3 说明了一件事: 两个 1 离得太远不算, 但这不影响后面两个 3 离得够近。

Brute force

每个位置 i, 往后看 k 个位置, 有没有和它相等的。O(n·k)。浪费和 Two Sum 一样: 内层在找"有没有一个和我相同的值"。

Intuition

和 Two Sum 一样, 把看过的数存进 dict, key 是值。区别是这次还要判断距离, 所以 value 存下标。

关键问题是: 同一个值出现了好几次, value 存哪一次的下标? 答案是最近的那一次。因为我们是从左往右扫, 对当前的 i 来说, 越靠后的旧位置离 i 越近。最近的一次都不满足 ≤ k, 更早的那些只会更远。

所以每看到一个数, 不管有没有命中, 都把它的下标覆盖成当前位置。

算法

  1. last = {}, 记每个值最近一次出现的下标。
  2. 从左到右看 x = nums[i]。如果 x 在 last 里, 并且 i - last[x] ≤ k, 返回 True。
  3. last[x] = i (覆盖成最新的)。
  4. 扫完都没有, 返回 False。

手动走一遍

复杂度

Time O(n)。Space O(n), last 存所有不同的值。如果只保留最近 k 个位置的值 (用一个 set, 超出 k 的从 set 里删掉), 空间可以降到 O(k), 这其实就是 sliding window。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def contains_nearby_duplicate(nums, k): last = {} # last: 值 -> 它最近一次出现的下标 for i, x in enumerate(nums): if x in last and i - last[x] <= k: # 最近的一次都不够近, 更老的更不行 return True last[x] = i # 不管有没有命中, 都覆盖成最新下标 return False

记:相同值 + 距离条件: dict 的 value 存"上次出现的下标", 每一步都覆盖成最新的。

3. Valid Anagram

题目在问什么

给两个字符串 s 和 t (小写字母)。问: t 是不是 s 的 anagram。anagram 的意思是: 把 s 的字母换个顺序, 能得到 t。等价的说法: 两个字符串里, 每个字母出现的次数都一样。

看例子

Brute force

把两个字符串都排序, 比较是否相同: sorted(s) == sorted(t)。O(n log n)。

这已经不慢了, 但它做了多余的事: 排序是为了把字母排成同样的顺序再一个一个比。可我们只关心每个字母有几个, 顺序是白排的。

Intuition

直接数次数。给 s 数一张表, 给 t 数一张表, 比较两张表。

可以再省一点: 只用一张表。s 里每个字母 +1, t 里每个字母 -1。如果两个字符串的次数完全一样, 最后每一格都正好抵消成 0。

还有一个常数上的优化: key 只可能是 26 个小写字母, 所以不用 dict, 用一个长度 26 的数组 cnt = [0] * 26, 下标 ord(ch) - 97 就是字母的编号。这其实就是一个"key 是 0..25" 的 Hash Table, 但不用算 hash, 更快。

算法

  1. 长度不同, 直接返回 False。
  2. cnt = [0] * 26。s 的每个字母 +1, t 的每个字母 -1。
  3. 所有格子都是 0, 返回 True; 否则 False。

手动走一遍

复杂度

Time O(n)。Space O(1): 数组固定 26 格, 和 n 无关。字符集不固定 (比如 Unicode) 时用 Counter, 空间是 O(字符种类数)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def is_anagram(s, t): if len(s) != len(t): # 长度不同, 一定不是 return False cnt = [0] * 26 # 小写字母: 下标 = ord(ch) - 97, 不需要 hash for ch in s: cnt[ord(ch) - 97] += 1 # s 里的字符 +1 for ch in t: cnt[ord(ch) - 97] -= 1 # t 里的字符 -1: 同样多就刚好抵消 return not any(cnt) # 全部抵消成 0 <=> 频率表相同# 字符集不固定 (Unicode / 任意 hashable): 换成 Counter# return Counter(s) == Counter(t)

记:和顺序无关的比较 (anagram、两个 multiset 是否相等), 用数次数代替排序。key 范围小而固定, 用数组; 否则用 Counter。

4. First Unique Character in a String

题目在问什么

给一个字符串 s。找到第一个在整个字符串里只出现一次的字符, 返回它的下标。没有就返回 -1。

看例子

Example 2 里 l 是第一个字符, 但它后面还会出现, 所以不算。要知道"后面还会不会出现", 必须看过整个字符串。

Brute force

对每个位置 i, 扫一遍整个字符串, 数 s[i] 出现了几次, 第一个次数为 1 的就是答案。O(n²)。浪费: 同一个字母被重复数了很多次。

Intuition

和第 3 题一样, 先把每个字母的次数数出来。但这里有一个新问题: 要的是按原来顺序的第一个。频率表本身没有顺序信息。

所以分两遍: 第一遍扫完整个字符串, 得到每个字母的次数 (这时才知道谁"后面还会出现"); 第二遍按原来的顺序从左往右扫, 第一个次数为 1 的就是答案。

算法

  1. 第一遍: cnt = Counter(s)。
  2. 第二遍: 从左往右看 s[i], 第一个 cnt[s[i]] == 1 的, 返回 i。
  3. 都没有, 返回 -1。

手动走一遍

复杂度

Time O(n), 两遍线性扫描。Space O(1), 小写字母最多 26 种。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def first_uniq_char(s): # pass 1: 全局频率 (等价于逐字符 cnt[ch] += 1) cnt = Counter(s) for i, ch in enumerate(s): # pass 2: 必须按原顺序扫, 才能拿到 "第一个" if cnt[ch] == 1: return i return -1

记:要"第一个满足某个次数条件的": 第一遍数次数, 第二遍按原顺序查。

5. Group Anagrams

题目在问什么

给一组字符串 strs。把互为 anagram 的字符串放进同一组, 返回所有的组 (组的顺序、组内的顺序都随意)。

看例子

Brute force

两两比较, 用第 3 题的方法判断是不是 anagram, 是的话合并到一组。n 个词有大约 n²/2 对, 每对比较 O(k) (k 是词长), 一共 O(n²·k)。浪费: 同一组里的词被反复互相比较。

Intuition: 给每个词算一个"身份证"

与其问"这两个词是不是同一组", 不如给每个词算一个 key, 让同一组的词算出来的 key 完全一样, 不同组的 key 不一样。这个 key 叫 canonical key (规范形式)。

有了 key, 分组就是 Hash Table: groups[key].append(word)。每个词只处理一次, 不用两两比较。

anagram 的 key 怎么选? 两种常用的:

  • 把词排序: "eat"、"tea"、"ate" 排序后都是 "aet"。每个词 O(k log k)。
  • 数 26 个字母的次数, 转成 tuple: 每个词 O(k)。注意 list 不能当 dict 的 key, 要转成 tuple。

算法

  1. groups = defaultdict(list)。
  2. 对每个词 w: key = "".join(sorted(w)), groups[key].append(w)。
  3. 返回 groups.values()。

手动走一遍

复杂度

Time O(n·k log k) (用排序当 key), 换成计数 tuple 是 O(n·k)。Space O(n·k), 要存下所有的词。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def group_anagrams(strs): groups = defaultdict(list) # key -> 这一组的所有词 for w in strs: key = "".join(sorted(w)) # canonical key: anagram 排序后一定相同 groups[key].append(w) return list(groups.values())# key 的另一种写法, O(k) 而不是 O(k log k):# cnt = [0] * 26# for ch in w: cnt[ord(ch) - 97] += 1# key = tuple(cnt) # list 不能当 key, 转成 tuple

记:要把"本质相同"的东西分组: 设计一个 canonical key, 用 defaultdict(list) 分桶。key 必须是 str 或 tuple, 不能是 list。

6. Longest Consecutive Sequence

题目在问什么

给一个没有排序的整数数组 nums。从里面挑一些数, 它们是连续的整数 (比如 1, 2, 3, 4), 问最多能挑几个。注意这里的"连续"指的是值连续, 不是位置连续。题目要求 O(n) 时间。

看例子

Brute force

最自然的做法是先排序, 再从左往右数最长的一段连续值。这是 O(n log n), 不满足题目要求。

另一种想法: 把所有数放进 set, 然后对每个数 x, 一直往右数 x+1, x+2, ... 在不在 set 里。问题是, 如果数组是 [1, 2, 3, ..., n], 从 1 开始数 n 个, 从 2 开始数 n-1 个, ... 一共 O(n²)。浪费: 序列中间的数被重复数了好几遍。从 2 开始数出来的那一段, 其实是从 1 开始那一段的一部分。

Intuition: 只从起点开始数

一段连续的数只需要数一次, 从它的起点开始数。

怎么判断 x 是不是起点? 看 x - 1 在不在 set 里。在, 说明 x 前面还有数, x 不是起点, 跳过, 让起点去数。不在, x 就是起点, 从它往右数。

这样每个数最多被"往右数"的过程走到一次, 总共 O(n)。

算法

  1. s = set(nums)。
  2. 对 s 里的每个 x: 如果 x - 1 in s, 跳过。
  3. 否则 x 是起点。y = x, 只要 y + 1 in s 就 y += 1。这一段长度是 y - x + 1, 更新 best。

手动走一遍

复杂度

Time O(n): for 循环 n 次, 每次判断 O(1); 所有 while 加起来, 每个数只被它所在那一段的起点走一次, 总共最多 n 步。Space O(n), set。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def longest_consecutive(nums): s = set(nums) # O(1) membership, 取代排序 best = 0 for x in s: # 遍历 set 去重, 重复的数不会重复起步 # x 前面还有数 -> x 不是序列起点, 交给起点去数 if x - 1 in s: continue y = x # x 是起点: 一路往右数 while y + 1 in s: y += 1 best = max(best, y - x + 1) return best

记:set 能在 O(1) 里回答"在不在", 可以用来代替"排序 + 看相邻"。再加上"只从起点出发", 嵌套循环就变成线性。

7. 补充: dict 还是数组, 以及什么时候别用 Hash Table

Hash Table 是用空间换时间。前面每道题, 不用 hash 和用 hash 的对比:

题不用 hash用 hash
Two Sum双层循环 O(n²) 时间, O(1) 空间O(n) 时间, O(n) 空间
Valid Anagram排序 O(n log n)数次数 O(n), 26 格数组 O(1) 空间
Group Anagrams两两比较 O(n²·k)算 key + 分桶 O(n·k log k)
Longest Consecutive排序 O(n log n)set + 只从起点数 O(n)

什么时候用数组代替 dict: key 是小写字母、数字 0-9、ASCII 这种范围小而且固定的, 用 [0] * 26 这样的数组, 常数更小。key 是任意整数或字符串, 用 dict。

什么时候别用 Hash Table: 输入已经排好序, 找 pair 用 two pointers (见 02), 空间是 O(1); 需要"最大、最小、有序", 用 heap 或排序, dict 不管大小顺序; 面试官限制额外空间时, 退回排序。

Python 的一个坑: defaultdict 只要读一个不存在的 key, 就会把它插进去。只想查的时候, 用 in 或 .get()。

defaultdict 的坑 (例子)
from collections import defaultdictd = defaultdict(int)if d["a"] == 0: # 只是 "读" 了一下... passlen(d) # 1: 读取也把 "a" 插进去了!# 只想查、不想插: 用 "a" in d 或 d.get("a")

8. 识别信号: 看到什么, 就想到 Hash Table

题目特征做法complexity
数组里找两个数满足某种关系 (和、差、配对), 不要求有序边扫边查"另一半" (Two Sum)O(n²) → O(n)
"相同的值" + "距离 ≤ k"dict 记最近一次的下标, 每步覆盖O(n·k) → O(n)
"有没有重复"set 一次遍历O(n²) → O(n)
和顺序无关: anagram、字母够不够用 (Ransom Note)数次数, 比较频率表O(n log n) → O(n)
"第一个只出现一次的" / "出现次数最多的"第一遍数次数, 第二遍按原顺序查O(n²) → O(n)
把"本质相同"的东西分组canonical key + defaultdict(list)O(n²) → O(n·k)
只问"某个数在不在", 要求 O(n), 排序太慢set + 只从起点出发O(n log n) → O(n)
key 是小写字母等固定小范围[0] * 26 代替 dict常数更小, 空间 O(1)

一句话: 在循环里反复"找"什么东西, 就把它存进 dict / set。 key 存什么、value 存什么, 决定了它是哪一种题。
