13 · Backtracking

这篇讲什么

有一类题要你列出所有的可能: 所有子集、所有排列、所有和为 target 的组合、所有合法的括号、所有棋盘放法……答案本身就有指数多个, 所以没有"更快"的算法, 只能一个一个生成出来。

问题是怎么系统地生成, 不重复、不遗漏, 而且尽早放弃没有希望的方向。这就是 backtracking (回溯)。

想象你在走一个迷宫, 每到一个岔路口就选一条路走下去; 走不通 (或者到了终点) 就退回上一个岔路口, 换另一条路。所有的选择画出来是一棵树, 叫 decision tree。backtracking 就是在这棵树上做 DFS。

每道 backtracking 题都只要想清楚三件事:

  • path: 目前已经做了哪些选择。
  • choices: 下一步还能选什么。
  • 结束条件: 什么时候 path 是一个完整的答案。

写法也固定: 做选择 (push) → 递归 → 撤销选择 (pop)。

1. Subsets

题目在问什么

给一个数组, 里面的数互不相同。返回它所有的子集 (包括空集和整个数组), 顺序随意, 但不能有重复的子集。

看例子

Brute force

如果数组长度固定是 3, 可以写三层循环 (每层决定一个数选不选)。但长度是变量, 循环的层数写不死。

另一种想法是先生成所有"可能的"序列, 再去重。比如把每个排列都生成一遍再转成 set, 会生成大量重复, 很浪费。

Intuition: 用 recursion 代替"写不死的循环"

recursion 的每一层就相当于一层循环, 层数可以是任意的。画出所有选择:

为了不重复 (不让 [1,2] 和 [2,1] 都出现), 规定只能往后选: 选了第 i 个数之后, 下一个只能从 i+1 往后选。这样每个子集只会按"下标从小到大"的顺序被生成一次。

这棵树上的每个节点都是一个合法的子集 (不只是叶子), 所以每进入一个节点就把 path 记下来。

记下来的时候要 path[:] 复制一份: path 是同一个 list, 后面还会被修改; 不复制的话, 最后答案里全是同一个 (空的) list。

算法

  1. dfs(start): 先把 path[:] 加入答案。
  2. 对 i 从 start 到 n-1: path.append(nums[i]), dfs(i + 1), path.pop()。
  3. 调用 dfs(0)。

手动走一遍

复杂度

Time O(n · 2ⁿ): 2ⁿ 个子集, 每个复制 O(n)。Space O(n) (recursion 深度, 不算输出)。

另一种写法: 每个数"选或不选", recursion 到第 n 层时记录。两种都对。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def subsets(nums): res, path = [], [] def dfs(start): # 每个节点都是答案; 要 copy, path 之后还会变 res.append(path[:]) # 只选 start 之后的: 有 [1,2], 没有 [2,1] for i in range(start, len(nums)): path.append(nums[i]) # 做选择 dfs(i + 1) # 递归: 下一层只能选 i 之后的 path.pop() # 撤销: 兄弟分支要看到干净的 path dfs(0) return res
def subsets(nums): # 另一种写法: 每个元素 "选 / 不选" (二叉树) res, path = [], [] def dfs(i): if i == len(nums): # 每个元素都决定完了, 才是叶子 res.append(path[:]) return dfs(i + 1) # 不选 nums[i]: path 不变 path.append(nums[i]) # 选 nums[i] dfs(i + 1) path.pop() # 撤销 dfs(0) return res

记:列出所有子集 / 组合: start index 只往后选防重复; 每个节点都记录 path[:]。

把第 1 题抽象一下: backtracking 模板

所有 backtracking 题都是这个形状, 只换三样东西: path 里放什么、choices 是什么、什么时候记录答案。

为什么一定要 pop (撤销选择)? 因为整个过程只用一个 path list。从一个分支退回来, 必须把这个分支加进去的东西拿掉, 才能去试下一个分支。

复杂度基本等于 decision tree 的节点数。所以优化的方向只有一个: 剪枝, 尽早发现某个分支不可能有答案, 不往下走 (第 3、5、8 题)。

通用模板代码
def backtrack(path, choices): if is_done(path): # 1. 结束条件: path 已经是一个完整答案 res.append(path[:]) # 必须 copy: path 还会继续被改 return for c in choices: # 2. choices: 此刻还能选什么 if not valid(path, c): # 约束剪枝: 这个选择一定走不通, 不进去 continue path.append(c) # 3. 做选择 backtrack(path, next_choices(path, c)) # 4. 递归: 树往下一层 path.pop() # 5. 撤销选择: path 回到 "做选择之前"

记:backtracking = decision tree 上的 DFS。做选择 → 递归 → 撤销选择。记录答案时复制 path。

2. Permutations

题目在问什么

给一个数组, 里面的数互不相同。返回所有的排列: 每个数恰好用一次, 顺序不同就算不同的排列。

看例子

Brute force

同样是循环层数写不死的问题。

Intuition: 每一层都从头选, 跳过已经用过的

和 Subsets 的区别: 排列和顺序有关, [1,2] 和 [2,1] 是两个答案。所以不能再用 start index 规定"只往后选", 每一层都要从头看所有数。

但同一个数不能用两次。用一个 used 数组记录哪些数已经在 path 里了, 选的时候跳过它们。

答案只在叶子上: path 的长度等于 n 时才是一个完整的排列。

算法

  1. dfs(): 如果 len(path) == n, 记录 path[:], 返回。
  2. 对每个 i: 如果 used[i], 跳过。否则 used[i] = True, push, dfs(), pop, used[i] = False。

手动走一遍

复杂度

Time O(n · n!), Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def permute(nums): res, path = [], [] used = [False] * len(nums) # used[i]: nums[i] 已在 path 里, O(1) 判断 def dfs(): if len(path) == len(nums): # 每个位置都填好了 res.append(path[:]) return for i in range(len(nums)): # 每一层都从头看: 排列允许先选后面的元素 if used[i]: # 剪枝: 已经用过的不能再用 continue used[i] = True # 做选择: 两个状态一起改 (path 和 used) path.append(nums[i]) dfs() path.pop() # 撤销: 两个状态一起还原 used[i] = False dfs() return res

记:排列: 每层从头选, used 跳过已选的; 长度满了才记录。

3. Combination Sum

题目在问什么

给一个数组 candidates (互不相同) 和 target。从中选一些数, 让它们的和等于 target。同一个数可以选任意多次。返回所有不同的组合 (组合不看顺序)。

看例子

Brute force

生成所有可能的多重集合, 检查和。不知道每个数要选几次, 没法列举。

Intuition: 和 Subsets 一样, 只改一个下标

组合不看顺序, 所以和 Subsets 一样用 start index 防止重复。

区别在于同一个数可以重复选: 选了 candidates[i] 之后, 下一层仍然可以从 i 开始选 (而不是 i+1)。所以递归时传 i。

用 remain 记录还差多少。remain == 0 就找到一个答案; remain < 0 就没希望了, 直接返回。

剪枝: 先把 candidates 排序。如果当前的 candidates[i] > remain, 它后面的更大, 都不用试了, 直接 break。

算法

  1. 排序。dfs(start, remain): remain == 0 就记录。
  2. 对 i 从 start 开始: candidates[i] > remain 就 break。否则 push, dfs(i, remain - candidates[i]), pop。

手动走一遍

复杂度

Time 是 decision tree 的大小, 上界大约 O(n^(target / min))。Space O(target / min)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def combination_sum(candidates, target): # 排序: 一旦 c > remain, 后面更大的也不行, 可以 break candidates.sort() res, path = [], [] def dfs(start, remain): # remain = target - sum(path), 不用每次重算 sum if remain == 0: # 结束条件: 刚好凑够 res.append(path[:]) return for i in range(start, len(candidates)): c = candidates[i] if c > remain: # 剪枝: 超了; 排过序, 后面的更大, 直接 break break path.append(c) dfs(i, remain - c) # 关键: 传 i (不是 i+1) => 同一个数可以重复选 path.pop() dfs(0, target) return res

记:可以重复选: 递归传 i; 不能重复选: 传 i + 1。排序后可以用 break 剪枝。

4. Combination Sum II

题目在问什么

和第 3 题类似, 但有两个不同: candidates 里可能有重复的数; 每个位置上的数最多用一次。返回所有不同的组合。

看例子

难点: 数组里有两个 1, 用第一个 1 和用第二个 1 得到的组合是一样的, 只能输出一次。

Brute force

像 Subsets 那样生成所有组合, 再用 set 去重。会生成很多重复的分支, 浪费时间。

Intuition: 同一层不选两次同样的值

先排序, 让相同的数挨在一起。

重复是怎么产生的? 在 decision tree 的同一层 (同一个位置上), 先选了第一个 1, 后来又选了第二个 1, 这两个分支下面长出来的东西完全一样。

所以规则是: 同一层里, 如果当前的数和前一个数相同, 就跳过。写成代码就是 if i > start and nums[i] == nums[i-1]: continue。

注意是 i > start, 不是 i > 0: 不同层选同样的值是可以的, 比如 [1,1,6] 里两个 1 在不同的层。

每个数只能用一次, 所以递归传 i + 1。

算法

  1. 排序。dfs(start, remain): remain == 0 就记录。
  2. 对 i 从 start 开始: i > start and nums[i] == nums[i-1] 就 continue; nums[i] > remain 就 break。
  3. push, dfs(i + 1, remain - nums[i]), pop。

手动走一遍

复杂度

Time O(2ⁿ · n) 上界, Space O(n)。Subsets II、Permutations II 都用同样的去重方法。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def combination_sum2(candidates, target): # 排序: 相同的数挨在一起, 才能 "和前一个比" 去重 candidates.sort() res, path = [], [] def dfs(start, remain): if remain == 0: res.append(path[:]) return for i in range(start, len(candidates)): if i > start and candidates[i] == candidates[i - 1]: continue # 同一层已试过这个值, 子树一样 c = candidates[i] if c > remain: break path.append(c) dfs(i + 1, remain - c) # 每个数只能用一次 => 传 i + 1 path.pop() dfs(0, target) return res

记:输入有重复、输出要去重: 先排序, 同一层 if i > start and nums[i] == nums[i-1]: continue。

5. Generate Parentheses

题目在问什么

给 n, 生成所有由 n 对括号组成的合法括号字符串。合法: 每个 ( 都有对应的 ), 而且从左往右读的时候, 任何时刻 ) 的个数都不超过 (。

看例子

Brute force

生成所有长度 2n 的 ( 和 ) 组成的字符串 (2^(2n) 个), 再一个一个检查是否合法。n = 3 时要生成 64 个, 只有 5 个合法。

Intuition: 只往合法的方向走 (剪枝)

与其先生成再检查, 不如在生成的过程中就保证合法。每一步只有两种选择: 加 ( 或者加 )。

  • 加 ( 的条件: 已经用的 ( 少于 n 个 (open < n)。
  • 加 ) 的条件: 已经用的 ) 少于 ( (close < open)。否则 ) 会比 ( 多, 一定不合法。

满足这两个条件, 生成出来的每个字符串都是合法的, 不需要再检查。这就是剪枝: 在走进一个分支之前就判断它有没有希望。

算法

  1. dfs(open, close): 长度到 2n, 记录。
  2. open < n: 加 (, dfs(open + 1, close), 撤销。
  3. close < open: 加 ), dfs(open, close + 1), 撤销。

手动走一遍

复杂度

Time 和答案个数成正比 (Catalan 数, 大约 4ⁿ / n^1.5)。Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def generate_parenthesis(n): res, path = [], [] def dfs(open_, close): # open_ / close: path 里已有的 ( 和 ) 的个数 if len(path) == 2 * n: res.append("".join(path)) return if open_ < n: # 剪枝 1: ( 最多 n 个 path.append("(") dfs(open_ + 1, close) path.pop() if close < open_: # 剪枝 2: ) 不能比 ( 多, 否则前缀已经不合法 path.append(")") dfs(open_, close + 1) path.pop() dfs(0, 0) return res

记:有约束的生成: 在 push 之前就检查约束, 只走合法的分支, 不要先生成再过滤。

6. Letter Combinations of a Phone Number

题目在问什么

手机键盘上, 2 对应 abc, 3 对应 def, ……, 9 对应 wxyz。给一串数字 (2–9), 返回它能表示的所有字母组合。

看例子

Brute force

每一位一层循环, 但位数不固定, 循环层数写不死。

Intuition: 第 i 层的选项由第 i 个数字决定

这是最直接的 backtracking: decision tree 的第 i 层, 选项就是第 i 个数字对应的那几个字母。path 长度等于数字个数时, 就是一个答案。

和前面的题不同, 这里没有 start index, 也没有 used: 每一层的选项本来就不同, 不会重复。也不需要剪枝, 所有组合都是答案。

算法

  1. dfs(idx): idx == len(digits), 记录 path。
  2. 对 phone[digits[idx]] 里的每个字母: push, dfs(idx + 1), pop。

手动走一遍

复杂度

Time O(4ⁿ · n), Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def letter_combinations(digits): if not digits: return [] PHONE = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl", "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"} res, path = [], [] def dfs(idx): # idx: 正在决定第几位数字 if idx == len(digits): res.append("".join(path)) return for ch in PHONE[digits[idx]]: # choices 由层数 idx 决定, 不用 start path.append(ch) dfs(idx + 1) path.pop() dfs(0) return res

记:每一层的选项不一样: 第 idx 层就从第 idx 组里选。

7. Word Search

题目在问什么

一个字母 grid 和一个单词 word。能不能从某个格子出发, 每一步走到上下左右相邻的格子, 依次拼出 word? 同一个格子在一条路径里只能用一次。

看例子

Brute force

从每个格子出发, 枚举所有可能的路径。不剪枝的话路径数量是指数级的。

Intuition: grid 上的 backtracking

从每个格子出发试一次。每一步: 当前格子的字母必须等于 word[i], 否则这条路不通, 立即返回 (这就是剪枝)。

相等的话, 往四个方向找 word[i+1]。

"同一个格子不能用两次": 走进一个格子时, 把它临时改成 '#', 这样后面的路径不会再走进来。退回时一定要恢复原来的字母, 因为别的路径 (从别的方向来的) 可能还要用它。这就是 backtracking 的"撤销选择"。

和 12 里的 Number of Islands 对比: 那题淹掉之后不恢复, 因为每个格子只需要访问一次; 这题要恢复, 因为同一个格子可以出现在不同的路径里。

算法

  1. dfs(r, c, i): i == len(word) 返回 True。越界或者 board[r][c] != word[i], 返回 False。
  2. tmp = board[r][c], board[r][c] = '#'。
  3. 四个方向有一个 dfs(..., i + 1) 返回 True, 结果就是 True。
  4. board[r][c] = tmp (恢复), 返回结果。对每个格子调用 dfs(r, c, 0)。

手动走一遍

复杂度

Time O(m·n · 3^L), L 是单词长度 (除了第一步, 每步最多 3 个方向, 不能走回头)。Space O(L)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def exist(board, word): R, C = len(board), len(board[0]) # k: 已经匹配了 word[:k]; 现在要让 (r, c) 匹配 word[k] def dfs(r, c, k): if k == len(word): # 结束条件: word 全部匹配 return True if not (0 <= r < R and 0 <= c < C) or board[r][c] != word[k]: return False # 剪枝: 越界 / 字母不对 / 已经被标记成 "#" # 做选择: 原地标记, 当作 used[] (字母里不会有 "#") board[r][c] = "#" found = (dfs(r + 1, c, k + 1) or dfs(r - 1, c, k + 1) or dfs(r, c + 1, k + 1) or dfs(r, c - 1, k + 1)) # 撤销: 恢复原字母; 找到了也要恢复, 不能留着改过的 board board[r][c] = word[k] return found return any(dfs(r, c, 0) for r in range(R) for c in range(C))

记:grid 上的路径搜索、格子不能重复用: 进去时标记, 出来时恢复。

8. N-Queens

题目在问什么

在 n × n 的棋盘上放 n 个皇后, 让它们互相攻击不到。皇后能攻击同一行、同一列、同一条斜线 (两个方向) 上的任何棋子。返回所有的放法。

看例子

Brute force

在 n² 个格子里选 n 个放皇后, 再检查。n = 8 时组合数超过 40 亿。

Intuition: 一行放一个, 用三个 set 检查冲突

每一行一定恰好有一个皇后 (不然有两个在同一行)。所以按行来: decision tree 的第 r 层, 决定第 r 行的皇后放在哪一列。

放之前检查会不会被攻击。如果每次都扫一遍已经放的皇后, 是 O(n)。用三个 set 可以 O(1):

  • cols: 已经被占的列。
  • diag: 已经被占的 "\" 斜线。同一条这种斜线上 r - c 相同。
  • anti: 已经被占的 "/" 斜线。同一条这种斜线上 r + c 相同。

放下皇后时把它的列、两条斜线加进三个 set; 退回时删掉。

剪枝的效果: 8 皇后实际只访问了 2057 个节点, 而不是 8⁸ ≈ 1677 万。

算法

  1. dfs(r): r == n, 记录当前的棋盘。
  2. 对每一列 c: c 在 cols、r - c 在 diag、r + c 在 anti, 有一个就跳过。
  3. 否则三个 set 加进去, 记录 path[r] = c, dfs(r + 1), 再从三个 set 删掉。

手动走一遍

复杂度

Time 上界 O(n!), 实际因为剪枝小很多。Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def solve_n_queens(n): res, path = [], [] # path[r] = 第 r 行皇后所在的列 # 三个 set: 已占用的 列 / r - c (\ 对角线) / r + c (/ 对角线) cols, diag, anti = set(), set(), set() def dfs(r): if r == n: # n 行都放好了 res.append(["." * c + "Q" + "." * (n - c - 1) for c in path]) return for c in range(n): if c in cols or (r - c) in diag or (r + c) in anti: continue # 剪枝: 同列或同一条对角线 # 做选择: 三个 set 各 add 一个值, path 也要 append cols.add(c); diag.add(r - c); anti.add(r + c) path.append(c) dfs(r + 1) # 撤销: 三个 set 和 path 全部还原 path.pop() cols.remove(c); diag.remove(r - c); anti.remove(r + c) dfs(0) return res

记:多个约束: 每个约束一个 set, 放之前 O(1) 检查, 放下 add, 退回 remove。

9. 识别信号: 看到什么, 就想到 backtracking

题目特征做法complexity
"所有子集 / 所有组合"start index 只往后选; 每个节点都记录O(n · 2ⁿ)
"所有排列"每层从头选, used 跳过O(n · n!)
和为 target 的组合, 可以重复选递归传 i (不是 i + 1), 排序后 break 剪枝decision tree 大小
输入有重复, 输出要去重排序 + 同层 i > start and a[i] == a[i-1] 跳过去掉重复的子树
生成所有合法的 xxx (括号、IP 地址)push 之前检查约束, 只走合法的分支只和答案个数有关
每一位的选项来自不同的集合第 idx 层从第 idx 组里选O(∏ 每组大小)
grid 上找路径, 格子不能重复用进去标记 #, 出来恢复O(m·n · 3^L)
棋盘放置, 多个约束每个约束一个 set, O(1) 检查剪枝后远小于 O(n!)
只要答案的个数 / 最优值, 不要列出来多半是 DP (见 14、15)指数 → 多项式

一句话: 题目要"列出所有", 就是 backtracking。先画出 decision tree, 想清楚 path、choices、结束条件, 再想哪些分支可以提前剪掉。
