09 · Heap / Top-K

这篇讲什么

很多题需要反复拿出当前最小 (或最大) 的那一个, 或者只关心"前 k 大"。最直接的做法是排序, O(n log n); 如果数据不断变化, 每次都重新排序就更慢。

Heap (堆, Python 里是 heapq) 是专门干这件事的数据结构。它只保证一件事: 堆顶是最小的。其他元素之间的顺序它不管。正因为管得少, 所以快:

  • 看堆顶: h[0], O(1)
  • 放一个进去: heappush, O(log n)
  • 拿走堆顶: heappop, O(log n)

你可以把 heap 画成一棵 tree: 每个节点都比它的子节点小, 所以最上面的根就是最小的。

Python 的 heapq 只有 min-heap。要 max-heap, 就存 -x, 拿出来再取负。图里一律画原来的正数。

1. Kth Largest Element in an Array

题目在问什么

给一个整数数组 nums 和 k, 返回第 k 大的数。"第 k 大" 是按从大到小排好之后的第 k 个, 重复的数也各占一个位置。

看例子

Brute force

排序, 取 nums[-k]。O(n log n)。

浪费在哪: 排序把所有 n 个数的顺序都排出来了, 但我们只关心最大的 k 个, 而且这 k 个之间的顺序也不重要, 只要知道其中最小的那个。

Intuition: 只留最大的 k 个, 用 min-heap

从左往右扫, 手里只留"目前见过的最大的 k 个数"。扫完之后, 这 k 个里最小的那个就是第 k 大。

每来一个新数, 怎么更新手里的 k 个? 先放进来, 变成 k + 1 个, 再把最小的那个扔掉。

"扔掉最小的" 和 "看最小的" 正是 min-heap 擅长的: 堆顶就是最小的。

这里容易糊涂: 求的是"大", 用的却是 min-heap。原因是 heap 的堆顶应该是下一个要被扔掉的。要留下大的, 就扔小的, 所以堆顶要是最小的。

算法

  1. h = []。
  2. 每个 x: heappush(h, x); 如果 len(h) > k, heappop(h)。
  3. 返回 h[0]。

手动走一遍

复杂度

Time O(n log k): n 次 push / pop, heap 最多 k + 1 个元素。Space O(k)。k 远小于 n 时比排序快很多。

另有 quickselect, 平均 O(n), 但最坏 O(n²), 面试里提一句就行。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def findKthLargest(nums, k): h = [] # min-heap, 永远只留 "目前最大的 k 个" for x in nums: heapq.heappush(h, x) if len(h) > k: heapq.heappop(h) # 弹掉最小的, 它一定不在前 k 大里 return h[0] # k 个里最小的 = 第 k 大

记:求最大的 k 个 / 第 k 大: 用大小为 k 的 min-heap。堆顶是"下一个要被踢掉的"。

把第 1 题抽象一下: 什么时候用 heap, 用哪个方向

第 1 题的规律:

  • 只关心最值, 不关心全部顺序, 或者数据在不断变化, 要反复取最值, 就用 heap 代替排序。
  • 要留下最大的 k 个, 就扔最小的, 用 min-heap。要留下最小的 k 个, 就扔最大的, 用 max-heap。
  • 一句话: 堆顶永远放"最该被扔掉的那个"。

记:heap 的方向: 堆顶 = 最该被扔掉的。留大的 → min-heap; 留小的 → max-heap。

2. Top K Frequent Elements

题目在问什么

返回数组里出现次数最多的 k 个数。顺序随意。

看例子

Brute force

用 Counter 数出每个数的次数, 按次数排序, 取前 k 个。O(m log m), m 是不同的数的个数。

Intuition: 先数次数, 再套第 1 题

数完次数之后, 问题就变成: 在 (次数, 数) 这些 pair 里, 找次数最大的 k 个。这正是第 1 题, 只是比较的东西从"数本身"换成了"次数"。

Python 的 tuple 从左往右比较, 所以把 (count, num) 放进 heap, 就是按 count 比。

算法

  1. c = Counter(nums)。
  2. 对每个 (num, count): push (count, num), 超过 k 个就 pop。
  3. 返回 heap 里所有的 num。

手动走一遍

复杂度

Time O(n + m log k), Space O(m)。另有 bucket sort 的 O(n) 做法: 次数最多是 n, 开 n + 1 个桶, 按次数放进桶, 从后往前取。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def topKFrequent(nums, k): count = Counter(nums) # O(n): num -> 出现次数 h = [] # min-heap of (count, num) for num, c in count.items(): # 只遍历不同的 num: m 个 heapq.heappush(h, (c, num)) if len(h) > k: # count 最小的踢掉 (和上一题唯一的区别) heapq.heappop(h) return [num for c, num in h] # 顺序不限

记:Top K 按某个属性: 先算出属性 (Counter), 再用 (属性, 元素) 进 heap。

3. K Closest Points to Origin

题目在问什么

平面上有一些点, 返回离原点最近的 k 个。距离只用来比较大小, 所以用 x² + y² 就行, 不用开根号。

看例子

Brute force

按距离排序, 取前 k 个, O(n log n)。

Intuition: 方向反过来, 用 max-heap

这次要留最小的 k 个 (最近的)。按上一节的规律: 留小的 → 扔大的 → 堆顶要是最大的 → max-heap。

Python 里存 (-距离², x, y), 这样最远的点在堆顶, 超过 k 个就把它 pop 掉。

算法

  1. 每个点: push (-(x² + y²), x, y); 超过 k 个就 pop。
  2. 返回 heap 里的点。

手动走一遍

复杂度

Time O(n log k), Space O(k)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def kClosest(points, k): # max-heap (存 -d), 留 "最近的 k 个" h = [] for x, y in points: d = x * x + y * y # 不开根号, 比大小等价 heapq.heappush(h, (-d, x, y)) # -d 最小 = d 最大, 在 top if len(h) > k: heapq.heappop(h) # 踢掉 d 最大的 (最远的) return [[x, y] for _, x, y in h]

记:留最小的 k 个: max-heap (Python 里存负数)。

4. Merge k Sorted Lists

题目在问什么

给 k 条 linked list, 每条都已经从小到大排好。把它们合并成一条排好序的 linked list。

看例子

Brute force

把所有节点的值收集起来, 排序, 再串成一条 list。N 是节点总数, O(N log N)。

另一种: 每次扫一遍 k 条 list 的头, 找最小的接到结果后面。每接一个要扫 k 个, O(N·k)。

Intuition: 下一个最小的, 一定是某条 list 的头

因为每条 list 自己是排好序的, 所以所有剩下的节点里最小的那个, 一定是某条 list 当前的头。

所以只需要在 k 个头里找最小的。上面第二种 brute force 每次扫 k 个太慢; 用 heap 存这 k 个头, 每次 pop 就是 O(log k)。

pop 出一个节点之后, 它所在的那条 list 的下一个节点成为新的头, push 进 heap。heap 里始终最多 k 个元素。

算法

  1. 把每条 list 的头 push 进 heap, 存 (val, i, node)。i 是 list 的编号, 用来在 val 相同时比较 (node 本身不能比大小)。
  2. 当 heap 不空: pop 出最小的, 接到结果后面; 如果它有 next, 把 next push 进去。

手动走一遍

复杂度

Time O(N log k), Space O(k)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def mergeKLists(lists): h = [] for i, node in enumerate(lists): if node: heapq.heappush(h, (node.val, i, node)) # (val, i, node) # i 用来在 val 相同时决胜负, 否则会去比较 ListNode (不能比) dummy = tail = ListNode() while h: val, i, node = heapq.heappop(h) # 全局最小一定是某条 list 的 head tail.next = node tail = node if node.next: # 这条 list 的新 head 补进来 heapq.heappush(h, (node.next.val, i, node.next)) return dummy.next

记:k 路归并: heap 里只放每一路当前的头, pop 一个就 push 它的下一个。

5. Find Median from Data Stream

题目在问什么

设计一个数据结构: addNum(x) 加入一个数, findMedian() 返回目前所有数的中位数。两个操作会交替调用很多次。

看例子

Brute force

用 list 存所有数, findMedian 时排序取中间, O(n log n)。或者每次 addNum 用插入保持有序, 插入是 O(n)。

Intuition: 中位数只取决于中间那两个数

把所有数分成两半: 较小的一半和较大的一半。中位数只和"较小一半的最大值"与"较大一半的最小值"有关。

所以用两个 heap:

  • lo: 较小的一半, 用 max-heap, 堆顶是这一半的最大值。
  • hi: 较大的一半, 用 min-heap, 堆顶是这一半的最小值。
  • 保持 lo 的个数等于 hi, 或者比 hi 多 1。

中位数: 总数是奇数, 就是 lo 的堆顶; 偶数, 就是两个堆顶的平均。

加一个数时, 要保证 lo 里所有数都 ≤ hi 里所有数。简单的办法: 先放进 lo, 再把 lo 的最大值移到 hi; 如果 hi 比 lo 多了, 再把 hi 的最小值移回 lo。

算法

  1. addNum(x): push x 进 lo; 把 lo 的堆顶 pop 出来 push 进 hi; 如果 len(hi) > len(lo), 把 hi 的堆顶移回 lo。
  2. findMedian: lo 多一个就返回 lo 的堆顶, 否则返回两个堆顶的平均。

手动走一遍

复杂度

addNum O(log n), findMedian O(1)。Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
class MedianFinder: def __init__(self): self.lo = [] # max-heap (存 -x): 较小的一半, top = 这一半最大 self.hi = [] # min-heap: 较大的一半, top = 这一半最小 def addNum(self, num): heapq.heappush(self.lo, -num) # 先进 lo, 再把 lo 最大的交给 hi -> 保证 max(lo) <= min(hi) heapq.heappush(self.hi, -heapq.heappop(self.lo)) if len(self.hi) > len(self.lo): # lo 允许比 hi 多 1 个, hi 不许多 heapq.heappush(self.lo, -heapq.heappop(self.hi)) def findMedian(self): if len(self.lo) > len(self.hi): # 总数奇数 return -self.lo[0] return (-self.lo[0] + self.hi[0]) / 2

记:动态的中位数: 两个 heap, 较小的一半用 max-heap, 较大的一半用 min-heap, 个数差不超过 1。

6. Minimum Cost to Hire K Workers

题目在问什么

每个 worker 有 quality q 和最低工资 wage。要雇 k 个人, 两条规则: (1) 每个人的工资和他的 q 成正比, 也就是大家用同一个单价 rate, 工资 = rate × q; (2) 每个人拿到的不能低于他自己的 wage。求最少要付多少钱。

看例子

从例子里能看出: 一组人选定之后, rate 必须满足组里要求最高的那个人, 也就是组里最大的 wage / q。总工资 = rate × total_q, total_q 是组里所有人的 q 相加。

Brute force

枚举所有 k 人组合, 每组算 max(rate) × total_q, 取最小。组合数 C(n, k), 指数级。

难在两个量互相牵制: 想让 rate 小, 就要挑 rate 小的人; 想让 total_q 小, 就要挑 q 小的人。这两件事经常冲突。

Intuition: 先固定一个维度

先把所有人按 rate 从小到大排序。然后从左往右, 依次考虑"让当前这个人当 rate 最高的那个"。

当前这个人的 rate 是 r, 那组里其他人只能从他左边 (rate 更小的) 挑。rate 已经固定为 r 了, 总工资 = r × total_q, 要让它最小, 就只能让 total_q 最小。

所以问题变成: 在目前见过的人里, 挑 q 最小的 k 个。这是第 3 题: 留最小的 k 个 → 用 max-heap 存 q, 超过 k 个就 pop 掉最大的 q。

每一步, heap 里是 q 最小的 k 个人, total_q 是 heap 里所有 q 相加, 算一次 r × total_q, 取所有步里的最小值。

算法

  1. 按 wage / q 从小到大排序。
  2. 从左往右, 对每个人: push 他的 q 进 max-heap, total_q += q。
  3. 如果 heap 超过 k 个: pop 最大的 q, total_q -= 它。
  4. 如果 heap 正好 k 个: ans = min(ans, rate × total_q)。

手动走一遍

复杂度

Time O(n log n) (排序 + heap)。Space O(n)。

同样的套路 ("按一个量排序, 往前推进时把现在可选的放进 heap, 堆顶决定选谁"):

  • Maximum Number of Events That Can Be Attended: 按开始时间排序, heap 存结束时间, 每天参加结束最早的。
  • IPO: 按需要的本钱排序, heap 存利润, 每次在做得起的项目里挑利润最大的。
参考代码 (先自己按上面的算法步骤写, 写不出来再展开)

7. Task Scheduler

题目在问什么

一串 task (用字母表示), CPU 每个时间单位做一个 task 或者 idle (什么都不做)。同一种 task 两次之间至少要隔 n 个时间单位。task 的顺序可以随便排。求做完所有 task 最少需要多少个时间单位。

看例子

Brute force

枚举所有排列, 检查间隔, 指数级。

Intuition: 每次做剩得最多的那种

剩得最多的那种 task 最"危险": 它需要的间隔最多, 如果拖到最后, 就只剩它一种, 中间只能 idle。所以 greedy: 每个时间单位, 都做当前能做的里剩得最多的。

"能做的里剩得最多的" 就是 max-heap 的堆顶 (按剩余次数)。

但这次有一个新问题: 做完一种 task 之后, 它要等 n 个单位才能再做。所以不能直接 push 回 heap, 而是放进一个冷却队列, 记下它什么时候可以回来。时间到了再 push 回 heap。

如果某个时间单位 heap 是空的, 但冷却队列里还有, 这个单位就只能 idle。

算法

  1. 数每种 task 的次数, 全部放进 max-heap。time = 0, 冷却队列 cool = deque()。
  2. 当 heap 或 cool 不空: time += 1。heap 不空就 pop 一个, 次数减 1, 还有剩就放进 cool, 记录 (剩余次数, time + n)。
  3. 如果 cool 的队头到时间了 (== time), 把它 push 回 heap。
  4. 返回 time。

手动走一遍

复杂度

Time O(T log 26), T 是总时间单位数。Space O(26)。

这题也有公式解: max(len(tasks), (max_count - 1) × (n + 1) + 次数等于 max_count 的种类数)。Reorganize String (相邻字符不能相同) 是 n = 1 的同一个结构。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def leastInterval(tasks, n): heap = [(-c, t) for t, c in Counter(tasks).items()] # max-heap: 剩余次数 heapq.heapify(heap) cooldown = deque() # (回来的 slot, -剩余次数, task), 回来时间递增 time = 0 while heap or cooldown: time += 1 # 每个 slot 无论做不做事, time 都 +1 if heap: c, t = heapq.heappop(heap) # 剩余最多的, 这个 slot 做它 if c + 1: # c 是负数, c + 1 != 0 说明还有剩 cooldown.append((time + n, c + 1, t)) if cooldown and cooldown[0][0] == time: # 冷却完了, 下个 slot 可以做 _, c, t = cooldown.popleft() heapq.heappush(heap, (c, t)) return time

记:每一步选当前最优, 而且候选会变化: greedy + heap。用过的要等一阵才能再用: 再加一个冷却队列。
