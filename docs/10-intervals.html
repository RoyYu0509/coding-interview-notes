10 · Intervals

这篇讲什么

interval (区间) 就是一个 [start, end], 比如一个会议从 9 点开到 11 点。这类题给你一堆区间, 问: 合并重叠的、最少删几个让它们不重叠、同一时刻最多有几个、两组区间的交集……

brute force 通常是把每两个区间都比一下, 看重不重叠, O(n²)。

几乎所有 interval 题的第一步都是排序。排好序之后, 每个区间只需要和"刚处理过的那一个"比较, 扫一遍就行, 总共 O(n log n)。整篇的关键问题是: 按 start 排还是按 end 排, 以及为什么。

先说清楚: 两个区间什么时候重叠

两个区间 a 和 b 重叠, 当且仅当 a.start ≤ b.end 并且 b.start ≤ a.end。反过来想更好记: 不重叠, 就是一个完全在另一个的左边 (a.end < b.start 或 b.end < a.start)。

重叠的部分是 [max(两个 start), min(两个 end)]。

还要看题目是闭区间还是半开区间: 闭区间 [1,4] 和 [4,5] 在 4 这一点碰到, 算重叠; 半开区间 [1,4) 和 [4,5) 不算。这决定了代码里写 ≤ 还是 <。

1. Merge Intervals

题目在问什么

给一组区间 (没有排序), 把所有互相重叠的区间合并成一个, 返回合并之后的区间列表。

看例子

Brute force

反复扫描: 找到任意两个重叠的区间就合并, 直到找不到为止。每轮 O(n²) 比较, 可能要很多轮。

Intuition: 按 start 排好, 只需要和最后一个合并结果比

先按 start 排序。然后从左往右, 一个一个放进结果 res。对当前的区间 cur:

  • 如果 cur.start ≤ res[-1].end: 和 res 里最后一块重叠, 合并进去: res[-1].end = max(res[-1].end, cur.end)。
  • 否则: 不重叠, cur 自己成为新的一块。

为什么只看 res[-1] 就够了? 因为排了序, cur.start 比之前所有区间的 start 都大。如果它连 res[-1] 都够不到 (cur.start > res[-1].end), 那更早的块 (end 更小) 就更够不到了。

合并时一定要取 max: cur 可能整个被 res[-1] 包在里面 (比如 [1,10] 和 [2,3]), 直接写 end = cur.end 会把 10 缩成 3。

算法

  1. 按 start 排序。
  2. 对每个区间: 和 res[-1] 重叠就合并 (end 取 max), 否则 append。

手动走一遍

复杂度

Time O(n log n) (排序)。Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def merge(intervals): # 按 start 排序: 之后只和 res[-1] 比 intervals.sort(key=lambda x: x[0]) res = [list(intervals[0])] for s, e in intervals[1:]: # 重叠: s 没超过 "上一个合并结果" 的 end if s <= res[-1][1]: res[-1][1] = max(res[-1][1], e) # 必须 max: cur 可能被整个包住 else: res.append([s, e]) # 不重叠: 开一个新块 return res

记:合并区间: 按 start 排序, 只和 res[-1] 比, 重叠就把 end 取 max。

把第 1 题抽象一下: 按 start 排, 还是按 end 排

interval 题基本都是"排序 + 扫一遍", 区别在按什么排:

  • 按 start 排: 要把区间连起来、拼起来 (合并、插入、检查冲突)。排好之后, 后面的区间只可能和最后一块接上。
  • 按 end 排: 要挑尽量多的、互不重叠的区间 (最多保留几个、最少删几个、最少几支箭)。先结束的先选, 给后面留出最多的空间。第 3 题会解释为什么。
  • 拆成事件: 要知道同一时刻有几个 (最少几间会议室)。每个 start 是 +1, 每个 end 是 -1, 按时间扫一遍。第 6 题会讲。
三种写法的模板
# A. 按 start 排序, 只和 res[-1] 比 -> 合并 / 冲突检测 / 插入intervals.sort(key=lambda x: x[0])for s, e in intervals: if res and s <= res[-1][1]: res[-1][1] = max(res[-1][1], e) else: res.append([s, e])# B. 按 end 排序, 贪心 (keep_end) -> 最多保留几个 / 最少箭 / 最少删除intervals.sort(key=lambda x: x[1])for s, e in intervals: if s >= keep_end: keep_end = e # 保留; 否则丢掉# C. 拆成事件, 扫描线 -> 同一时刻最多几个events = [(s, 1) for s, e in iv] + [(e, -1) for s, e in iv]events.sort() # 同一时刻 -1 排在 +1 前for t, delta in events: cur += delta; best = max(best, cur)

记:拼接 → 按 start; 挑最多不重叠的 → 按 end; 同时有几个 → 拆成 +1 / -1 事件。

2. Insert Interval

题目在问什么

给一个已经按 start 排好、互不重叠的区间列表, 再给一个新区间 new。把 new 插进去, 有重叠就合并。返回的结果也要排好、不重叠。

看例子

Brute force

把 new 加进列表, 再做一遍第 1 题: 排序 + 合并。O(n log n)。浪费: 列表本来就排好了, 不需要再排。

Intuition: 列表被 new 分成三段

因为原来的列表是有序、不重叠的, 所以它按和 new 的关系, 正好分成连续的三段:

  1. 完全在 new 左边 的 (end < new.start): 原样放进结果。
  2. 和 new 重叠 的: 全部并进 new。new 的 start 取最小、end 取最大。
  3. 完全在 new 右边 的 (start > new.end): 先把合并好的 new 放进去, 再把它们原样放进去。

算法

  1. i = 0。当 intervals[i].end < new.start: 放进结果, i += 1。
  2. 当 intervals[i].start ≤ new.end: new = [min(start), max(end)], i += 1。
  3. 放进 new, 再放进剩下的所有区间。

手动走一遍

复杂度

Time O(n), Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def insert(intervals, new): # intervals 已排序且互不重叠 res, i, n = [], 0, len(intervals) # 1. 左边: end 比 new 的 start 还小 while i < n and intervals[i][1] < new[0]: res.append(intervals[i]) i += 1 # 2. 重叠: start 没超过 new 的 end while i < n and intervals[i][0] <= new[1]: new = [min(new[0], intervals[i][0]), # 吞进 new, new 越吞越大 max(new[1], intervals[i][1])] i += 1 res.append(new) # new 此刻是最终形态, 放进去 res.extend(intervals[i:]) # 3. 右边: 原样接上 return res

记:已经排好的列表插入新区间: 左边不碰的、重叠的、右边不碰的, 三段扫一遍。

3. Non-overlapping Intervals

题目在问什么

给一组区间。最少删掉几个, 能让剩下的区间互不重叠? 这题里首尾相接 (比如 [1,2] 和 [2,3]) 不算重叠。

等价的问法: 最多能保留几个互不重叠的区间? 答案 = 总数 - 最多保留数。

看例子

Brute force

枚举所有子集, 检查是否互不重叠, 找最大的。O(2ⁿ · n)。

Intuition: 每次留下最先结束的那个

想象你要在一天里参加尽量多的、时间不冲突的活动。你会先选哪个? 选最早结束的那个。因为它结束得最早, 留给后面的时间最多。

为什么这样不会错? 假设最优解里第一个选的活动不是最早结束的那个 X, 而是 Y。把 Y 换成 X: X 结束得比 Y 早 (或一样), 所以 Y 后面能接的活动, X 后面也都能接。换完之后数量不变, 还是最优。所以选 X 不会吃亏。

那为什么不按 start 排? 反例: 一个很长的区间 [1,11] 最早开始, 但它挡住了后面三个短区间。按 start 选它, 就要删掉 3 个; 按 end 选, 只用删它 1 个。

算法

  1. 按 end 排序。keep_end = -∞, removed = 0。
  2. 对每个区间: 如果 start ≥ keep_end, 不冲突, 保留它, keep_end = end。
  3. 否则冲突, 删掉它 (removed += 1), keep_end 不变。

手动走一遍

复杂度

Time O(n log n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def erase_overlap_intervals(intervals): intervals.sort(key=lambda x: x[1]) # 按 end 排序: 先看结束得最早的 # 已保留的最后一个 interval 的 end keep_end = -inf removed = 0 for s, e in intervals: # 不重叠 (首尾相接 s == keep_end 也算不重叠) if s >= keep_end: # 保留它, 它是目前 end 最小的选择 keep_end = e else: # 和已保留的重叠: 丢掉这个 (它的 end 更大) removed += 1 return removed

记:最多保留几个不重叠 / 最少删几个: 按 end 排序, 每次保留最先结束的。

4. Minimum Number of Arrows to Burst Balloons

题目在问什么

每个气球在 x 轴上占一段 [start, end]。在某个 x 处竖直射一支箭, 能射爆所有 start ≤ x ≤ end 的气球。最少需要几支箭, 才能射爆所有气球?

看例子

Brute force

枚举箭的位置组合, 指数级。

Intuition: 和第 3 题是同一个 greedy

一支箭能射爆的一组气球, 就是一组互相重叠的气球。所以问题变成: 最少分成几组, 每组里的气球有公共点。

还是按 end 排序。第一支箭射在第一个气球的 end 上: 尽量往右射, 才能顺便射到更多后面的气球, 而又不会漏掉第一个。

之后每个气球: 如果它的 start ≤ 当前箭的位置, 已经被射爆了; 否则需要一支新箭, 射在它的 end 上。

和第 3 题只差一个符号: 这题是闭区间, 碰到边也算被射中, 所以判断"需要新箭"用 start > arrow_x; 第 3 题首尾相接不算重叠, 用 start ≥ keep_end。

算法

  1. 按 end 排序。arrows = 0, arrow_x = -∞。
  2. 对每个气球: 如果 start > arrow_x, 新射一箭, arrow_x = end, arrows += 1。

手动走一遍

复杂度

Time O(n log n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def find_min_arrow_shots(points): points.sort(key=lambda p: p[1]) # 按 end 排序 arrows = 0 arrow_x = -inf # 最近一支箭射在哪个 x for s, e in points: # 箭射不到它 (首尾相接 s == arrow_x 能射到) if s > arrow_x: arrows += 1 # 新箭射在它的 end: 尽量往右, 多串几个 arrow_x = e return arrows

记:最少几个点能覆盖所有区间: 按 end 排序, 点放在当前区间的 end 上。

5. Meeting Rooms

题目在问什么

给一组会议时间。一个人能不能参加所有会议? 也就是判断所有会议是不是两两都不重叠 (首尾相接可以)。

看例子

Brute force

每两个会议比一下, O(n²)。

Intuition: 排好序之后, 只看相邻的两个

按 start 排序。如果有任何两个会议重叠, 那么一定有相邻的两个会议重叠。

为什么? 假设所有相邻的两个都不重叠: 第 1 个在第 2 个开始前结束, 第 2 个在第 3 个开始前结束……它们排成一条链, 一个接一个, 不可能有隔着的两个重叠。

所以只需要检查每对相邻的: intervals[i].start < intervals[i-1].end 就是冲突。

算法

  1. 按 start 排序。
  2. i 从 1 到 n-1: 如果 start[i] < end[i-1], 返回 False。
  3. 返回 True。

手动走一遍

复杂度

Time O(n log n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def can_attend_meetings(intervals): intervals.sort(key=lambda x: x[0]) for i in range(1, len(intervals)): # 下一个在上一个结束前就开始 (相接不算) if intervals[i][0] < intervals[i - 1][1]: return False return True

记:判断有没有重叠: 按 start 排序, 只比较相邻的两个。

6. Meeting Rooms II

题目在问什么

给一组会议时间, 最少需要几间会议室, 才能让所有会议都开得成?

换个说法: 同一时刻, 最多有几个会议在同时进行? 这个最大值就是需要的房间数。

看例子

Brute force

对每个时间点, 数有几个会议覆盖它, 取最大。时间点很多时很慢。或者每个会议的开始时刻, 数有几个会议正在进行, O(n²)。

Intuition A: 用 heap 管"正在用的房间什么时候空出来"

按 start 排序, 一个一个会议地安排。对新来的会议, 问: 现在有没有房间已经空出来了?

最可能空出来的, 是最早结束的那个房间。所以用一个 min-heap 存每个正在用的房间的结束时间, 堆顶就是最早空出来的。

  • 如果 堆顶 ≤ 新会议的 start: 那个房间已经空了, 复用它: pop 掉旧的结束时间, push 新会议的结束时间。
  • 否则: 没有空房间, 新开一间: 直接 push。
  • 最后 heap 的大小就是房间数。

Intuition B: sweep line (扫描线)

另一种更直接的想法: 把每个会议拆成两个事件, 开始时 +1, 结束时 -1。把所有事件按时间排序, 从左往右扫, 维护当前人数 cur, 记录 cur 的最大值。

同一时刻既有结束又有开始时, 要先算结束 (-1), 再算开始 (+1): 一个会 10 点结束、另一个 10 点开始, 可以用同一个房间。

两种做法都是 O(n log n)。sweep line 更容易推广 (比如"最忙的时刻是什么时候"); heap 做法能顺便知道每个会议分到了哪间房。

复杂度

Time O(n log n), Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def min_meeting_rooms(intervals): # 按 start 排序: 按开会顺序分配房间 intervals.sort(key=lambda x: x[0]) # min-heap: 每个正在用的房间, 当前会议的 end ends = [] for s, e in intervals: # 最早结束的房间已经空出来 (相接不算冲突) if ends and ends[0] <= s: heapq.heappop(ends) # 复用这个房间: 它的旧 end 出局 # 复用或新开, 这场会议的 end 都要进 heap heapq.heappush(ends, e) # heap 里有几个元素 = 同时用着几个房间 return len(ends)
def min_meeting_rooms(intervals): events = [] for s, e in intervals: events.append((s, 1)) # 开始: 同时进行的会议 +1 events.append((e, -1)) # 结束: -1 # (t, -1) < (t, 1): 同一时刻先结束再开始 events.sort() cur = best = 0 for t, delta in events: cur += delta # cur = 时刻 t 正在进行的会议数 best = max(best, cur) return best

记:同一时刻最多几个: 拆成 +1 / -1 事件扫一遍 (同一时刻先 -1); 或者 min-heap 存结束时间。

7. Interval List Intersections

题目在问什么

两个区间列表 A 和 B, 各自按顺序排好、内部互不重叠。求它们的交集: 所有被 A 和 B 同时覆盖的部分。都是闭区间。

看例子

Brute force

A 里每个区间和 B 里每个区间都算一下交集, O(m·n)。

Intuition: 双指针, 先结束的那个往前走

两个列表都是有序的, 就像 02 里的 merge: 各放一个指针 i 和 j。

  • 当前两个区间 A[i] 和 B[j] 的交集是 [max(start), min(end)], 如果 lo ≤ hi 就是一段交集。
  • 然后, 先结束的那个往前走。因为它已经结束了, 不可能再和对方的下一个区间相交 (对方的下一个区间开始得更晚)。

算法

  1. i = j = 0。当两个都没走完:
  2. lo = max(A[i].start, B[j].start), hi = min(A[i].end, B[j].end)。lo ≤ hi 就记下 [lo, hi]。
  3. A[i].end < B[j].end 则 i += 1, 否则 j += 1。

手动走一遍

复杂度

Time O(m + n), Space O(m + n) (输出)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
# A, B 各自已排序, 各自内部不重叠def interval_intersection(A, B): i = j = 0 res = [] while i < len(A) and j < len(B): lo = max(A[i][0], B[j][0]) # 交集的左端 = 两个 start 里大的 hi = min(A[i][1], B[j][1]) # 交集的右端 = 两个 end 里小的 if lo <= hi: # 就是 overlap 条件 res.append([lo, hi]) # end 小的那个不可能再和对方后面的相交 if A[i][1] < B[j][1]: i += 1 else: j += 1 return res

记:两个有序区间列表求交集: 双指针, 交集是 [max(start), min(end)], 先结束的往前走。

8. My Calendar I

题目在问什么

实现一个日历: book(start, end) 预订半开区间 [start, end)。如果和已有的任何预订重叠, 就拒绝 (返回 False); 否则记下来, 返回 True。

和前面不同, 这次区间是一个一个来的, 每来一个都要马上回答。

看例子

Brute force

每次 book, 把新区间和已有的所有预订都比一下, 每次 O(n), 共 O(n²)。

Intuition: 只需要和左右两个邻居比

把已有的预订按 start 排好存起来 (它们互不重叠)。新区间来了, 用二分 (bisect) 找到它应该插在哪个位置。

它只可能和左边的邻居 (start 比它小的最后一个) 或右边的邻居 (start 比它大的第一个) 重叠。更远的预订被这两个邻居隔开了, 不可能碰到。

  • 左邻居的 end 要 ≤ 新的 start。
  • 右邻居的 start 要 ≥ 新的 end。

算法

  1. i = bisect_left(starts, start)。
  2. 检查左邻居 i-1 和右邻居 i, 都不冲突就在 i 插入, 返回 True; 否则返回 False。

手动走一遍

复杂度

查找 O(log n); Python list 的插入是 O(n), 所以每次 book 是 O(n)。用平衡树 (比如 sortedcontainers) 可以做到 O(log n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
class MyCalendar: def __init__(self): self.books = [] def book(self, start, end): # 半开区间 [start, end) for s, e in self.books: # overlap 条件 (半开区间: 用 < 不用 <=) if start < e and s < end: return False self.books.append((start, end)) return True
class MyCalendar: def __init__(self): self.starts = [] # 已预订的 start, 保持有序 # ends[i] 是 starts[i] 那场的 end self.ends = [] def book(self, start, end): # 半开区间 [start, end) i = bisect.bisect_left(self.starts, start) # 新预订应插在第 i 个位置 if i > 0 and self.ends[i - 1] > start: # 前一场还没结束 return False # 后一场在我结束前就开始 if i < len(self.starts) and self.starts[i] < end: return False self.starts.insert(i, start) self.ends.insert(i, end) return True

记:区间一个一个来、要判断冲突: 有序存储, 二分找位置, 只和左右两个邻居比。

9. 识别信号: 看到什么, 就想到这些做法

题目特征做法complexity
合并重叠的区间按 start 排序, 和 res[-1] 比, end 取 maxO(n²) → O(n log n)
往有序、不重叠的列表插入三段扫描O(n)
最多保留几个不重叠 / 最少删几个按 end 排序, greedy 保留最先结束的O(2ⁿ) → O(n log n)
最少几个点覆盖所有区间按 end 排序, 点放在 end 上O(n log n)
能不能全部参加 (有没有重叠)按 start 排序, 比相邻的O(n²) → O(n log n)
同一时刻最多几个 / 最少几间房+1 / -1 事件扫描, 或 min-heap 存 endO(n²) → O(n log n)
两个有序区间列表求交集双指针, 先结束的往前走O(m·n) → O(m + n)
区间一个一个来, 判断冲突有序存储 + bisect, 比左右邻居每次 O(n) 比较 → O(log n) 查找
