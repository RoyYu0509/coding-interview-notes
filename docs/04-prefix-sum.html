04 · Prefix Sum

这篇讲什么

这一类题都和区间和有关: 数组里一段连续的数加起来是多少, 或者有多少段连续的数, 加起来满足某个条件。

最直接的做法是每次都把那一段重新加一遍。问题是, 不同的区间重叠很多, 同一个数会被加很多次。

Prefix Sum (前缀和) 的想法是: 先花 O(n) 算出"从开头加到每个位置"的和, 存起来。之后任何一段的和都能用两个前缀和相减得到, 只要 O(1)。

它最重要的用法是和 Hash Table 配合, 把"数有多少段的和等于 k"从 O(n²) 降到 O(n)。这也是本篇的核心 (第 2 题)。

前置知识: 01 · Hash Table 里 "边扫边查" 的思路 (Two Sum)。

先认识 prefix sum: 区间和 = 两个前缀和相减

先看最基础的问题 (Range Sum Query): 数组 nums 不会变, 但会被问很多次 "nums[i..j] 的和是多少"。

Brute force: 每次从 i 加到 j, O(n)。q 次就是 O(n·q)。浪费: sum(1..3) 和 sum(0..3) 都把 nums[1..3] 重新加了一遍。

办法: 先算 prefix[k] = 前 k 个数的和 (nums[0] + ... + nums[k-1])。那么 nums[i..j] 的和 = 前 j+1 个数的和 - 前 i 个数的和 = prefix[j+1] - prefix[i]。

prefix 比 nums 多一格, prefix[0] = 0 表示"一个数都不取"。有了它, 从下标 0 开始的区间也能直接相减, 不用特判。

代码: 建 prefix 数组 + 查区间和
# prefix[i] = nums[0] + ... + nums[i-1] prefix[0] = 0 (空前缀)prefix = [0] * (len(nums) + 1)for i, x in enumerate(nums): prefix[i + 1] = prefix[i] + x # 每个元素只加一次: O(n)def range_sum(i, j): # nums[i..j] 闭区间 return prefix[j + 1] - prefix[i] # 两次查表: O(1)

记:sum(i..j) = prefix[j+1] - prefix[i], prefix[0] = 0。建表 O(n), 之后每次 O(1)。

1. Find Pivot Index

题目在问什么

找一个下标 i, 使得 i 左边所有数的和等于 i 右边所有数的和 (都不包括 nums[i] 自己)。有多个就返回最左边的, 没有返回 -1。

看例子

Example 3 说明: 下标 0 的左边什么都没有, 和算作 0。

Brute force

每个 i, 把左边加一遍, 右边加一遍, 比较。O(n²)。浪费: i 往右走一格, 左边的和只多了一个数, 却整个重算。

Intuition

左边的和就是前缀和, 从左往右走的时候边走边加就行, 一个变量 left 够了。

右边的和不用再加: 先算出总和 total, 那么右边 = total - left - nums[i]。

算法

  1. total = sum(nums), left = 0。
  2. i 从左往右: 如果 left == total - left - nums[i], 返回 i。否则 left += nums[i]。
  3. 走完都没有, 返回 -1。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def pivotIndex(nums): total = sum(nums) left = 0 # nums[0..i-1] 之和 = prefix[i] for i, x in enumerate(nums): if left == total - left - x: # right = total - left - nums[i] return i left += x # 处理完 i, left 变成 prefix[i+1] return -1

记:前缀和不一定要存成数组。只需要当前位置的前缀和时, 一个边走边加的变量就够。

2. Subarray Sum Equals K (本篇核心)

题目在问什么

给一个整数数组 nums 和整数 k。数一数: 有多少段连续的 subarray, 加起来正好等于 k。数组里可能有负数。

看例子

Example 3 里有负数, 这一点很重要。它意味着这题不能用 sliding window (03), 因为往右加一个数, 和可能变大也可能变小。最后一节会专门对比。

Brute force

枚举所有起点 i 和终点 j, 用前缀和 O(1) 算出区间和, 等于 k 就计数。一共 O(n²) 对 (i, j)。

浪费在哪: 固定终点 j 之后, 我们其实只想知道"有几个起点 i 能让 prefix[j+1] - prefix[i] == k", 却把所有 i 一个一个试了。

Intuition: 把条件移项, 变成查表

把 prefix[j+1] - prefix[i] == k 移项, 得到 prefix[i] == prefix[j+1] - k。

右边是已知的数。所以问题变成: 在 j 前面, 有多少个前缀和恰好等于 prefix[j+1] - k?

这和 01 里的 Two Sum 一模一样: 边走边把看过的前缀和存进 dict (key 是前缀和的值, value 是出现了几次), 每到一个新位置, 先查 dict 里有几个"我需要的那个值", 再把自己存进去。

两个细节:

  • dict 一开始要放 {0: 1}。它代表空前缀 (一个数都不取, 和为 0)。不放它, 从下标 0 开始的 subarray 就数不到。比如 Example 3 的 [3, 4], 就是靠它数到的。
  • 先查再存。起点必须在终点之前。

算法

  1. count = {0: 1}, prefix = 0, ans = 0。
  2. 从左往右, 每个数 x: prefix += x。
  3. ans += count[prefix - k] (之前有几个前缀和等于 prefix - k, 就有几段以当前位置结尾、和为 k 的 subarray)。
  4. count[prefix] += 1。

手动走一遍

复杂度

Time O(n): 每个数一次查表、一次写入。Space O(n): count 最多 n + 1 项。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def subarraySum(nums, k): count = {0: 1} # 别忘了: 空前缀 0 出现 1 次 prefix = ans = 0 for x in nums: prefix += x need = prefix - k ans += count.get(need, 0) # 之前有多少个 prefix == need count[prefix] = count.get(prefix, 0) + 1 # 查完才放进去 return ans
# 空前缀 prefix = 0 出现过 1 次, 让 "从下标 0 开始" 的 subarray 也能被数到count = {0: 1}prefix = ans = 0for x in nums: prefix += x need = prefix - k # 要找的起点 prefix 值 ans += count.get(need, 0) # 以当前位置结尾, 有多少个起点 count[prefix] = count.get(prefix, 0) + 1 # 先查再放: 起点在当前位置之前

记:连续 subarray + 和等于 k (可能有负数): 前缀和 + Hash Table。先查 count[prefix - k], 再 count[prefix] += 1, 初始 {0: 1}。

3. Subarray Sums Divisible by K

题目在问什么

数一数: 有多少段连续的 subarray, 和是 k 的倍数 (包括 0 和负数倍)。

看例子

Brute force

和第 2 题一样, 枚举所有 (i, j), O(n²)。

Intuition: 和是 k 的倍数 ⇔ 两个前缀和的余数相同

区间和 = prefix[j+1] - prefix[i]。它是 k 的倍数, 等价于两个前缀和除以 k 的余数相同。比如 k = 5, 前缀和 9 和 4 的余数都是 4, 相减 5 是倍数。

所以只要把第 2 题的 key 从"前缀和"换成"前缀和 % k", 查的也从 prefix - k 换成"和我余数相同的"。

Python 的 % 对负数也返回 0..k-1 (比如 -2 % 5 == 3), 所以不用特殊处理负数。

算法

  1. count = {0: 1}。从左往右累加 prefix。
  2. r = prefix % k。ans += count[r], 然后 count[r] += 1。

手动走一遍

变体 Continuous Subarray Sum: 问"是否存在长度 ≥ 2、和是 k 的倍数的 subarray"。只问存在、还有长度要求, 所以 dict 不存次数, 存这个余数第一次出现的下标。

复杂度

Time O(n), Space O(k)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def subarraysDivByK(nums, k): count = {0: 1} prefix = ans = 0 for x in nums: # Python 的 % 对负数也返回 0..k-1, 不用额外处理 prefix = (prefix + x) % k ans += count.get(prefix, 0) # 余数相同的前缀两两配对 count[prefix] = count.get(prefix, 0) + 1 return ans# Continuous Subarray Sum: 长度 >= 2, 和是 k 的倍数, 求 "存在"def checkSubarraySum(nums, k): first = {0: -1} # 余数 0 出现在下标 -1 (空前缀) prefix = 0 for i, x in enumerate(nums): prefix = (prefix + x) % k if prefix in first: if i - first[prefix] >= 2: # 长度至少 2 return True else: first[prefix] = i # 只记第一次: 越早越长, 不覆盖 return False

记:和是 k 的倍数: 用 prefix % k 当 key。数个数存次数; 问存在 / 最长存第一次出现的下标。

4. Contiguous Array

题目在问什么

数组只有 0 和 1。找最长的一段连续 subarray, 里面 0 和 1 的个数一样多, 返回长度。

看例子

Brute force

枚举所有段, 数 0 和 1, O(n²)。

Intuition: 先把题目变成"和为 0"

"0 和 1 一样多" 不是一个和。但如果把 0 看成 -1, 一样多就等价于这一段的和是 0。

和为 0 就是第 2 题 k = 0 的情况: 两个前缀和相等。

和第 2 题的区别是这题要最长, 不是个数。同一个前缀和值出现了好几次时, 用最早的那次当起点, 段最长。所以 dict 存的是每个前缀和第一次出现的下标, 之后再出现不覆盖。

起始放 {0: -1}, 表示空前缀在下标 -1 的位置, 这样从下标 0 开始的段长度也能算对。

算法

  1. first = {0: -1}, s = 0。
  2. 从左往右, 遇到 1 则 s += 1, 遇到 0 则 s -= 1。
  3. s 在 first 里: 用 i - first[s] 更新最长。s 不在: first[s] = i。

手动走一遍

同样的模板可以做 Maximum Size Subarray Sum Equals k: 查 prefix - k 第一次出现的位置。

复杂度

Time O(n), Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def findMaxLength(nums): first = {0: -1} # first[s] = s 第一次出现的下标 s = best = 0 for i, x in enumerate(nums): # 0 看成 -1: 0 和 1 一样多 <=> 区间和为 0 s += 1 if x == 1 else -1 if s in first: best = max(best, i - first[s]) # 长度 = i - first[s] else: first[s] = i # 求最长: 只记最早, 不覆盖 return best
# Maximum Size Subarray Sum Equals kdef maxSubArrayLen(nums, k): first = {0: -1} prefix = best = 0 for i, x in enumerate(nums): prefix += x if prefix - k in first: best = max(best, i - first[prefix - k]) if prefix not in first: # 先查后放, 且不覆盖 first[prefix] = i return best

记:"两种东西一样多": 一种记 +1, 一种记 -1, 变成和为 0。求最长: dict 存第一次出现的下标。

5. Product of Array Except Self

题目在问什么

返回一个数组 out, out[i] = nums 里除了 nums[i] 以外所有数的乘积。不能用除法, 要求 O(n)。

看例子

Example 2 解释了为什么不能用除法: 数组里有 0 时, "总积 ÷ nums[i]" 算不出来。

Brute force

每个 i, 把其他 n - 1 个数乘一遍。O(n²)。浪费: 相邻两个位置要乘的数几乎一样。

Intuition: 左边的积 × 右边的积

"除了 i 以外的所有数" = i 左边的所有数 + i 右边的所有数。所以 out[i] = (左边所有数的积) × (右边所有数的积)。

左边的积就是"前缀积", 从左往右一遍边乘边记。右边的积是"后缀积", 从右往左一遍。这就是 prefix sum 的思路, 只是把加法换成了乘法。

省空间的做法: 第一遍把左边的积直接写进 out; 第二遍从右往左, 用一个变量 r 记右边的积, 乘到 out 上。除了答案数组, 只用了一个变量。

算法

  1. 第一遍 (从左往右): out[i] = nums[0..i-1] 的积。out[0] = 1。
  2. 第二遍 (从右往左): r = 1。每个 i: out[i] *= r, 然后 r *= nums[i]。

手动走一遍

复杂度

Time O(n), 两遍。额外 Space O(1) (答案数组不算)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def productExceptSelf(nums): n = len(nums) out = [1] * n l = 1 # l = nums[0..i-1] 的乘积 for i in range(n): out[i] = l # 先存 "左边所有数的乘积" l *= nums[i] r = 1 # r = nums[i+1..n-1] 的乘积 for i in range(n - 1, -1, -1): out[i] *= r # 再乘 "右边所有数的乘积" r *= nums[i] return out # 额外空间 O(1) (out 是答案)

记:"除了自己以外的所有": 左边一遍、右边一遍。左边的结果存进答案, 右边用一个变量。

6. Range Sum Query 2D

题目在问什么

一个矩阵不会变。会被问很多次: 左上角 (r1, c1) 到右下角 (r2, c2) 的子矩形里所有数的和。

看例子

Brute force

每次两层循环把子矩形加一遍, 每次 O(m·n)。

Intuition: 一维的前缀和推广到二维

定义 P[i][j] = 矩阵左上角 i 行 j 列 (也就是第 0..i-1 行、第 0..j-1 列) 所有数的和。

要算一个子矩形, 先拿右下角对应的大矩形 P[r2+1][c2+1], 减掉上面多出来的一块 P[r1][c2+1], 再减掉左边多出来的一块 P[r2+1][c1]。但左上角那一小块被减了两次, 要加回来一次 P[r1][c1]。

建 P 的时候也是同样的道理: 当前格 + 上面 + 左边 - 左上角。

算法

  1. 建表: P[i+1][j+1] = matrix[i][j] + P[i][j+1] + P[i+1][j] - P[i][j]。
  2. 查询: P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]。

手动走一遍

复杂度

建表 O(m·n), 每次查询 O(1)。Space O(m·n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
class NumMatrix: def __init__(self, matrix): m, n = len(matrix), len(matrix[0]) # P[i][j] = matrix 左上角 i 行 j 列的和 self.P = [[0] * (n + 1) for _ in range(m + 1)] for i in range(m): for j in range(n): # P[i][j] 和 P[i+1][j] 重叠的部分加了两次, 减一次 self.P[i + 1][j + 1] = (matrix[i][j] + self.P[i][j + 1] + self.P[i + 1][j] - self.P[i][j]) def sumRegion(self, r1, c1, r2, c2): P = self.P return (P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]) # 左上角被减了两次, 加回来

记:二维前缀和: 大矩形 - 上面 - 左边 + 左上角。P 比矩阵多一行一列 0。

7. Corporate Flight Bookings (difference array)

题目在问什么

有 n 个航班, 编号 1 到 n。每条 booking [first, last, seats] 表示: 航班 first 到 last, 每一班都订了 seats 个座位。返回每个航班一共订了多少座位。

看例子

这题和前面方向相反。前面是"数组不变, 问很多次区间和"; 这里是"很多次给一个区间加一个数, 最后读一次结果"。

Brute force

每条 booking, 循环把 first..last 每个位置加 seats。m 条 booking, 每条最多 n 个位置, O(m·n)。

Intuition: 只记录变化的边界

一条 booking 给 [l, r] 每个位置加 v。换个角度看: 从左往右走, 走到 l 时数值开始多 v, 走过 r 之后又不再多 v。

所以只需要在两个边界做记号: diff[l] += v (从这里开始加), diff[r+1] -= v (从这里开始不加)。最后从左往右做一遍前缀和, 每个位置累计到的值就是答案。

这个 diff 数组叫 difference array (差分数组)。它和前缀和是互逆的: 对 diff 做前缀和, 得到原数组。

算法

  1. diff = [0] * (n + 1)。
  2. 每条 booking: diff[first-1] += seats, diff[last] -= seats (编号从 1 开始, 换成下标要减 1)。
  3. 对 diff 的前 n 项做前缀和, 就是答案。

手动走一遍

Car Pooling 是同一个模板: 乘客上车的位置 +num, 下车的位置 -num, 扫一遍看车上人数有没有超过 capacity。

复杂度

Time O(m + n), Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def corpFlightBookings(bookings, n): diff = [0] * (n + 1) # 多留一格: last 可能等于 n for first, last, seats in bookings: # 航班编号从 1 开始 diff[first - 1] += seats # 从 first 开始, 每个位置 +seats diff[last] -= seats # 过了 last 就抵消掉 ans, cur = [], 0 for i in range(n): cur += diff[i] # 对 diff 做 prefix sum = 还原 ans.append(cur) return ansdef carPooling(trips, capacity): diff = [0] * 1001 for num, start, end in trips: diff[start] += num diff[end] -= num # end 站已下车: 区间 [start, end) cur = 0 for dx in diff: cur += dx if cur > capacity: return False return True

记:很多次区间 +v, 最后才读: diff[l] += v, diff[r+1] -= v, 最后做一遍前缀和。

8. 什么时候用 sliding window, 什么时候用 prefix sum

03 · Sliding Window 和这篇都在处理"连续 subarray 的和"。到底用哪个, 只看一件事: 数组里有没有负数。

sliding window 成立的前提是: 右边加一个数, 和只会变大; 左边去掉一个数, 和只会变小。这样"和太大就缩左边"才是安全的。全是正数时成立, 比如 Minimum Size Subarray Sum。

有负数时这个前提没了: 后面的一个负数可以把和拉回来。下面的例子里, window 在和太大时扔掉了开头的 5, 结果漏掉了以 5 开头的答案:

前缀和 + Hash Table 不需要这个前提, 因为它不移动边界, 所有起点都留在 dict 里, 随时可以查。代价是空间从 O(1) 变成 O(n)。

代码: 全正数时的 window, 以及有负数时 window 的错误写法
# 全是正数: sliding windowdef minSubArrayLen(target, nums): left = total = 0 best = len(nums) + 1 for right, x in enumerate(nums): total += x # 右移: total 只会变大 while total >= target: # 够了就缩左边: total 只会变小 best = min(best, right - left + 1) total -= nums[left] left += 1 return best if best <= len(nums) else 0
# 错误示范: 把 window 套到 "有负数" 的 Subarray Sum Equals Kdef wrong(nums, k): left = total = ans = 0 for right, x in enumerate(nums): total += x while total > k and left <= right: # 以为 "超过 k 就缩左边" total -= nums[left] # 但后面的负数会把 total 拉回来 left += 1 if total == k: ans += 1 return ans

记:全是正数 → sliding window, O(1) 空间。有负数 → 前缀和 + Hash Table, O(n) 空间。
