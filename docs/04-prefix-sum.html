04 · Prefix Sum

主线: 区间和 = 两个前缀和之差。把 '每次重新加一遍' 换成 '建一次表, 之后 O(1) 查表'; 再把 '找起点' 变成 Hash Table 里的一次查找。

概念链: Range Sum / Find Pivot Index → Subarray Sum Equals K (prefix + Hash Table, 核心) → Subarray Sums Divisible by K (余数) → Contiguous Array (0 看成 -1) → Product of Array Except Self (前缀积 / 后缀积) → Range Sum Query 2D → Corporate Flight Bookings (difference array) → 和 sliding window 的分界

0. 第一性原理: brute force 在浪费什么

题目: 数组 nums 不变, 有很多次 query, 每次问 sum(nums[i..j])。

Brute force: 每次 query 从 i 加到 j, 最坏 O(n)。q 次 query 就是 O(n · q)。

浪费在哪: 不同的 query 重叠很多。sum(1..3) 和 sum(0..3) 都要把 nums[1..3] 重新加一遍。每个元素被反复加了很多次。

消掉的办法: 每个元素只加一次, 把 '从头加到 k' 的结果存下来, 叫 prefix[k]。任何区间都是两个 prefix 之差。

通用模板。prefix 比 nums 多一格, prefix[0] = 0 表示空前缀, 这样从下标 0 开始的区间也不需要特判:

# prefix[i] = nums[0] + ... + nums[i-1] prefix[0] = 0 (空前缀)prefix = [0] * (len(nums) + 1)for i, x in enumerate(nums): prefix[i + 1] = prefix[i] + x # 每个元素只加一次: O(n)def range_sum(i, j): # nums[i..j] 闭区间 return prefix[j + 1] - prefix[i] # 两次查表: O(1)

第二个模板是本 doc 的主角: 要的不是某个区间的和, 而是 '有多少个区间的和满足条件'。固定右端点 j, 区间和 = prefix_j - prefix_i, 所以满足条件就是对 prefix_i 提了一个要求。把之前所有的 prefix_i 放进 Hash Table, 这个要求就是一次查找 (下面第 2 节详细讲):

# 空前缀 prefix = 0 出现过 1 次, 让 "从下标 0 开始" 的 subarray 也能被数到count = {0: 1}prefix = ans = 0for x in nums: prefix += x need = prefix - k # 要找的起点 prefix 值 ans += count.get(need, 0) # 以当前位置结尾, 有多少个起点 count[prefix] = count.get(prefix, 0) + 1 # 先查再放: 起点在当前位置之前

复杂度: 建表 O(n), 每次 query O(1); 数区间时从 O(n²) (枚举所有 i, j) 降到 O(n)。

记:prefix 的本质: 'sum(i..j) = prefix[j+1] - prefix[i]', 每个元素只加一次。prefix[0] = 0 (空前缀) 要记得放。

1. Find Pivot Index: 左边和 == 右边和, prefix 的最小用法

题目: 找最左的下标 i, 使 nums[0..i-1] 之和 == nums[i+1..] 之和。例: [1, 7, 3, 6, 5, 6] → 3。

Brute force: 每个 i 把左边加一遍、右边加一遍, O(n²)。浪费: 相邻两个 i 的左边只差一个元素, 却整个重算。

关键观察: 左边和就是 prefix[i], 边走边累加即可; 右边和 = 总和 - 左边 - nums[i], 不用再加。这题不用建整个 prefix 数组, 一个变量 left 就是滚动的 prefix。

def pivotIndex(nums): total = sum(nums) left = 0 # nums[0..i-1] 之和 = prefix[i] for i, x in enumerate(nums): if left == total - left - x: # right = total - left - nums[i] return i left += x # 处理完 i, left 变成 prefix[i+1] return -1

Time O(n): 一次求 total, 一次扫描。Space O(1)。

记:prefix 不一定要存成数组。只要 '只问当前位置的 prefix', 一个滚动变量就够。

2. Subarray Sum Equals K: prefix + Hash Table (核心)

题目: 数 nums 里有多少个连续 subarray 的和等于 k。数组里可以有负数。例: nums = [3, 4, 7, 2, -3, 1, 4, 2], k = 7 → 4。

Brute force: 枚举起点 i 和终点 j, 区间和用 prefix 查表, 仍是 O(n²) 个 (i, j)。浪费: 固定 j 之后, 我们只想知道 '有几个 i 满足 prefix[j] - prefix[i] == k', 却把每个 i 都试了一遍。

关键观察: 条件移项, prefix[i] == prefix[j] - k。右边是已知数 (记作 need), 所以问题变成 '之前出现过几次值为 need 的 prefix', 这正是 Hash Table 的一次查找。做法: 从左到右扫, 对每个 j 先 ans += count[need], 再把当前 prefix 放进 count。

两个细节。第一, {0: 1}: 空前缀 prefix = 0 也是一个起点, 不放它, 从下标 0 开始的 subarray 就漏了 (图里 [3, 4] 就是靠它数到的)。第二, 先查再放: 起点必须严格在终点之前。

def subarraySum(nums, k): count = {0: 1} # 别忘了: 空前缀 0 出现 1 次 prefix = ans = 0 for x in nums: prefix += x need = prefix - k ans += count.get(need, 0) # 之前有多少个 prefix == need count[prefix] = count.get(prefix, 0) + 1 # 查完才放进去 return ans

Time O(n): 每个元素一次 Hash Table 查找和一次写入。Space O(n): count 最多 n + 1 项。

记:'连续 subarray + 和 == k' → prefix + Hash Table, 先查 count[prefix - k], 再 count[prefix] += 1, 初始 {0: 1}。

3. Subarray Sums Divisible by K: 把 prefix 换成 prefix % k

题目: 数有多少个连续 subarray 的和是 k 的倍数。例: [4, 5, 0, -2, -3, 1], k = 5 → 7。

相比上一题多了什么: 不要求和 == k, 而是和 % k == 0。模板只改一行, 不再找 prefix - k, 而是找 '余数相同的 prefix'。

为什么: (prefix[j] - prefix[i]) % k == 0 等价于 prefix[j] % k == prefix[i] % k。余数相同的 prefix 放进同一个桶, 同桶任意两个配成一个答案。

下面还放了同一族的 Continuous Subarray Sum (长度至少 2, 求 '是否存在'): '存在' 只需要知道最早的下标, 所以 dict 存第一次出现的位置, 不再存次数。

def subarraysDivByK(nums, k): count = {0: 1} prefix = ans = 0 for x in nums: # Python 的 % 对负数也返回 0..k-1, 不用额外处理 prefix = (prefix + x) % k ans += count.get(prefix, 0) # 余数相同的前缀两两配对 count[prefix] = count.get(prefix, 0) + 1 return ans# Continuous Subarray Sum: 长度 >= 2, 和是 k 的倍数, 求 "存在"def checkSubarraySum(nums, k): first = {0: -1} # 余数 0 出现在下标 -1 (空前缀) prefix = 0 for i, x in enumerate(nums): prefix = (prefix + x) % k if prefix in first: if i - first[prefix] >= 2: # 长度至少 2 return True else: first[prefix] = i # 只记第一次: 越早越长, 不覆盖 return False

Time O(n)。Space O(k) (余数只有 k 种, 也不会超过 n + 1)。

记:'和是 k 的倍数' → prefix % k 当 key。数个数存次数, 求存在 / 最长存最早下标。Python 的 % 对负数也给 0..k-1。

4. Contiguous Array: 把 0 看成 -1, 求最长

题目: 二进制数组, 找最长的连续 subarray, 里面 0 和 1 一样多, 返回长度。例: [0, 1, 1, 0, 1, 1, 1, 0] → 4。

相比上一题多了两个变化。一, 条件 '0 和 1 一样多' 不是和, 先变形: 0 看成 -1, 这样一样多 ⟺ 区间和 = 0 ⟺ 两个 prefix 相等 (就是第 2 节 k = 0)。二, 要最长而不是个数: 同一个 prefix 值出现多次时, 最早的那个起点最长, 所以只记第一次出现的下标, 不覆盖。

Brute force: 每个 subarray 数一遍 0 和 1, O(n²) (或 O(n³))。

def findMaxLength(nums): first = {0: -1} # first[s] = s 第一次出现的下标 s = best = 0 for i, x in enumerate(nums): # 0 看成 -1: 0 和 1 一样多 <=> 区间和为 0 s += 1 if x == 1 else -1 if s in first: best = max(best, i - first[s]) # 长度 = i - first[s] else: first[s] = i # 求最长: 只记最早, 不覆盖 return best

Time O(n), Space O(n)。同一模板还能解 Maximum Size Subarray Sum Equals k: need = prefix - k 去 first 里查, 查完再 '没有才放':

# Maximum Size Subarray Sum Equals kdef maxSubArrayLen(nums, k): first = {0: -1} prefix = best = 0 for i, x in enumerate(nums): prefix += x if prefix - k in first: best = max(best, i - first[prefix - k]) if prefix not in first: # 先查后放, 且不覆盖 first[prefix] = i return best

记:'两种东西一样多' → 一种记 +1, 另一种记 -1, 变成 '和为 0'。求最长: dict 存最早下标; 求个数: dict 存次数。

5. Product of Array Except Self: prefix 不只能是加法

题目: 返回 out, out[i] = 除 nums[i] 以外所有数的乘积, 不许用除法。例: [1, 2, 3, 4] → [24, 12, 8, 6]。

相比上一题多了什么: 不再问区间 '和', 而是 '除自己外的积'; 但结构一样, 把 + 换成 ×。Brute force: 每个 i 乘其余 n - 1 个数, O(n²)。浪费: 相邻两个 i 的积共享几乎所有因子。

关键观察: out[i] = (i 左边所有数的积) × (i 右边所有数的积)。左边的积是 prefix product, 右边的积是 suffix product。为什么不用除法: 有 0 时 '总积 / nums[i]' 不成立。

def productExceptSelf(nums): n = len(nums) out = [1] * n l = 1 # l = nums[0..i-1] 的乘积 for i in range(n): out[i] = l # 先存 "左边所有数的乘积" l *= nums[i] r = 1 # r = nums[i+1..n-1] 的乘积 for i in range(n - 1, -1, -1): out[i] *= r # 再乘 "右边所有数的乘积" r *= nums[i] return out # 额外空间 O(1) (out 是答案)

Time O(n): 两遍扫描。Space O(1) 额外: 左积直接存进 out (答案本身), 右积只用一个变量 r。

记:'除自己以外' → 左边一遍, 右边一遍。左边的结果存进答案数组, 右边用一个滚动变量, 额外空间 O(1)。

6. Range Sum Query 2D: 二维 prefix, 要用 inclusion-exclusion

题目: 矩阵不变, 多次 query 子矩形 (r1, c1) 到 (r2, c2) 的和。

Brute force: 每次 query 双重循环, O(m · n) 每次。

相比一维多了什么: 一维只要减一个 prefix, 二维要减两块 (上面和左边), 左上角被减了两次, 要加回来。P[i][j] 定义为左上角 i 行 j 列的和。建表时用同样的 inclusion-exclusion。

class NumMatrix: def __init__(self, matrix): m, n = len(matrix), len(matrix[0]) # P[i][j] = matrix 左上角 i 行 j 列的和 self.P = [[0] * (n + 1) for _ in range(m + 1)] for i in range(m): for j in range(n): # P[i][j] 和 P[i+1][j] 重叠的部分加了两次, 减一次 self.P[i + 1][j + 1] = (matrix[i][j] + self.P[i][j + 1] + self.P[i + 1][j] - self.P[i][j]) def sumRegion(self, r1, c1, r2, c2): P = self.P return (P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]) # 左上角被减了两次, 加回来

Time: 建表 O(m · n), 每个 query O(1)。Space O(m · n)。

记:二维 prefix: P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]。P 比 matrix 多一行一列 0, 和一维的 prefix[0] = 0 同理。

7. Corporate Flight Bookings: difference array, 区间加

题目: n 个航班, 每条 booking [first, last, seats] 表示航班 first..last 各订了 seats 个座位, 求每个航班的总座位数。例: [[1,2,10],[2,3,20],[2,5,25]], n = 5 → [10, 55, 45, 25, 25]。

这题和前面方向相反: 前面是 '先建 prefix, 再查区间'; 这里是 '很多次区间修改, 最后读一遍'。Brute force: 每个 booking 循环改 last - first + 1 个位置, O(m · n)。浪费: 区间里每个位置都被同一个 +v 各改一次。

关键观察: 只记录 '变化的边界'。difference array diff[i] = arr[i] - arr[i-1], 区间 [l, r] 加 v 只影响两个边界: diff[l] += v, diff[r+1] -= v。最后对 diff 做 prefix sum 就还原 arr。difference 和 prefix sum 是互逆的。

def corpFlightBookings(bookings, n): diff = [0] * (n + 1) # 多留一格: last 可能等于 n for first, last, seats in bookings: # 航班编号从 1 开始 diff[first - 1] += seats # 从 first 开始, 每个位置 +seats diff[last] -= seats # 过了 last 就抵消掉 ans, cur = [], 0 for i in range(n): cur += diff[i] # 对 diff 做 prefix sum = 还原 ans.append(cur) return ansdef carPooling(trips, capacity): diff = [0] * 1001 for num, start, end in trips: diff[start] += num diff[end] -= num # end 站已下车: 区间 [start, end) cur = 0 for dx in diff: cur += dx if cur > capacity: return False return True

Time O(m + n): m 个 booking 各 O(1), 加一遍 prefix sum。Space O(n)。Car Pooling 是同一个模板: 每次上车 +num, 下车 -num, 扫一遍看 cur 有没有超过 capacity。

记:'很多次区间 +v, 最后才读结果' → diff[l] += v, diff[r+1] -= v, 最后 prefix sum。

8. 和 sliding window 的分界: 有负数时 window 为什么失效

同样是 '连续 subarray 的和', 什么时候用 window, 什么时候用 prefix + Hash Table? 看元素有没有负数。

Sliding window 成立的前提是单调: 右端点右移, 和只会变大; 左端点右移, 和只会变小。有了这个单调性, '和超过目标就缩左边' 是安全的, 因为再往右加只会更大, 被丢掉的左端点不可能再变成答案。全正数的 Minimum Size Subarray Sum 就是这个情形:

# 全是正数: sliding windowdef minSubArrayLen(target, nums): left = total = 0 best = len(nums) + 1 for right, x in enumerate(nums): total += x # 右移: total 只会变大 while total >= target: # 够了就缩左边: total 只会变小 best = min(best, right - left + 1) total -= nums[left] left += 1 return best if best <= len(nums) else 0

有负数时单调性没了: 后面的 -2 可以把和拉回来。下面把 window 套到 Subarray Sum Equals K 上, 在 [5, -2, 0], k = 3 上失败:

# 错误示范: 把 window 套到 "有负数" 的 Subarray Sum Equals Kdef wrong(nums, k): left = total = ans = 0 for right, x in enumerate(nums): total += x while total > k and left <= right: # 以为 "超过 k 就缩左边" total -= nums[left] # 但后面的负数会把 total 拉回来 left += 1 if total == k: ans += 1 return ans

prefix + Hash Table 不依赖单调性: 它不移动任何边界, 每个起点都留在 Hash Table 里, 随时可以查。代价是 Space 从 O(1) 变成 O(n)。

记:元素全为正 (和单调) → sliding window, O(1) 空间。有负数 → prefix + Hash Table, O(n) 空间。
