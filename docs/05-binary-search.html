05 · Binary Search

这篇讲什么

先想一个猜数字游戏: 我心里想一个 1 到 100 的数, 你每猜一次, 我告诉你"大了"还是"小了"。最笨的办法是从 1 开始一个一个猜, 最多 100 次。聪明的办法是先猜 50: 如果"大了", 1..50 以外的一半直接排除。每猜一次排除一半, 最多 7 次 (log₂ 100 ≈ 7)。

这就是 Binary Search。它能用的前提是: 问一次, 就能确定答案在哪一半。排好序的数组满足这个前提, 但这篇会看到, 很多没有排序的问题也满足 (旋转数组、找 peak、二分答案)。

复杂度从 O(n) 降到 O(log n)。n = 10⁹ 时, 线性要 10 亿步, 二分只要 30 步。

每道题的顺序: 题目在问什么 → 看例子 → brute force → intuition → 算法 → 手动走一遍 → 复杂度。代码放在最后, 默认折叠。

二分最容易错的是边界 (lo、hi、mid 怎么更新, 会不会死循环)。这篇全程只用一个写法, 讲完第 1 题后会专门讲它, 之后每题只换"条件", 不换写法。

1. Find First and Last Position of Element in Sorted Array

题目在问什么

数组 nums 从小到大排好, 可能有重复。找 target 第一次出现和最后一次出现的下标。没有就返回 [-1, -1]。要求 O(log n)。

看例子

Brute force

从左往右扫一遍, 记下第一个和最后一个等于 target 的位置。O(n)。浪费: 数组已经排好序, "左边都小、右边都大"这个信息完全没用上。

Intuition: 把"等于 target"换成"≥ target"

直接问"nums[i] 等于 target 吗"没法二分: 结果是 否 否 否 是 是 否, 看到一个"否", 你不知道答案在左边还是右边。

换个问法: "nums[i] ≥ target 吗?" 对 [5,7,7,8,8,10], target = 8, 结果是 否 否 否 是 是 是。前面一段全是"否", 后面一段全是"是", 中间只有一个分界点。这就可以二分了: 问一下中间, 是"是", 分界点在左边 (或就是这里); 是"否", 分界点在右边。

第一个"是"的位置, 就是 target 第一次出现的位置 (index 3)。

最后一次出现: 问 "nums[i] > target 吗?", 结果是 否 否 否 否 否 是。第一个"是"在 index 5, 减 1 就是 8 最后一次出现的位置 (index 4)。

如果第一个 ≥ target 的位置上的数不等于 target (或者越界了), 说明 target 不存在。

算法

  1. 找第一个满足 nums[i] >= target 的位置, 记为 left。
  2. 如果 left 越界, 或者 nums[left] != target, 返回 [-1, -1]。
  3. 找第一个满足 nums[i] > target 的位置, 记为 right。返回 [left, right - 1]。

"找第一个满足条件的位置" 怎么写, 下一节专门讲。

手动走一遍

复杂度

Time O(log n), 两次二分。Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def search_range(nums, target): n = len(nums) left = first_true(0, n, lambda i: nums[i] >= target) # bisect_left right = first_true(0, n, lambda i: nums[i] > target) # bisect_right if left == right: # 两个分界点重合 = 中间没有 == target 的数 return [-1, -1] return [left, right - 1] # [left, right) 里全是 target

记:找"等于 x": 改成找"第一个 ≥ x", 再检查是不是 x。最后一个 x = 第一个 > x 的位置 - 1。

把第 1 题抽象一下: 一个写法解决所有二分

第 1 题里, 我们做的事情都是同一件: 有一个条件 pred(i), 它在 i 从小到大时是 否 否 ... 否 是 是 ... 是, 要找第一个"是"的位置。

这个条件可以是任何东西, 只要满足"前面全否、后面全是"。这才是二分的本质, 不是"数组排好序"。排好序只是让 nums[i] >= x 恰好满足这个形状。后面的题都是在找不同的 pred。

写法 (全篇只用这一个, 叫 first_true):

  1. 在 [lo, hi) 里找 (左闭右开)。保持两件事一直成立: lo 左边的都已确认是"否", hi 和 hi 右边的都已确认是"是"。
  2. 当 lo < hi: 取 mid = (lo + hi) // 2。
  3. pred(mid) 是"是": 答案在 mid 或 mid 左边, hi = mid。
  4. pred(mid) 是"否": 答案在 mid 右边, lo = mid + 1。
  5. 结束时 lo == hi, 就是第一个"是"。如果全是"否", 返回的是原来的 hi (越界), 调用的地方要检查。

为什么不会死循环: 因为 lo ≤ mid < hi, 两个分支都让范围严格变小。如果写成 lo = mid, 当 hi = lo + 1 时 mid = lo, 就永远不动了。

Python 里 bisect_left(a, x) 就是 pred = a[i] >= x 的 first_true, bisect_right(a, x) 是 a[i] > x。

first_true 模板代码
def first_true(lo, hi, pred): """在 [lo, hi) 里找第一个 pred 为 True 的位置, 都是 False 就返回 hi。 前提: pred 在 [lo, hi) 上是 False...False True...True (单调)。""" while lo < hi: # invariant: < lo 全是 False, >= hi 全是 True mid = (lo + hi) // 2 # lo <= mid < hi, 所以 mid 一定在区间里 if pred(mid): hi = mid # mid 是 True: 分界点在 mid 或 mid 左边, mid 留着 else: lo = mid + 1 # mid 是 False: 分界点一定在 mid 右边, mid 丢掉 return lo # lo == hi: 就是分界点

记:二分 = 找一个"前面全否、后面全是"的条件, 找第一个"是"。是: hi = mid; 否: lo = mid + 1; 返回 lo。

2. Find Minimum in Rotated Sorted Array

题目在问什么

一个从小到大排好序、元素不重复的数组, 被"旋转"了若干次: 把开头一段剪下来接到最后。比如 [1,2,3,4,5] 旋转后可能变成 [3,4,5,1,2]。找最小值, 要求 O(log n)。

看例子

旋转后的数组是两段各自排好序的数组拼起来的。左段的数都比右段大。最小值是右段的第一个。

Brute force

min(nums), O(n)。

Intuition: 找一个"前面全否、后面全是"的条件

整个数组不是排好序的, 不能直接用 nums[i] >= x。但我们可以和最后一个数 last = nums[-1] 比较:

  • 左段的每个数都 > last (左段整体比右段大, last 是右段的最后一个)。
  • 右段的每个数都 ≤ last (右段是排好序的, last 是右段最大的)。

所以 pred(i) = nums[i] <= last 在左段全是"否", 在右段全是"是"。第一个"是"就是右段的开头, 也就是最小值。直接套 first_true。

算法

  1. last = nums[-1]。
  2. i = first_true(0, n, lambda i: nums[i] <= last)。
  3. 返回 nums[i]。

手动走一遍

复杂度

Time O(log n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def find_min(nums): last = nums[-1] # 左段 (旋转前较大的那段) 全 > last, 右段全 <= last: False...False True...True i = first_true(0, len(nums), lambda i: nums[i] <= last) return nums[i]

记:旋转数组: 拿最后一个数当尺子, nums[i] <= nums[-1] 就是可以二分的条件。

3. Search in Rotated Sorted Array

题目在问什么

同样是旋转过的排序数组 (元素不重复)。这次找 target 的下标, 没有返回 -1。要求 O(log n)。

看例子

Brute force

线性扫一遍, O(n)。

一个可行的 O(log n) 做法: 先用第 2 题找到最小值的位置 p, 数组就分成了两段排好序的 [0, p) 和 [p, n), 再根据 target 的大小选一段做第 1 题的二分。两次二分。

Intuition: 从 mid 切开, 总有一半是排好序的

面试里更常见的是一次二分的写法。关键观察: 从 mid 把当前范围切成左右两半, 旋转的那个"断点"只可能在其中一半里, 所以另一半一定是排好序的。

怎么知道哪一半是排好序的? 看 nums[lo] <= nums[mid]: 成立就是左半有序, 否则右半有序。

有序的那一半, 只看两个端点就知道 target 在不在里面。在, 就去这一半; 不在, 就去另一半。

算法

  1. lo = 0, hi = n - 1。当 lo ≤ hi: 取 mid, 如果 nums[mid] == target 返回 mid。
  2. 如果左半有序 (nums[lo] <= nums[mid]): target 在 [nums[lo], nums[mid]) 里就 hi = mid - 1, 否则 lo = mid + 1。
  3. 否则右半有序: target 在 (nums[mid], nums[hi]] 里就 lo = mid + 1, 否则 hi = mid - 1。
  4. 循环结束返回 -1。

注意这题没有用 first_true 写法, 因为它不是"找第一个满足条件的", 而是"找某个值"。这里用的是闭区间, 不变的是"target 如果存在, 一定在 [lo, hi] 里"。

手动走一遍

复杂度

Time O(log n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def search(nums, target): lo, hi = 0, len(nums) # invariant: target 如果存在, 一定在 [lo, hi) 里 while lo < hi: mid = (lo + hi) // 2 if nums[mid] == target: return mid if nums[lo] <= nums[mid]: # 左半 [lo, mid] 有序 if nums[lo] <= target < nums[mid]: # target 在有序的左半里 hi = mid else: lo = mid + 1 else: # 否则右半 [mid, hi-1] 有序 if nums[mid] < target <= nums[hi - 1]: # target 在有序的右半里 lo = mid + 1 else: hi = mid return -1

记:旋转数组里找数: 从 mid 切开, 总有一半有序; target 在有序那半里就进去, 否则去另一半。

4. Find Peak Element

题目在问什么

peak 是比左右两个邻居都大的元素。数组两端的外面当作 -∞。相邻元素不相等。返回任意一个 peak 的下标。要求 O(log n)。

看例子

Brute force

从左往右扫, 第一个 nums[i] > nums[i+1] 的就是 peak。O(n)。

Intuition: 往上坡走, 一定能走到 peak

这个数组完全没有排序。但看 mid 和它右边的邻居 mid+1:

  • 上坡 (nums[mid] < nums[mid+1]): 从 mid+1 一直往右走。要么中途开始下坡, 下坡前的那个点就是 peak; 要么一直上坡到最后一个元素, 它右边是 -∞, 它也是 peak。所以右边一定有 peak, 去右边。
  • 下坡 (nums[mid] > nums[mid+1]): 同理, mid 自己或者 mid 左边一定有 peak, 去左边 (保留 mid)。

用 first_true 的话, pred 就是 nums[i] > nums[i+1] ("这里是下坡吗")。它整体不一定是"前面全否、后面全是", 但每一步的判断都是对的: 上坡就往右, 下坡就往左, 最后停下的地方一定是 peak。

算法

  1. lo = 0, hi = n - 1。当 lo < hi: 取 mid。
  2. nums[mid] < nums[mid+1] (上坡): lo = mid + 1。否则 (下坡): hi = mid。
  3. 返回 lo。

手动走一遍

复杂度

Time O(log n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def find_peak(nums): n = len(nums) # pred(i): "i 右边更低"。nums[n] 当作 -inf, 所以 pred(n-1) 一定是 True return first_true(0, n, lambda i: i == n - 1 or nums[i] > nums[i + 1])

记:没排序, 但能比较 mid 和邻居: 看坡度, 往上坡走一定有 peak。

5. Koko Eating Bananas

题目在问什么

piles[i] 是第 i 堆香蕉的数量。Koko 每小时选一堆吃 k 根; 这一堆不够 k 根, 就吃完这一堆, 这一小时也就结束了 (不会去吃下一堆)。要在 h 小时内吃完所有香蕉, 求最小的整数速度 k。

看例子

一堆 p 根香蕉、速度 k, 要 ceil(p / k) 小时。总小时数就是每堆加起来。

Brute force

从 k = 1 开始一个一个试: 算总小时数, 第一个 ≤ h 的 k 就是答案。每个 k 要 O(n), 最多试 max(piles) 个。如果某堆有 10⁹ 根, 就跑不完了。

Intuition: 二分答案

这道题没有一个可以二分的数组。但是看"k 能不能在 h 小时内吃完"这个问题:

  • k 越大, 吃得越快, 需要的小时数只会越少。
  • 所以如果 k 行, 比 k 大的都行; 如果 k 不行, 比 k 小的都不行。
  • "k 行不行" 在 k = 1, 2, 3, ... 上就是 否 否 ... 否 是 是 ... 是。

这正是 first_true 要的形状。二分的对象不是数组下标, 而是答案 k 本身。这叫二分答案。

二分答案的三步:

  1. 写一个 feasible(k): 给定一个候选答案, 用 O(n) 判断它行不行。
  2. 确定范围: 答案最小可能是多少, 最大可能是多少。这题 k 最小是 1, 最大是 max(piles) (每小时吃完最大的一堆, 一定够)。
  3. 在这个范围上用 first_true 找第一个 feasible 的 k。

算法

  1. feasible(k) = sum(ceil(p / k) for p in piles) <= h。
  2. first_true(1, max(piles) + 1, feasible)。

手动走一遍

复杂度

Time O(n log max(piles)): 二分 log max(piles) 轮, 每轮 feasible 是 O(n)。Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def min_eating_speed(piles, h): def feasible(k): # 速度 k 能不能在 h 小时内吃完 # (p + k - 1) // k = ceil(p / k): 这堆要吃几小时 return sum((p + k - 1) // k for p in piles) <= h return first_true(1, max(piles) + 1, feasible) # 答案在 [1, max(piles)]

记:答案有范围, 能 O(n) 验证一个候选值, 而且候选值越大越容易满足: 对答案二分。

6. Capacity To Ship Packages Within D Days

题目在问什么

包裹 weights 按顺序装船, 每天开一船, 一船最多装 cap 的重量。不能拆包裹, 也不能改顺序。要在 days 天内运完, 求最小的 cap。

看例子

Brute force

从 cap = max(weights) 开始往上试, 每个 cap 模拟一遍装船 O(n), 最多试到 sum(weights)。O(n × sum)。

Intuition: 和第 5 题一样, 只换 feasible

cap 越大, 每船装得越多, 需要的天数只会越少。所以"cap 行不行"也是"前面全否、后面全是", 可以二分答案。

唯一不同的是 feasible 怎么写: 给定 cap, 最少要几天? 用贪心: 从头开始装, 当前这船装得下就装, 装不下就开下一船。这样用的天数一定最少。

范围: cap 至少是 max(weights) (最重的包裹要装得下), 最多是 sum(weights) (一天全运完)。

算法

  1. feasible(cap): 贪心装船, 数天数, 判断 ≤ days。
  2. first_true(max(weights), sum(weights) + 1, feasible)。

手动走一遍

复杂度

Time O(n log(sum)), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def ship_within_days(weights, days): def feasible(cap): # 载重 cap 能不能在 days 天内运完 need, load = 1, 0 # need = 已经用了几天, load = 今天已装多少 for w in weights: if load + w > cap: # 今天装不下了: 另起一天 need += 1 load = 0 load += w return need <= days # 答案在 [max(weights), sum(weights)] return first_true(max(weights), sum(weights) + 1, feasible)

记:feasible 可以是任何 O(n) 的验证, 公式或者贪心。范围下限是"单个元素必须放得下", 上限是"全部放在一起"。

7. Split Array Largest Sum

题目在问什么

把数组 nums 切成 k 段连续的 subarray。每段有一个和, 其中最大的那个叫"最大段和"。怎么切能让最大段和最小? 返回这个最小值。

看例子

Brute force

枚举所有切法: 在 n - 1 个空隙里选 k - 1 个切, 组合数很大。也可以用 DP, O(k·n²)。

浪费: 题目最后要的只是一个数 (最小的最大段和), 却在枚举所有的切法。

Intuition: 反过来问

把问题反过来: "如果每段的和都不能超过 x, 最少要切几段?" 这个可以贪心回答: 从头开始加, 加上下一个数会超过 x 就另起一段。

x 越大, 需要的段数只会越少。所以"最少段数 ≤ k" 在 x 上是"前面全否、后面全是"。第一个"是"的 x 就是答案。

你会发现这和第 6 题是同一道题: days 就是 k, cap 就是 x, weights 就是 nums。代码一行不差。

"最小的最大值" (minimize the maximum) 是二分答案最典型的信号。

算法

  1. feasible(x): 贪心切段, 段数 ≤ k 就是 True。
  2. first_true(max(nums), sum(nums) + 1, feasible)。

手动走一遍

反过来的"最大的最小值" (比如 Magnetic Force Between Two Balls): x 越大越难满足, 形状是"前面全是、后面全否", 要找最后一个"是"。用 last_true (代码里有)。

复杂度

Time O(n log(sum)), 比 DP 的 O(k·n²) 快很多。Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def split_array(nums, k): def feasible(x): # 每段和都 <= x, 最少要切几段? 够不够 k 段 pieces, cur = 1, 0 for v in nums: if cur + v > x: # 当前段再加 v 就超 x: 另起一段 pieces += 1 cur = 0 cur += v return pieces <= k # 答案在 [max(nums), sum(nums)] return first_true(max(nums), sum(nums) + 1, feasible)
def last_true(lo, hi, pred): """pred 是 True...True False...False 时, 找最后一个 True; 没有就返回 lo - 1。""" return first_true(lo, hi, lambda x: not pred(x)) - 1

记:"最小的最大值": 二分这个最大值 x, 贪心验证。"最大的最小值": 同理, 找最后一个满足的。

8. Search a 2D Matrix

题目在问什么

m × n 的矩阵, 每行从小到大, 而且每行的第一个数大于上一行的最后一个数。判断 target 在不在矩阵里, 要求 O(log(m·n))。

看例子

Brute force

全部扫一遍, O(m·n)。

Intuition: 当成一维数组

题目的两个条件合起来, 意思是: 按行连起来读, 就是一个排好序的、长度 m·n 的一维数组。

不需要真的把它拼出来。一维的下标 i 对应矩阵的第 i // n 行、第 i % n 列。然后就是第 1 题的二分。

算法

  1. 在 [0, m·n) 上找第一个 matrix[i // n][i % n] >= target 的 i。
  2. i 没越界, 而且那个位置等于 target, 返回 True。

手动走一遍

复杂度

Time O(log(m·n)), Space O(1)。

变体 Search a 2D Matrix II 只保证每行、每列各自排好序, 拼不成一维。那题不用二分: 从右上角出发, 当前数比 target 大就往左, 比 target 小就往下, O(m + n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def search_matrix(matrix, target): m, n = len(matrix), len(matrix[0]) # 把 m x n 看成长度 m*n 的 sorted 数组: 下标 i <-> (i // n, i % n) i = first_true(0, m * n, lambda i: matrix[i // n][i % n] >= target) return i < m * n and matrix[i // n][i % n] == target

9. Median of Two Sorted Arrays (简述)

题目在问什么

两个排好序的数组 A 和 B, 求它们合并之后的中位数。要求 O(log(m + n))。

看例子

Brute force

合并两个数组 (02 里的 merge), 取中间。O(m + n)。

Intuition: 二分"左半边从 A 拿几个"

中位数只取决于一件事: 合并后的数组怎么分成"左半"和"右半"。左半一共要放 half = (m + n + 1) // 2 个数。

如果左半从 A 拿 i 个 (A 的前 i 个), 那从 B 就要拿 j = half - i 个。所以只有一个未知数 i。

i 对不对, 看交界处的 4 个数: 要求 A[i-1] ≤ B[j] 并且 B[j-1] ≤ A[i] (左半的最大值不超过右半的最小值)。如果 A[i-1] > B[j], 说明 A 拿多了, i 要变小; 否则 i 可以变大。这又是一个可以二分的条件。

找到 i 之后, 中位数就是左半最大值 (总数是奇数时), 或者左半最大值和右半最小值的平均 (偶数时)。

手动走一遍

复杂度

Time O(log min(m, n)): 在较短的数组上二分。Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def find_median(A, B): if len(A) > len(B): A, B = B, A # 在短的那个上二分: A 里取 i 个放进左半 m, n = len(A), len(B) half = (m + n + 1) // 2 # 左半共 half 个: A 取 i, B 取 j = half - i INF = float("inf") def cut_too_small(i): # pred(i): A 取得够多了吗? F...F T...T # i == m: A 全进左半; 否则 A[i] (在右半) 不能比 B[j-1] (在左半) 小 return i == m or A[i] >= B[half - i - 1] i = first_true(max(0, half - n), m + 1, cut_too_small) j = half - i left_max = max(A[i - 1] if i > 0 else -INF, B[j - 1] if j > 0 else -INF) right_min = min(A[i] if i < m else INF, B[j] if j < n else INF) if (m + n) % 2: return left_max return (left_max + right_min) / 2

记:二分的对象可以是"分割点"。先把问题写成"某个整数变量上的、前面全否后面全是的条件", 剩下就是 first_true。
