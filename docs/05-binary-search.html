05 · Binary Search

主线: binary search 的本质不是 "sorted array", 而是 "存在一个单调的 predicate, 答案是 False → True 的分界点"。全文只用一个模板 first_true, 每道题只是换 pred 和搜索范围。

概念链: first_true 模板 → First/Last Position (换 pred: >= 和 >) → Find Min in Rotated (和 nums[-1] 比出单调) → Search in Rotated (哪半有序) → Find Peak (没有 sorted, 局部单调) → Koko → Capacity → Split Array (二分答案, feasible 单调) → 2D Matrix (下标换成 i // n, i % n) → Median of Two Sorted Arrays (二分分割点)。

0. 第一性原理: brute force 在浪费什么

问题的统一形式: 在下标 (或答案) 范围 [lo, hi) 上有一个 pred(x), 它是 False ... False True ... True。要找第一个 True 的位置, 也就是 False → True 的分界点。

Brute force: 从左往右一个个算 pred, 遇到第一个 True 停。最坏 O(n) 次 pred。

浪费在哪: 单调性已经告诉我们 "pred(mid) 是 True ⇒ mid 右边全是 True", "pred(mid) 是 False ⇒ mid 左边全是 False"。一次 pred(mid) 的结果其实回答了半个区间, brute force 却把这半个区间里的 pred 一个个重新算。每问一次丢掉一半, 只要问 O(log n) 次。

sorted array 只是特例: 在 sorted 数组里找 target, 是因为 nums[i] >= target 刚好单调。换一个 pred, 数组不 sorted 也能二分 (rotated, peak); 甚至没有数组, 直接对答案本身二分 (Koko)。所以做题时先问自己: 我能写出一个 False...False True...True 的 pred 吗?

统一模板 (全文只用这一个, 区间一律左闭右开 [lo, hi)):

def first_true(lo, hi, pred): """在 [lo, hi) 里找第一个 pred 为 True 的位置, 都是 False 就返回 hi。 前提: pred 在 [lo, hi) 上是 False...False True...True (单调)。""" while lo < hi: # invariant: < lo 全是 False, >= hi 全是 True mid = (lo + hi) // 2 # lo <= mid < hi, 所以 mid 一定在区间里 if pred(mid): hi = mid # mid 是 True: 分界点在 mid 或 mid 左边, mid 留着 else: lo = mid + 1 # mid 是 False: 分界点一定在 mid 右边, mid 丢掉 return lo # lo == hi: 就是分界点

为什么不会死循环: 进循环时 lo < hi, 所以 lo <= mid < hi。True 分支 hi = mid 让 hi 严格变小; False 分支 lo = mid + 1 让 lo 严格变大。每轮区间长度至少减 1, 一定终止。如果写成 lo = mid, 在 lo = 3, hi = 4 时 mid = 3, lo 不动, 死循环。

返回值: 返回 lo。如果整段都是 False, lo 一路走到 hi, 返回 hi (= n), 表示 "没有 True"。所以调用方要检查 i < n。

complexity: pred 调用 O(log(hi - lo)) 次, 总时间 = O(log n × 单次 pred 的代价)。后面 "二分答案" 里单次 pred 是 O(n), 总 O(n log range)。

Python 的 bisect_left(a, x) 就是 first_true(0, n, lambda i: a[i] >= x), bisect_right 是 a[i] > x。Python 3.10+ 的 bisect_left(range(lo, hi), True, key=pred) 甚至可以直接对 pred 二分; 不确定版本就手写上面 8 行, 面试里直接内联进每道题也行。

记:先找 pred, 再套 first_true。lo 左边全 False, hi 及右边全 True; True 分支 hi = mid, False 分支 lo = mid + 1; 返回 lo。

1. Find First and Last Position: 同一个模板, 换两个 pred

题目: sorted 数组 nums, 找 target 第一次和最后一次出现的下标, 没有返回 [-1, -1]。例: nums = [5, 7, 7, 8, 8, 8, 10, 12], target = 8 → [3, 5]。(Binary Search / Search Insert Position 就是这题的一半: 只要 left。)

Brute force: 线性扫一遍记下第一个和最后一个, O(n)。浪费: 数组已经 sorted, 却完全没用到 "左边都小、右边都大"。

关键观察: "等于 target" 本身不单调 (F F T T T F F), 但 ">= target" 是 F F T T T T T, "> target" 是 F F F F F T T 都单调。第一个 >= target 的位置是 left, 第一个 > target 的位置是 right, [left, right) 里恰好全是 target。把 "找等于" 改写成 "找第一个 >=" 是二分最重要的一步。

def search_range(nums, target): n = len(nums) left = first_true(0, n, lambda i: nums[i] >= target) # bisect_left right = first_true(0, n, lambda i: nums[i] > target) # bisect_right if left == right: # 两个分界点重合 = 中间没有 == target 的数 return [-1, -1] return [left, right - 1] # [left, right) 里全是 target

Time: O(log n), 两次二分。Space: O(1)。

记:"找等于 x" → 改成 "第一个 >= x" 再检查; 最后一个 = 第一个 > x 的位置 - 1。

2. Find Minimum in Rotated Sorted Array: 找出隐藏的单调 predicate

题目: 元素不重复的 sorted 数组被旋转过 (比如 [1..9] 变成 [4,5,6,7,8,9,1,2,3]), 找最小值。

Brute force: min(nums), O(n)。浪费: 数组由两段 sorted 拼成, 最小值就是断开的位置, 这个信息没用上。

相比上一题: 数组整体不 sorted, 所以没法直接 >= target。但可以和最后一个元素比: 左段全部大于 last, 右段全部 <= last, 于是 nums[i] <= last 是 False...False True...True。第一个 True 就是最小值。只改 pred, 模板一行不动。

def find_min(nums): last = nums[-1] # 左段 (旋转前较大的那段) 全 > last, 右段全 <= last: False...False True...True i = first_true(0, len(nums), lambda i: nums[i] <= last) return nums[i]

Time: O(log n)。Space: O(1)。有重复元素的变体 (Find Minimum II) 会出现 nums[mid] == last 判断不了的情况, 只能 hi -= 1 一格一格缩, 最坏 O(n), 这里不展开。

记:rotated 数组: 拿 nums[-1] 当尺子, nums[i] <= nums[-1] 就是单调 pred。

3. Search in Rotated Sorted Array: 总有一半是有序的

题目: 同样的 rotated 数组 (元素不重复), 找 target 的下标, 没有返回 -1。例: nums = [4,5,6,7,8,9,1,2,3], target = 3 → 8。

Brute force: 线性扫, O(n)。可行的 2 步做法: 先用上一题找到最小值的下标 p, 再选 [0, p) 或 [p, n) 其中有序的一段用 first_true, 总共 2 次 O(log n), 完全合法。

一次二分的做法 (面试更常见): 把 [lo, hi) 从 mid 切开, 旋转点只可能在其中一侧, 所以另一侧一定有序。有序的那一侧用两个端点 O(1) 就能判断 target 在不在里面: 在就进去, 不在就去另一侧。这里的 invariant 不是 "False/True", 而是 "target 如果存在, 一定在 [lo, hi) 里"; 判定方式换了, 区间一样左闭右开, 每轮至少缩 1, 不会死循环。

def search(nums, target): lo, hi = 0, len(nums) # invariant: target 如果存在, 一定在 [lo, hi) 里 while lo < hi: mid = (lo + hi) // 2 if nums[mid] == target: return mid if nums[lo] <= nums[mid]: # 左半 [lo, mid] 有序 if nums[lo] <= target < nums[mid]: # target 在有序的左半里 hi = mid else: lo = mid + 1 else: # 否则右半 [mid, hi-1] 有序 if nums[mid] < target <= nums[hi - 1]: # target 在有序的右半里 lo = mid + 1 else: hi = mid return -1

Time: O(log n)。Space: O(1)。有重复元素 (Search in Rotated II) 时 nums[lo] == nums[mid] 分不清哪半有序, 只能 lo += 1, 最坏 O(n)。

记:旋转数组: 切开 mid, 一半必有序; target 在有序那半就进去, 否则去另一半。

4. Find Peak Element: 没有 sorted, 只有局部单调

题目: 相邻元素不相等的数组, 找任意一个 peak (比左右邻居都大), 越界的邻居当作 -inf。例: [1,2,3,5,4,6,7,9,8,3,1] → 7 (值 9) 或 3 (值 5) 都对。

Brute force: 扫一遍找 nums[i] > nums[i+1], O(n)。

关键观察: 数组完全无序, 但看 mid 和 mid+1 就知道往哪边走: 上坡 (nums[mid] < nums[mid+1]) → 一直往右走, 要么中途遇到下坡 (那里是 peak), 要么走到尽头 (尽头外是 -inf, 最后一个元素是 peak), 所以右边一定有 peak; 下坡 → mid 自己或左边一定有 peak。每步都能丢一半, 且保证 "peak 还在剩下的里面"。

相比上一题: pred 换成 nums[i] > nums[i+1]。它整体并不 F...F T...T (图里 5 → 4 就是下坡, 后面又上坡), 但二分只需要局部保证: lo 左边那个数比 lo 小 (上坡进来的), hi 处是下坡。最后 lo == hi 时两头都成立, lo 就是 peak。

def find_peak(nums): n = len(nums) # pred(i): "i 右边更低"。nums[n] 当作 -inf, 所以 pred(n-1) 一定是 True return first_true(0, n, lambda i: i == n - 1 or nums[i] > nums[i + 1])

Time: O(log n)。Space: O(1)。

记:无序但能比较 mid 和邻居 → 看坡度, 往上坡走一定有 peak; Mountain Array 找山顶是同一个写法。

5. Koko Eating Bananas: 二分答案, feasible(x) 单调

题目: piles 是每堆香蕉数, 每小时选一堆吃 k 根 (不够 k 就吃完这堆, 当小时结束)。要在 h 小时内吃完, 求最小的整数速度 k。例: piles = [3,6,7,11], h = 8 → 4。

Brute force: 从 k = 1 开始试, 每个 k 花 O(n) 算小时数, 最多试 max(piles) 个 k, 总 O(n × max(piles))。piles 里有 1e9 时跑不完。

浪费在哪: k 越大小时数只会越少, 所以 "k 能吃完吗" 是 False...False True...True。试了 k = 3 不行, 就没必要再试 1 和 2; 试了 k = 6 行, 就没必要再试 7..11。二分的对象不是数组, 是答案 k 本身。

怎么写: 1) 写 feasible(k): O(n) 验证一个候选值; 2) 定范围 [最小可能答案, 最大可能答案]; 3) 套 first_true。

def min_eating_speed(piles, h): def feasible(k): # 速度 k 能不能在 h 小时内吃完 # (p + k - 1) // k = ceil(p / k): 这堆要吃几小时 return sum((p + k - 1) // k for p in piles) <= h return first_true(1, max(piles) + 1, feasible) # 答案在 [1, max(piles)]

Time: O(n log max(piles)): 二分 log(max) 轮, 每轮 feasible 扫 O(n)。Space: O(1)。

记:答案有范围、能 O(n) 验证一个候选值、候选值越大越容易 (或越难) → 对答案二分。

6. Capacity To Ship Packages Within D Days: 同一招, feasible 换成贪心

题目: weights 按顺序装船, 每天一条船, 载重 cap, 不能拆包裹也不能换顺序。要在 days 天内运完, 求最小的 cap。例: weights = [1..10], days = 5 → 15。

Brute force: 从 cap = max(weights) 往上试, 每个 cap 贪心 O(n), 最多试 sum(weights) 个, 共 O(n × sum)。

相比上一题: 完全一样的结构, 变的只有 feasible: 不再是公式, 而是一次贪心扫描 (装得下就装, 装不下另起一天)。cap 越大天数只会更少, 单调。范围: 下限 max(weights) (最重的包裹要装得下), 上限 sum (一天全装)。

def ship_within_days(weights, days): def feasible(cap): # 载重 cap 能不能在 days 天内运完 need, load = 1, 0 # need = 已经用了几天, load = 今天已装多少 for w in weights: if load + w > cap: # 今天装不下了: 另起一天 need += 1 load = 0 load += w return need <= days # 答案在 [max(weights), sum(weights)] return first_true(max(weights), sum(weights) + 1, feasible)

Time: O(n log(sum - max)): 二分 log(sum) 轮, 每轮贪心 O(n)。Space: O(1)。

记:feasible 可以是任何 O(n) 的验证 (公式、贪心); 范围的下限是 "单个元素必须放得下", 上限是 "全部放一起"。

7. Split Array Largest Sum: "最小的最大值" 的标准形式

题目: 把 nums 切成 k 段连续子数组, 使得各段和的最大值最小, 求这个最小值。例: nums = [7,2,5,10,8], k = 2 → 18 (切成 [7,2,5] 和 [10,8])。

Brute force: 枚举所有切法, C(n-1, k-1) 种, 每种 O(n); 或者 DP O(k n²)。浪费: 题目问的是一个数值 (最大段和), 却在枚举切法。

关键观察: 把问题反过来问: "如果每段和都不能超过 x, 最少要切几段?" 这个可以贪心 O(n) 回答 (当前段再加就超 x 才另起一段)。x 越大段数越少, 所以 最少段数 <= k 单调。看到 "最小的最大值 / 最大的最小值", 就想: 二分这个值 x, 问 "x 行不行"。

相比上一题: 代码逐行一样, 只是 days → k, cap → x, weights → nums。Capacity 和 Split Array 是同一道题的两种说法。

def split_array(nums, k): def feasible(x): # 每段和都 <= x, 最少要切几段? 够不够 k 段 pieces, cur = 1, 0 for v in nums: if cur + v > x: # 当前段再加 v 就超 x: 另起一段 pieces += 1 cur = 0 cur += v return pieces <= k # 答案在 [max(nums), sum(nums)] return first_true(max(nums), sum(nums) + 1, feasible)

Time: O(n log(sum - max)), 从 DP 的 O(k n²) 降下来。Space: O(1)。

"最大的最小值" (如 Magnetic Force Between Two Balls, Aggressive Cows) 方向相反: pred 是 True...True False...False (x 越大越难), 要最后一个 True。把 pred 取反就能复用模板:

def last_true(lo, hi, pred): """pred 是 True...True False...False 时, 找最后一个 True; 没有就返回 lo - 1。""" return first_true(lo, hi, lambda x: not pred(x)) - 1

记:求 "最小的最大值": 二分这个值 x, 贪心验证 x 行不行; "最大的最小值": 同理, 用 last_true (或 pred 取反再 -1)。

8. Search a 2D Matrix: 二维当一维

题目: m x n 矩阵, 每行从左到右 sorted, 每行第一个数 > 上一行最后一个数。判断 target 在不在。例: matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 11 → True。

Brute force: 全扫 O(mn)。

关键观察: 按行拼起来就是一个 sorted 的长度 m*n 的数组, 不需要真的拼, 下标 i 对应 matrix[i // n][i % n]。相比第 1 题: 搜索范围变成 [0, m*n), 取值的地方改成 matrix[i // n][i % n], 其余不变。

def search_matrix(matrix, target): m, n = len(matrix), len(matrix[0]) # 把 m x n 看成长度 m*n 的 sorted 数组: 下标 i <-> (i // n, i % n) i = first_true(0, m * n, lambda i: matrix[i // n][i % n] >= target) return i < m * n and matrix[i // n][i % n] == target

Time: O(log(mn)) = O(log m + log n)。Space: O(1)。

记:每行首 > 上行尾 → 整体当 sorted 一维; 下标用 // n 和 % n 换算。

(Search a 2D Matrix II: 只保证每行每列各自 sorted, 拼不成一维。不要二分, 从右上角出发, 大了往左、小了往下, O(m + n)。)

9. Median of Two Sorted Arrays: 二分的是 "分割点" (简述)

题目: 两个 sorted 数组, 求合并后的中位数, 要求 O(log(m + n))。例: A = [1,3,8,9,15], B = [7,11,18,19,21,25] → 11。

Brute force: 合并再取中间, O(m + n)。 思路: 中位数只取决于 "左半 / 右半" 怎么分。左半一共放 half = (m + n + 1) // 2 个, 其中 A 放 i 个, B 就放 j = half - i 个, 所以只有一个自由变量 i。i 对不对只看分割线两侧紧挨着的 4 个数: A[i-1] <= B[j] 且 B[j-1] <= A[i]。i 太小还是太大有明确方向, 所以对 i 二分 (范围 [0, m], 在较短的数组上做)。同样套 first_true, pred(i) = A[i] >= B[j-1] (A 取得够多了), i = m 时当作 True。边界上的 -inf / +inf 处理是这题最烦的部分, 面试里写清楚 INF 哨兵就行, 不用深挖。

def find_median(A, B): if len(A) > len(B): A, B = B, A # 在短的那个上二分: A 里取 i 个放进左半 m, n = len(A), len(B) half = (m + n + 1) // 2 # 左半共 half 个: A 取 i, B 取 j = half - i INF = float("inf") def cut_too_small(i): # pred(i): A 取得够多了吗? F...F T...T # i == m: A 全进左半; 否则 A[i] (在右半) 不能比 B[j-1] (在左半) 小 return i == m or A[i] >= B[half - i - 1] i = first_true(max(0, half - n), m + 1, cut_too_small) j = half - i left_max = max(A[i - 1] if i > 0 else -INF, B[j - 1] if j > 0 else -INF) right_min = min(A[i] if i < m else INF, B[j] if j < n else INF) if (m + n) % 2: return left_max return (left_max + right_min) / 2

Time: O(log min(m, n)): 二分在较短的数组上。Space: O(1)。

记:二分的对象可以是 "分割点"; 先把问题写成 "某个整数变量上的单调 pred", 剩下就是 first_true。

10. 识别信号: 看到什么 → 试什么

题目特征做法complexity
sorted 数组, 找值 / 插入位置 / 第一个、最后一个 / 个数first_true(nums[i] >= x) 和 > xO(n) → O(log n)
sorted 数组被旋转, 找最小值或某个数和 nums[-1] 比做 pred; 或判断哪半有序O(n) → O(log n)
数组无序, 但相邻元素有上坡/下坡结构 (peak, mountain)比较 nums[mid] 和 nums[mid+1], 往上坡走O(n) → O(log n)
n 很大 (1e9) 无法枚举答案, 但能 O(n) 验证一个候选值二分答案: 写 feasible(x), 范围 [最小可能, 最大可能]O(n × range) → O(n log range)
求 "最小的最大值" (min of max): 切段、分天、分配二分这个最大值 x, 贪心验证, 用 first_trueDP O(k n²) 或枚举 → O(n log sum)
求 "最大的最小值" (max of min): 放球、放牛二分最小值 x, 贪心验证, 用 last_true枚举 → O(n log range)
"最小的 x 使得 ... 成立", 且 x 越大越容易成立feasible(x) 单调 → first_trueO(range) → O(log range)
矩阵每行 sorted 且行首 > 上一行行尾拉平成一维, 下标 // n 和 % nO(mn) → O(log mn)
两个 sorted 数组, 第 k 个 / 中位数, 要求 log对较短数组的分割点 i 二分O(m + n) → O(log min(m, n))
按权重随机选 (Random Pick with Weight)前缀和 + bisect_left 找第一个 >= 随机数每次 O(n) → O(log n)

写之前问自己三个问题: 1) pred 是什么, 是 F...F T...T 吗 (不是就反过来或换 pred)? 2) 搜索范围 [lo, hi) 是什么, 答案一定在里面吗 (hi 要多 +1)? 3) 找的是第一个 True 还是最后一个 True?
