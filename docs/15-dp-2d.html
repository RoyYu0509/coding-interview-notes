15 · Dynamic Programming (2): Grid / Two Strings / Interval

主线: state 需要两个 index 才能描述子问题时, 用 2D 表 dp[i][j]。问 "最后一步做了什么" 得到 transition, 依赖方向决定填表顺序, 只依赖上一行就能滚动数组。

概念链: Unique Paths → Minimum Path Sum → Maximal Square → Longest Common Subsequence → Edit Distance → Longest Palindromic Substring → Palindromic Substrings → Regular Expression Matching。(1D 的 Climbing Stairs / House Robber / Coin Change / knapsack 在 14 号文档。)

0. 第一性原理: 为什么需要 2D, 怎么推 transition

Brute force 在浪费什么。以 Unique Paths 为例: 从 (0,0) 走到 (m-1,n-1), 暴力递归 f(i,j) = f(i-1,j) + f(i,j-1), 每个格子拆成两个子问题, 时间 O(2^(m+n))。但是不同的 (i, j) 一共只有 m*n 个: 同一个 f(1,2) 被反复重新算。DP 就是给每个 (i, j) 一个格子, 只算一次, 之后直接读。

为什么是 2D。子问题的 state 要用两个 index 才说得清: 走到第 i 行第 j 列; text1 的前 i 个字符和 text2 的前 j 个字符; s[i..j] 这一段。只用一个 index 描述不了, 所以表是 2D 的。1D DP (一个数组 / 一个序列) 在 14 号文档。

怎么推 transition。固定三步:

① 写下 state 的含义(一句话, 包括 i、j 是 "前 i 个" 还是 "第 i 个"); ② 问"最后一步做了什么": 最后一步有几种做法, 每种做法把问题缩成哪个更小的 (i', j'); ③ 把几种做法用题目要的方式合起来 (求方案数用 +, 求最小用 min, 求能不能用 or)。

填表顺序。不用背: 画出 dp[i][j] 依赖哪些格子, 这些格子必须先填好。依赖上 / 左 / 左上, 就是行从上到下、列从左到右。如果依赖的是下一行(第 6 题的 dp[i+1][j-1]), 就要从下往上填。

滚动数组。如果 dp[i] 只读 dp[i-1] (和同一行左边), 只需要两行 prev / cur, 甚至一行原地更新, space 从 O(m*n) 降到 O(n)。代价: 丢了整张表, 如果要 还原方案(比如打印出 LCS 本身)就不能滚动。

def solve(A, B): # A, B: 两个 string / 一个 grid 的行列 m, n = len(A), len(B) # dp[i][j] = 只看 A 的前 i 个、B 的前 j 个时, 子问题的答案 (两个 index → 2D) dp = [[0] * (n + 1) for _ in range(m + 1)] # base: dp[0][*] 和 dp[*][0] = 其中一边为空时的答案 (先填好) for i in range(1, m + 1): # 填表顺序 = 依赖的反方向: for j in range(1, n + 1): # dp[i][j] 依赖 (i-1, j) (i, j-1) (i-1, j-1) # 问 "最后一步做了什么"? 每种选择 → 一个更小的子问题 → 取 min / max / sum dp[i][j] = f(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]) return dp[m][n] # 答案在右下角# 滚动数组: dp[i] 只读 dp[i-1] → 只留 prev, cur 两行, space O(m*n) → O(n)

记:2D DP = 定义 dp[i][j] 的含义 → 问最后一步做了什么 → 依赖方向定填表顺序 → 只读上一行就滚动。

1. Unique Paths: 最后一步从上或从左, 相加

题目。m × n 的格子, 机器人从左上角走到右下角, 每次只能向右或向下, 有多少条不同路径? 例: m = 3, n = 4 → 10。

Brute force。递归 f(i,j) = f(i-1,j) + f(i,j-1), O(2^(m+n)) time。浪费: 同一个格子被重复展开 (见图)。

关键观察。到 (i,j) 的最后一步只可能从上面或左边来, 这两类路径不重叠、也没有遗漏 → 相加。第 0 行 / 第 0 列只有一种走法。

def unique_paths(m, n): dp = [[1] * n for _ in range(m)] # 第 0 行 / 第 0 列只有 1 种走法 (一直直走) for i in range(1, m): for j in range(1, n): # 最后一步要么从上面 (i-1, j) 下来, 要么从左边 (i, j-1) 过来 # 两类路径互不重叠, 而且已经包含了所有路径 → 相加 dp[i][j] = dp[i - 1][j] + dp[i][j - 1] return dp[m - 1][n - 1]def unique_paths_1row(m, n): # 滚动数组: 只依赖上一行 → 一维就够 row = [1] * n # row 当前代表 "上一行" for _ in range(m - 1): for j in range(1, n): row[j] += row[j - 1] # row[j] 旧值 = 上面, row[j-1] 新值 = 左边 return row[-1]

Complexity。Time O(m*n): 每格 O(1)。Space O(m*n); 滚动成一行后 O(n)。

记:grid 路径计数: dp[i][j] = 上 + 左, 第 0 行 / 列 = 1。

2. Minimum Path Sum: 相加变 min, 多加自己

题目。grid 每格有非负数, 从左上走到右下 (只能右 / 下), 求路径上数字之和的最小值。例: [[1,3,1],[1,5,1],[4,2,1]] → 7。

Brute force。枚举所有路径 (Unique Paths 的那 C(m+n-2, m-1) 条), 每条求和。浪费: 不同路径共享大量前缀。

关键观察。相比上一题, 改两处: ① 不再数路径条数, 而是求最小和, 所以 + 变 min; ② 每格有自己的代价, 所以要加上 grid[i][j]。之所以只看邻居的 dp 值就够, 是因为 optimal substructure: 到 (i,j) 的最优路径, 去掉最后一格后, 一定是到某个邻居的最优路径。

def min_path_sum(grid): m, n = len(grid), len(grid[0]) dp = [[0] * n for _ in range(m)] dp[0][0] = grid[0][0] for j in range(1, n): # 第 0 行: 只能从左边来 dp[0][j] = dp[0][j - 1] + grid[0][j] for i in range(1, m): # 第 0 列: 只能从上面来 dp[i][0] = dp[i - 1][0] + grid[i][0] for i in range(1, m): for j in range(1, n): # 改的就是这一行: 相加 → min。到 (i, j) 的最小和 = 两个来路里小的那个 + 自己 dp[i][j] = min(dp[i - 1][j], dp[i][j - 1]) + grid[i][j] return dp[m - 1][n - 1]def min_path_sum_1row(grid): # 滚动数组: inf 当哨兵, 不用单独处理第 0 行 n = len(grid[0]) row = [float("inf")] * n row[0] = 0 for r in grid: row[0] += r[0] # 第 0 列: 只能从上面来 for j in range(1, n): row[j] = min(row[j], row[j - 1]) + r[j] # 旧 row[j] = 上, row[j-1] = 左 return row[-1]

Complexity。Time O(m*n); Space O(m*n), 滚动后 O(n)。

记:路径最小和: dp[i][j] = min(上, 左) + grid[i][j]。从 Unique Paths 改一行。

3. Maximal Square: min(上, 左, 左上) + 1

题目。0/1 矩阵, 找只含 1 的最大正方形, 返回面积。例: ["10100","10111","11111","10010"] → 4。

Brute force。枚举每个格子当左上角, 再枚举边长 k, 检查 k×k 是否全 1: O(m*n*min(m,n)²) (检查也要算)。浪费: 检查 k×k 全 1 时, 又把 (k-1)×(k-1) 检查了一遍。

关键观察。改 state: dp[i][j] = 以 (i,j) 为右下角的最大全 1 正方形边长。当前格是 1 时, 想长成 (k+1)×(k+1), 它的上、左、左上三个邻居都必须能撑起 k×k。三个里最小的先撞墙, 所以边长 = 最小 + 1。这里依赖三个邻居, 是本文档里第一次用到左上。

def maximal_square(matrix): # matrix 里是 "0" / "1" 字符 m, n = len(matrix), len(matrix[0]) # dp[i][j] = 以 matrix[i-1][j-1] 为右下角的全 1 正方形, 最大边长 dp = [[0] * (n + 1) for _ in range(m + 1)] # 多一圈 0 当边界, 省掉 if i == 0 best = 0 for i in range(1, m + 1): for j in range(1, n + 1): if matrix[i - 1][j - 1] == "1": # 上 / 左 / 左上 三个邻居里最小的那个, 决定先撞墙的方向 → 边长 = 最小 + 1 dp[i][j] = min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]) + 1 best = max(best, dp[i][j]) # 是 "0" 就保持 0: 这个格子不能当任何正方形的右下角 return best * best # 题目要面积

Complexity。Time O(m*n); Space O(m*n), 滚动成两行后 O(n)。答案是整张表的最大值 (不是右下角), 因为正方形可以在任何位置。

记:最大正方形: 当前格是 1 → dp = min(上, 左, 左上) + 1; 答案取全表最大值再平方。

4. Longest Common Subsequence: 比较两个前缀的最后一个字符

题目。两个 string, 求最长公共子序列 (不要求连续) 的长度。例: "abcde", "ace" → 3 ("ace")。

Brute force。枚举 text1 的所有子序列 (2^m 个), 逐个判断是不是 text2 的子序列, O(2^m * n)。浪费: 子序列的前半段被无数次重复判断。

关键观察。从 grid 过渡到两个 string: dp[i][j] 看 text1[:i] 和 text2[:j], i 和 j 分别是两个 string 的指针。最后一步: 看 text1[i-1] 和 text2[j-1]。相同 → 配对, 去掉这一对看左上; 不同 → 至少有一个字符没用, 丢一个, 看上或左, 取 max。

def longest_common_subsequence(text1, text2): m, n = len(text1), len(text2) # dp[i][j] = text1[:i] 和 text2[:j] 的 LCS 长度 dp = [[0] * (n + 1) for _ in range(m + 1)] # dp[0][*] = dp[*][0] = 0: 有一边是空串 for i in range(1, m + 1): for j in range(1, n + 1): if text1[i - 1] == text2[j - 1]: # 最后一个字符相同 → 一定可以配对, 去掉这一对, 看左上角 dp[i][j] = dp[i - 1][j - 1] + 1 else: # 不同 → 至少有一个字符没用上: 丢 text1 的最后一个, 或丢 text2 的最后一个 dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]) return dp[m][n]def lcs_2rows(text1, text2): # 滚动数组: 只留上一行 prev 和当前行 cur n = len(text2) prev = [0] * (n + 1) for ch in text1: cur = [0] * (n + 1) for j in range(1, n + 1): if ch == text2[j - 1]: cur[j] = prev[j - 1] + 1 else: cur[j] = max(prev[j], cur[j - 1]) prev = cur return prev[n]

Complexity。Time O(m*n); Space O(m*n), 滚动后 O(min(m,n)) (让短的当列)。

记:两个 string 求最优: dp[i][j] 看两个前缀, 比最后一个字符: 相同 → 左上, 不同 → 丢一个。

5. Edit Distance: 三种操作对应三个方向

题目。把 word1 变成 word2, 每步可以 insert / delete / replace 一个字符, 求最少步数。例: "horse" → "ros" = 3。

Brute force。每个位置试三种操作的递归, O(3^max(m,n))。浪费: 不同操作顺序会走到同一个 (i, j) 状态。

关键观察。state 和 LCS 完全一样 (两个前缀), 变的是 transition 和 base:① 最后字符相同 → 白拿左上, 不加 1; ② 不同 → 三种操作, 对应三个方向:replace = 左上, delete = 上, insert = 左, 取 min 再 +1; ③ base 不是 0: 第 0 行 / 第 0 列是 0, 1, 2, ... (全插入 / 全删除)。

def min_distance(word1, word2): m, n = len(word1), len(word2) # dp[i][j] = word1[:i] 变成 word2[:j] 的最少操作数 dp = [[0] * (n + 1) for _ in range(m + 1)] for i in range(m + 1): dp[i][0] = i # word1[:i] → "": 删 i 次 for j in range(n + 1): dp[0][j] = j # "" → word2[:j]: 插 j 次 for i in range(1, m + 1): for j in range(1, n + 1): if word1[i - 1] == word2[j - 1]: dp[i][j] = dp[i - 1][j - 1] # 最后一个字符已经一样: 不用操作, 白拿左上角 else: dp[i][j] = 1 + min( dp[i - 1][j - 1], # replace: 改成 word2[j-1], 两边各缩 1 dp[i - 1][j], # delete: 删掉 word1[i-1], word1 缩短 1 dp[i][j - 1], # insert: 在末尾补上 word2[j-1], word2 缩短 1 ) return dp[m][n]

Complexity。Time O(m*n); Space O(m*n), 滚动后 O(n)。

记:Edit Distance = LCS 的 state + 三个方向 (替换 / 删 / 插) 取 min + 1, base 是 0..n。

6. Longest Palindromic Substring: 先中心扩展, 再看 interval 填表

题目。求 s 的最长回文子串 (连续)。例: "babad" → "bab" ("aba" 也对)。

Brute force。枚举所有子串 O(n²), 每个检查是不是 palindrome O(n), 共 O(n³)。浪费: 检查 s[i..j] 时又把里面的 s[i+1..j-1] 检查了一遍。

最实用的解: 中心扩展。palindrome 一定对称, 有一个中心。枚举 2n-1 个中心从中心往外扩, O(n²) time, O(1) space, 代码短、不容易错。面试首选这个。

def longest_palindrome(s): start, end = 0, 0 # 当前最长 palindrome 的闭区间 [start, end] def expand(l, r): # 从中心往两边扩, 直到越界或两端不同 while l >= 0 and r < len(s) and s[l] == s[r]: l -= 1 r += 1 return l + 1, r - 1 # 循环停下时 l, r 已经多走了一步, 退回来 for c in range(len(s)): # 2n-1 个中心: n 个字符 + n-1 个缝 for l, r in (expand(c, c), expand(c, c + 1)): # 奇数长度 / 偶数长度 if r - l > end - start: start, end = l, r return s[start:end + 1]

Interval DP 版。state 变成一段区间: dp[i][j] = s[i..j] 是不是 palindrome。最后一步: 看两端。s[i] == s[j] 且里面 dp[i+1][j-1] 也是 → True。填表顺序是关键: dp[i][j] 依赖下一行 (i+1) 的左边一格 (j-1), 所以 i 必须从大到小; 按长度从短到长填也行, 这是 interval DP 的通用顺序。

def longest_palindrome_dp(s): n = len(s) # dp[i][j] = s[i..j] (闭区间) 是不是 palindrome dp = [[False] * n for _ in range(n)] start, best = 0, 1 for i in range(n - 1, -1, -1): # i 从大到小: dp[i+1][j-1] 在 "下一行" for j in range(i, n): # 两端相同 + 里面 s[i+1..j-1] 也是 palindrome; 长度 <= 2 时里面是空的, 直接成立 if s[i] == s[j] and (j - i < 2 or dp[i + 1][j - 1]): dp[i][j] = True if j - i + 1 > best: start, best = i, j - i + 1 return s[start:start + best]

Complexity。中心扩展: Time O(n²), Space O(1)。DP: Time O(n²), Space O(n²)。(另有 Manacher 算法 O(n), 面试不需要。)

Interval DP 的模板(dp[i][j] 描述一段区间, 由更短的区间推出): for length in range(2, n+1): for i in range(n-length+1): j = i+length-1。最难的 Burst Balloons 就是这个套路, 在区间里枚举 "最后一个" 被戳的气球 k, 合并 dp[i][k] 和 dp[k][j]; 这里一句话带过, 不展开。

记:最长回文子串: 面试写中心扩展 (O(n²), O(1))。interval DP 记住: 依赖更短的区间 → 从下往上 / 按长度填。

7. Palindromic Substrings: 同一套中心, 改成计数

题目。数 s 里有多少个回文子串 (位置不同算不同)。例: "aba" → 4。

Brute force。O(n³), 同上一题。

关键观察。相比上一题, 只改一件事: 不记最长, 而是每扩一步成功 count += 1。每个 palindrome 恰好有一个中心, 所以不重不漏。(DP 版也行: 数 dp 表里 True 的个数。)

def count_substrings(s): count = 0 for c in range(len(s)): for l, r in ((c, c), (c, c + 1)): # 奇数中心 / 偶数中心 while l >= 0 and r < len(s) and s[l] == s[r]: count += 1 # 每成功扩一步 = 发现一个新的 palindrome l -= 1 r += 1 return count

Complexity。Time O(n²) (最坏全是同一个字符, 每个中心扩 O(n)); Space O(1)。

记:数回文子串: 中心扩展, 每成功一步 count += 1。

8. Regular Expression Matching: '*' 的两种选择

题目。实现 . (任意一个字符) 和 * (前一个字符重复 0 次或多次) 的匹配, 要求整个 s 被匹配。例: s = "aab", p = "c*a*b" → True。

Brute force。递归: 遇到 '*' 就枚举吃几个, 最坏指数级。浪费: 同一对 (s 的位置, p 的位置) 被反复匹配。

关键观察。state 和 LCS 一样 (两个前缀), 难在 '*' 的 transition。普通字符 / '.' : 各吃一个, 看左上。遇到 'x*' 有两种选择, 任一成立即可 (or):

① 匹配 0 次: 把 "x*" 整个去掉 → dp[i][j-2]; ② 匹配 1 次并保留 pattern: 前提 x 能匹配 s[i-1], s 去掉一个字符, 但 "x*" 还留着 → dp[i-1][j]。"保留" 是关键: 因为 x* 还可以继续吃前面的字符, 这样就不用枚举到底吃几个。

def is_match(s, p): m, n = len(s), len(p) # dp[i][j] = s[:i] 能不能被 p[:j] 完整匹配 dp = [[False] * (n + 1) for _ in range(m + 1)] dp[0][0] = True # 空 pattern 匹配空 string for j in range(2, n + 1): # s 为空: 只有 "a*b*" 这类全匹配 0 次的能过 if p[j - 1] == "*": dp[0][j] = dp[0][j - 2] for i in range(1, m + 1): for j in range(1, n + 1): if p[j - 1] == "*": # p[j-2] 是被 * 修饰的字符, 比如 "a*" 里的 a dp[i][j] = dp[i][j - 2] # 选择 1: a* 匹配 0 次 → 把 "a*" 整个去掉 if p[j - 2] in (s[i - 1], "."): # 选择 2: a* 匹配 s[i-1] 这一个, 但 pattern 保留 (还能继续匹配更多) dp[i][j] = dp[i][j] or dp[i - 1][j] elif p[j - 1] in (s[i - 1], "."): dp[i][j] = dp[i - 1][j - 1] # 普通字符 / "." 匹配: 各吃一个 return dp[m][n]

Complexity。Time O(m*n); Space O(m*n), 可滚动成 O(n)。

记:正则 / 通配符匹配: dp[i][j] = s[:i] 匹配 p[:j]; '*' = (匹配 0 次: dp[i][j-2]) or (吃一个保留: dp[i-1][j])。

dp[i] 只读 dp[i-1]滚动数组, 只留 prev / cur 两行space O(m*n) → O(n)

从 1D 过渡的例子: Decode Ways("226" → 3)。dp[i] = s 前 i 个字符的解码方式数, 最后一步 "解一位" 或 "解两位": dp[i] = dp[i-1](末位 1-9) + dp[i-2](末两位 10-26)。state 只需一个 index, 所以是 1D, 放在 14 号文档; 但 "问最后一步做了什么" 的推法和本文档一模一样。
