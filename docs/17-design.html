17 · Data Structure Design

主线: design 题 = 先列出每个操作要求的 complexity, 再把 '擅长这个操作' 的数据结构组合起来, 并保证它们永远描述同一批元素 (同步)。

概念链: 第一性原理 → LRU Cache (dict + DLL) → GetRandom (dict + list, swap-pop) → Time Based KV (dict + sorted list + bisect) → Hit Counter / Logger (deque / dict) → Snapshot Array (只记变化 + bisect) → LFU Cache (LRU 的分层版)

0. 第一性原理: 没有一个结构什么都快, 所以要组合

Design 题给你一组 API, 每个都要求 O(1) 或 O(log n)。面试里它在考的不是某个技巧, 而是一个固定的推理流程:

① 把每个操作要求的 complexity 写出来 · ② 对每个操作问: 哪个结构能在这个 complexity 内做它 · ③ 没有一个结构能全包 → 组合两个, 每个操作交给擅长它的那个 · ④ 想清楚两个结构之间的 同步 invariant (一边改了另一边必须跟着改)。

Brute force 是什么: 只用一个 list (或一个 dict) 硬做。浪费在哪里:

• 只用 list: 按 key 找要 O(n) 扫描, 删中间要 O(n) 搬动。 • 只用 dict: 没有'最旧 / 第 i 个 / ≤ t 的最近'这类顺序信息。每个结构单独都有它做不到的操作。

所以 design 题的本质是分工: 把操作按'需要什么能力'分类, 每类交给一个结构。组合之后新增的负担只有一个: 同步。每次 mutate (增 / 删 / 移动) 都要检查'另一个结构改了没有', 绝大多数 bug 出在这里。

class Design: def __init__(self): self.index = {} # 结构 A: 擅长 "按 key O(1) 找到东西" self.order = ... # 结构 B: 擅长 "顺序 / 位置 / 最旧 / <= t" (list, DLL, deque ...) def op(self, key): # 1) 用 A 在 O(1) 内定位 -> 拿到 B 里的位置 (node / index) # 2) 用 B 在 O(1) 内做顺序操作 # 3) 回头把 A 也改掉 -> invariant: A 和 B 永远描述同一批元素 ...

记:先写出每个操作要的 complexity, 再用图 0 选结构。组合 = 分工 + 同步。同步 invariant 要能用一句话说出来。

1. LRU Cache: dict 按 key 找 node, doubly linked list 管新旧

题目: get(key) 返回值 (没有返回 -1); put(key, val) 写入, 超过 capacity 就踢掉最久没用的。get 和 put 都要 O(1)。例: capacity = 2, put(1,10), put(2,20), get(1), put(3,30) → 踢掉 key 2。

Brute force: 用 list 按使用顺序存 (key, val)。get 要扫描找 key O(n), 再 remove + append 也 O(n)。dict 能 O(1) 找到 key, 但它不知道谁最旧; list 知道顺序, 但按 key 找、删中间都慢。

关键观察: 要的三件事 ——按 key 找、把某个中间元素移到最新、删最旧—— dict 做第一件, doubly linked list 做后两件 (只要手里有 node 指针, 摘下和接上都是 O(1))。让 dict 的 value 直接就是 node 指针, 两个结构就连起来了。

class Node: def __init__(self, key=0, val=0): self.key, self.val = key, val # node 里也存 key: 踢人时要靠它去 del cache[key] self.prev = self.next = Noneclass LRUCache: def __init__(self, capacity): self.cap = capacity self.cache = {} # key -> Node (O(1) 找 node) self.head, self.tail = Node(), Node() # dummy: 永远存在, 摘/插都不用判 None self.head.next, self.tail.prev = self.tail, self.head # list 顺序: head <-> LRU(最久没用) ... MRU(刚用过) <-> tail def _remove(self, node): # O(1): 有 prev 才能不扫描就摘下来 node.prev.next = node.next node.next.prev = node.prev def _add_to_tail(self, node): # O(1): 接到 tail 前面 = 变成 MRU last = self.tail.prev last.next, node.prev = node, last node.next, self.tail.prev = self.tail, node def get(self, key): if key not in self.cache: return -1 node = self.cache[key] self._remove(node) # 用过了: 摘下来 ... self._add_to_tail(node) # ... 放到 MRU 端 return node.val def put(self, key, val): if key in self.cache: # 已存在: 更新值 + 变成 MRU node = self.cache[key] node.val = val self._remove(node) self._add_to_tail(node) return node = Node(key, val) self.cache[key] = node # dict 和 list 一起加 (同步) self._add_to_tail(node) if len(self.cache) > self.cap: # 超过 capacity: 踢 LRU = head.next lru = self.head.next self._remove(lru) del self.cache[lru.key] # dict 也要删 (同步) -> 所以 node 要存 key

Time O(1): get / put 都是'一次 dict 查找 + 常数条指针赋值'。Space O(capacity): dict 和 list 各存 capacity 个 node (同一批对象, 不是两份数据)。

面试速写版: Python 的 OrderedDict 已经是 dict + doubly linked list。先问面试官'能不能用 OrderedDict', 能的话 10 行写完; 不能就写上面的版本。注意两个版本的对应: move_to_end = _remove + _add_to_tail, popitem(last=False) = 踢 head.next。

from collections import OrderedDictclass LRUCache: # 面试速写版: OrderedDict = dict + DLL 已经帮你焊好 def __init__(self, capacity): self.cap = capacity self.od = OrderedDict() # 左 = LRU, 右 = MRU def get(self, key): if key not in self.od: return -1 self.od.move_to_end(key) # O(1): 变成 MRU return self.od[key] def put(self, key, val): self.od[key] = val self.od.move_to_end(key) # 新 key 本来就在最右, 旧 key 要挪过去 if len(self.od) > self.cap: self.od.popitem(last=False) # O(1): 弹最左 = 踢 LRU

记:LRU = dict(key→node) + doubly linked list(左 LRU 右 MRU)。用了就摘下接到右边, 满了踢 head.next, 同时 del dict。node 里存 key, 用 dummy head/tail。

2. Insert Delete GetRandom O(1): dict 找位置, list 取随机, 删除 = 换到末尾再 pop

题目: insert(val)、remove(val)、getRandom() 全部 O(1), getRandom 每个元素等概率。例: insert 5, 7, 9 → remove 5 → insert 4 → remove 7。

Brute force: 只用 list, insert 是 append O(1), 但 remove(val) 要先找 O(n) 再搬动 O(n)。只用 set, 删除 O(1), 但 getRandom 要 O(n) 才能抽 (set 不能按 index 取)。

相比上一题: 又是 dict + 一个顺序结构, 但这次顺序结构是 list, 要的能力是'按 index O(1) 取'。list 唯一的软肋是删中间; 但 set 本来就不要求顺序, 所以可以 先把末尾元素搬到要删的位置, 再 pop 尾巴 —— 删中间变成删末尾。代价: 搬动的元素在 list 里的 index 变了, dict 必须同步。

import randomclass RandomizedSet: def __init__(self): self.nums = [] # 能 O(1) random.choice(nums) <- 只有 list 能按 index O(1) 取 self.pos = {} # val -> 它在 nums 里的 index <- 只有 dict 能按 val O(1) 找 def insert(self, val): if val in self.pos: return False self.pos[val] = len(self.nums) # 先记 index, 再 append self.nums.append(val) return True def remove(self, val): if val not in self.pos: return False i = self.pos[val] # 要删的 val 在哪 last = self.nums[-1] # 末尾元素: list 只有删末尾才是 O(1) self.nums[i] = last # 把末尾搬到 i, 覆盖 val self.pos[last] = i # last 的 index 变了, dict 必须同步 self.nums.pop() # 删尾巴 O(1) del self.pos[val] # 顺序不能反: val == last 时, 这行才会把它删干净 return True def getRandom(self): return random.choice(self.nums) # 每个 index 等概率

Time 三个操作都是 O(1) (dict 查找 + list 末尾操作 + 一次赋值)。Space O(n): nums 和 pos 各 n 项。

变体 (Duplicates allowed): pos 改成 val → set(indices), remove 时从 set 里取任意一个 index 来换; 其余完全一样。

记:list 要 O(1) 随机取, dict 要 O(1) 找位置。删中间 = 末尾搬过来覆盖 + pop 尾巴 + 同步 pos。val == last 时 del pos 必须放在最后。

3. Time Based Key-Value Store: dict of list, append 天然有序, bisect 找 ≤ t

题目: set(key, value, timestamp) 存一条; get(key, timestamp) 返回该 key 在 timestamp 之前 (≤) 最近一次 set 的 value, 没有则 ""。set 的 timestamp 严格递增。

Brute force: 每个 key 一个 list, get 时从后往前扫, O(n)。浪费在哪里: 扫描完全没用上'记录按时间有序'这个信息。

关键观察: 因为 timestamp 递增, append 之后 list 自动有序, 不需要 sort / heap。'有序 list 里找最后一个 ≤ t' 就是 bisect_right(times, t) - 1, O(log n)。

from bisect import bisect_rightfrom collections import defaultdictclass TimeMap: def __init__(self): self.times = defaultdict(list) # key -> [timestamp ...] 严格递增 (题目保证) self.vals = defaultdict(list) # key -> [value ...] 和 times 同一个 index def set(self, key, value, timestamp): self.times[key].append(timestamp) # 时间只增不减 -> append 之后天然有序, 不用 sort self.vals[key].append(value) def get(self, key, timestamp): ts = self.times.get(key) # 用 .get: 避免 defaultdict 悄悄造一个空 list if not ts: return "" i = bisect_right(ts, timestamp) - 1 # 最后一个 <= t 的 idx; 全更大 -> -1 return self.vals[key][i] if i >= 0 else ""

Time set O(1); get O(log n) (n = 该 key 的记录数)。Space O(总 set 次数)。

相比上一题: dict 仍然按 key 分流, 但 value 是有序 list + bisect, 要的能力从'按 index 取'变成'找 ≤ t 的最近'。如果 timestamp 不保证递增, 就要用 sortedcontainers 或 insort (O(n) 插入), 面试时说明即可。

记:Time-based / 版本 / 历史查询 = dict of 有序 list + bisect_right(...) - 1。bisect_right 找 ≤ t, bisect_left 找 < t。

4. Design Hit Counter / Logger Rate Limiter: 时间窗口 = deque 左边出队

Hit Counter: hit(timestamp) 记一次, getHits(timestamp) 返回过去 300 秒内 (timestamp - 300, timestamp] 的 hit 数。timestamp 不减。

Brute force: 存所有时间戳, getHits 时全部扫一遍数 O(n), 内存还无限增长。

关键观察: 到达顺序就是时间顺序, 所以 最旧的永远在最左边; 过期的是连续的一段前缀。用 deque, getHits 时从左边 popleft 到不过期为止, 剩下的数量就是答案。每个时间戳进一次、出最多一次, 均摊 O(1)。

from collections import dequeclass HitCounter: def __init__(self): self.q = deque() # 时间戳, 左 = 最旧, 右 = 最新 (题目保证 timestamp 不减) def hit(self, timestamp): self.q.append(timestamp) # 新的永远在右边 def getHits(self, timestamp): # 窗口: (timestamp - 300, timestamp] while self.q and self.q[0] <= timestamp - 300: self.q.popleft() # 过期的一定在最左边: 从左边出队, 每个时间戳只出一次 return len(self.q) # 剩下的就是窗口内的

Time hit O(1), getHits 均摊 O(1)。Space O(窗口内 hit 数)。若同一秒有大量 hit: 改存 (timestamp, count) 并维护 total, 空间降到 O(300)。

Logger Rate Limiter (同一条 message 10 秒内只打印一次) 是更简单的变体: 不需要窗口, 只需要'每条 message 下一次可以打印的时间', 一个 dict 就够。(如果要求内存有界, 才需要 deque + set 过期清理。)

class Logger: # Logger Rate Limiter: 不用 deque, 一个 dict 就够 def __init__(self): self.next_ok = {} # message -> 最早什么时候又可以打印 def shouldPrintMessage(self, timestamp, message): if timestamp < self.next_ok.get(message, 0): return False # 还在 10 秒冷却里 self.next_ok[message] = timestamp + 10 return True

记:滑动时间窗口 = deque(时间戳) 从右 append、从左 popleft 过期的。单 key 限流 = dict(key→下次允许时间)。

5. Snapshot Array: 不复制数组, 每个 index 只记录变化, bisect 回溯

题目: SnapshotArray(length) 初值全 0; set(i, v); snap() 返回 snap_id (从 0 递增); get(i, snap_id) 返回 snap 时刻 index i 的值。例: length = 3, set(0,5), snap()=0, set(0,6), set(2,8), get(0,0)=5。

Brute force: snap() 复制整个数组, O(n) 时间 + O(n) 空间 / 次。snap 很多次、n 很大时炸掉。浪费在哪里: 绝大多数 index 在两次 snap 之间根本没变, 却被一遍遍复制。

关键观察: 只有 set 才产生新信息。给每个 index 一个变化记录 [(snap_id, val)], snap() 只是 snap_id += 1; snap_id 只增, 所以每个记录 list 天然有序, get 用 bisect 找'最后一个 snap_id' ≤ 查询的 snap_id'。这和上一题是同一个 pattern: 'timestamp' 换成 'snap_id', 'key' 换成 'index'。

from bisect import bisect_rightclass SnapshotArray: def __init__(self, length): # hist[i] = [(snap_id, val), ...] 只记录 "index i 在哪个 snap_id 期间被改成了 val" self.hist = [[(0, 0)] for _ in range(length)] # 初值 (0, 0): bisect 不会落到 -1 self.snap_id = 0 # 下一次 snap() 要返回的 id = 当前 "进行中" 的版本 def set(self, index, val): h = self.hist[index] if h[-1][0] == self.snap_id: # 本版本里已经改过: 覆盖, 不重复记 h[-1] = (self.snap_id, val) else: h.append((self.snap_id, val)) # snap_id 只增 -> h 天然按 snap_id 有序 def snap(self): self.snap_id += 1 # O(1): 不复制任何东西 return self.snap_id - 1 def get(self, index, snap_id): h = self.hist[index] i = bisect_right(h, (snap_id, float("inf"))) - 1 # 最后一个 <= snap_id 的记录 return h[i][1]

Time set O(1), snap O(1), get O(log s) (s = 该 index 的变化次数)。Space O(length + set 次数)。

记:'历史 / 版本 / 回溯' = 每个对象只记变化 [(version, val)], get 时 bisect_right(h, (v, inf)) - 1。初值放一条 (0, 0) 避免 -1。

6. LFU Cache: 把 LRU 按 freq 分层 (只讲结构)

题目: 和 LRU 一样, 但踢访问次数最少的; 次数相同时踢最久没用的。get / put 仍要 O(1)。

Brute force: 每次踢人扫描所有 key 找 (freq, 最后使用时间) 最小的, O(n); 或用 heap, 每次 get 更新 freq 要 O(log n)。

关键观察: freq 每次只 +1, 所以key 只会从桶 f 搬到桶 f + 1。每个 freq 一个 LRU 桶 (OrderedDict, 左 = 最久没用), 再记一个 min_freq 指向最低的非空桶 → 踢人就是 bucket[min_freq].popitem(last=False)。min_freq 的维护只有两种情况: 新 key 进来 → 1; 最低桶被搬空 → +1。

from collections import defaultdict, OrderedDictclass LFUCache: def __init__(self, capacity): self.cap = capacity self.val = {} # key -> value self.freq = {} # key -> 访问次数 self.bucket = defaultdict(OrderedDict) # freq -> {key: None}, 左 = 最久没用 self.min_freq = 0 # 当前最小的 freq: 踢人去 bucket[min_freq] 的最左边 def _touch(self, key): # key 被用了一次: 从 bucket[f] 搬到 bucket[f + 1] f = self.freq[key] del self.bucket[f][key] if not self.bucket[f]: del self.bucket[f] if self.min_freq == f: # 最低的桶空了 -> 最小频率一定正好 +1 self.min_freq += 1 self.freq[key] = f + 1 self.bucket[f + 1][key] = None # 接到右边 = 这个频率里最新的 def get(self, key): if key not in self.val: return -1 self._touch(key) return self.val[key] def put(self, key, value): if self.cap == 0: return if key in self.val: self.val[key] = value self._touch(key) return if len(self.val) >= self.cap: # 满了: 先踢 (频率最低里, 最久没用的) old, _ = self.bucket[self.min_freq].popitem(last=False) if not self.bucket[self.min_freq]: del self.bucket[self.min_freq] del self.val[old] del self.freq[old] self.val[key] = value self.freq[key] = 1 self.bucket[1][key] = None self.min_freq = 1 # 新 key freq = 1, 一定是最小的

Time get / put 都是 O(1) (几次 dict / OrderedDict 操作)。Space O(capacity)。

记:LFU = 三个 dict(val, freq, freq→OrderedDict) + min_freq。get 一次 = key 从桶 f 搬到桶 f+1; 踢 = 最低桶最左边; 新 key 把 min_freq 重置为 1。
