17 · Data Structure Design

这篇讲什么

design 题让你实现一个 class, 有几个方法, 而且每个方法都有复杂度要求 (通常是 O(1))。比如 LRU Cache: get 和 put 都要 O(1)。

难点是: 没有任何一个单独的数据结构能把所有操作都做快。dict 查找快但没有顺序; list 能按位置取但删除中间很慢; linked list 删除快但查找慢……

所以 design 题的套路是: 列出每个操作要什么 → 看每种数据结构能 O(1) 做什么 → 把两个结构组合起来, 每个操作交给擅长它的那个, 同时保证两个结构的内容一直同步。

design 题的一般写法
class Design: def __init__(self): self.index = {} # 结构 A: 擅长 "按 key O(1) 找到东西" # 结构 B: 擅长 "顺序 / 位置 / 最旧 / <= t" (list, DLL, deque ...) self.order = ... def op(self, key): # 1) 用 A 在 O(1) 内定位 -> 拿到 B 里的位置 (node / index) # 2) 用 B 在 O(1) 内做顺序操作 # 3) 回头把 A 也改掉 -> invariant: A 和 B 永远描述同一批元素 ...

每道题的顺序: 题目在问什么 → 看例子 → brute force → intuition → 算法 → 手动走一遍 → 复杂度。代码放在最后, 默认折叠。

1. LRU Cache

题目在问什么

实现一个容量为 capacity 的 cache:

  • get(key): key 存在就返回 value, 否则返回 -1。
  • put(key, value): 放进去 (已存在就更新)。如果放进去之后超过了容量, 就踢掉最久没被用过 (least recently used) 的那个。
  • get 和 put 都算"用过"。两个操作都要 O(1)。

看例子

Brute force

用一个 list 按"最近用过"的顺序存 key, 最久没用的在最前面。get 时要在 list 里找到 key 并移到最后, O(n); 踢人是删掉第一个, 也是 O(n) (list 删头要移动所有元素)。

Intuition: dict 负责找, linked list 负责排顺序

需要两种能力:

  • 按 key 找到它: dict, O(1)。
  • 维护"谁最久没用"的顺序, 并且能把任意一个元素 O(1) 地移到"最新"的位置、O(1) 删掉"最旧"的: doubly linked list (双向链表)。只要手里有 node 的引用, 删除它和插到末尾都是 O(1)。

组合起来: dict 存 key → node, node 在链表里。链表头部是最久没用的, 尾部是最近用的。

  • get: dict 找到 node, 把它从链表里拿出来, 放到尾部, 返回 value。
  • put: 已存在就更新 value 并移到尾部; 不存在就新建 node 放到尾部、加进 dict; 超过容量就删掉头部的 node, 并且从 dict 里也删掉它的 key (两边要同步, 所以 node 里也要存 key)。

一个写链表的技巧: 用两个假的 dummy node 当头和尾, 这样插入和删除都不用判断"是不是空链表"、"是不是第一个"。

算法

  1. head、tail 两个 dummy node, 中间是真正的 node。cache = {} 存 key → node。
  2. 两个辅助函数: remove(node) 把 node 从链表里摘掉; add_to_end(node) 插到 tail 前面。
  3. get: 不在就 -1; 在就 remove + add_to_end, 返回值。
  4. put: 在就先 remove; 新建或更新 node, add_to_end, 存进 cache。如果 len(cache) > capacity: 删掉 head.next, 并 del cache[它的 key]。

手动走一遍

复杂度

get 和 put 都是 Time O(1)。Space O(capacity)。

面试时如果允许用库, Python 的 OrderedDict 本身就是 dict + 双向链表: move_to_end(key) 移到最新, popitem(last=False) 踢掉最旧。但面试官通常想看你自己写链表。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
class Node: def __init__(self, key=0, val=0): # node 里也存 key: 踢人时要靠它去 del cache[key] self.key, self.val = key, val self.prev = self.next = Noneclass LRUCache: def __init__(self, capacity): self.cap = capacity # key -> Node (O(1) 找 node) self.cache = {} # dummy: 永远存在, 摘/插都不用判 None self.head, self.tail = Node(), Node() self.head.next, self.tail.prev = self.tail, self.head # list 顺序: head <-> LRU(最久没用) ... MRU(刚用过) <-> tail # O(1): 有 prev 才能不扫描就摘下来 def _remove(self, node): node.prev.next = node.next node.next.prev = node.prev # O(1): 接到 tail 前面 = 变成 MRU def _add_to_tail(self, node): last = self.tail.prev last.next, node.prev = node, last node.next, self.tail.prev = self.tail, node def get(self, key): if key not in self.cache: return -1 node = self.cache[key] self._remove(node) # 用过了: 摘下来 ... self._add_to_tail(node) # ... 放到 MRU 端 return node.val def put(self, key, val): if key in self.cache: # 已存在: 更新值 + 变成 MRU node = self.cache[key] node.val = val self._remove(node) self._add_to_tail(node) return node = Node(key, val) self.cache[key] = node # dict 和 list 一起加 (同步) self._add_to_tail(node) # 超过 capacity: 踢 LRU = head.next if len(self.cache) > self.cap: lru = self.head.next self._remove(lru) # dict 也要删 (同步) -> 所以 node 要存 key del self.cache[lru.key]
from collections import OrderedDict# 面试速写版: OrderedDict = dict + DLL 已经帮你焊好class LRUCache: def __init__(self, capacity): self.cap = capacity self.od = OrderedDict() # 左 = LRU, 右 = MRU def get(self, key): if key not in self.od: return -1 self.od.move_to_end(key) # O(1): 变成 MRU return self.od[key] def put(self, key, val): self.od[key] = val # 新 key 本来就在最右, 旧 key 要挪过去 self.od.move_to_end(key) if len(self.od) > self.cap: self.od.popitem(last=False) # O(1): 弹最左 = 踢 LRU

记:要 O(1) 查找 + O(1) 维护顺序 (移到最新、删掉最旧): dict + doubly linked list, dummy head / tail。

把第 1 题抽象一下: design 题怎么想

  1. 列出每个操作和它的复杂度要求。
  2. 对每个操作, 想"哪种数据结构能 O(1) 做到"。
  3. 如果一个结构做不完所有操作, 就组合两个。想清楚每次修改时, 两个结构要怎么同步 (LRU 里删 node 时也要删 dict 里的 key)。

常见的组合: dict + linked list (要顺序), dict + list (要随机取或按下标), dict + heap (要最值), dict + 有序 list + 二分 (要按时间 / 版本查)。

记:design 题 = 每个操作交给擅长它的结构 + 保持两个结构同步。

2. Insert Delete GetRandom O(1)

题目在问什么

设计一个 set, 支持 insert(val) (不存在才插入)、remove(val) (存在才删除)、getRandom() (等概率返回一个元素)。三个操作都要平均 O(1)。

看例子

Brute force

只用 set: insert / remove 是 O(1), 但 getRandom 要先转成 list, O(n)。只用 list: getRandom 是 random.choice, O(1), 但 remove 要先找到它、再删中间, O(n)。

Intuition: list 存元素, dict 记它在 list 里的位置

getRandom 需要"按位置随机取", 只能用 list。问题是 list 删中间很慢。

技巧: 删除时, 把要删的元素和 list 最后一个元素交换, 然后 pop 最后一个。pop 末尾是 O(1)。顺序乱了没关系, set 本来就不关心顺序。

但要和最后一个交换, 先得知道要删的元素在哪个位置。所以再用一个 dict 记 val → 它在 list 里的下标。交换之后, 被换过来的那个元素位置变了, dict 里也要更新它的下标。

算法

  1. insert: 已经在 dict 里就返回 False。否则 pos[val] = len(arr), arr.append(val)。
  2. remove: 不在就返回 False。i = pos[val], last = arr[-1]; 把 last 放到位置 i: arr[i] = last, pos[last] = i; 然后 arr.pop(), del pos[val]。
  3. getRandom: random.choice(arr)。

手动走一遍

复杂度

三个操作都是平均 Time O(1)。Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
import randomclass RandomizedSet: def __init__(self): # 能 O(1) random.choice(nums) <- 只有 list 能按 index O(1) 取 self.nums = [] # val -> 它在 nums 里的 index <- 只有 dict 能按 val O(1) 找 self.pos = {} def insert(self, val): if val in self.pos: return False self.pos[val] = len(self.nums) # 先记 index, 再 append self.nums.append(val) return True def remove(self, val): if val not in self.pos: return False i = self.pos[val] # 要删的 val 在哪 # 末尾元素: list 只有删末尾才是 O(1) last = self.nums[-1] self.nums[i] = last # 把末尾搬到 i, 覆盖 val # last 的 index 变了, dict 必须同步 self.pos[last] = i self.nums.pop() # 删尾巴 O(1) # 顺序不能反: val == last 时, 这行才会把它删干净 del self.pos[val] return True def getRandom(self): return random.choice(self.nums) # 每个 index 等概率

记:要 O(1) 删除 + O(1) 随机取: list + dict(val → index), 删除时和最后一个交换再 pop。

3. Time Based Key-Value Store

题目在问什么

set(key, value, timestamp) 记录 key 在某个时刻的值。get(key, t) 返回 key 在 timestamp ≤ t 里最新的那个值, 没有就返回空字符串。题目保证同一个 key 的 set 调用, timestamp 是严格递增的。

看例子

Brute force

每个 key 存一个 (timestamp, value) 的 list。get 时从后往前扫, 找第一个 timestamp ≤ t 的。O(n) 每次。

Intuition: list 本来就是排好序的, 用二分

timestamp 严格递增, 所以 set 时直接 append, list 天然就是按时间排好序的。

get 时要找"最后一个 timestamp ≤ t 的位置"。这正是 05 里的二分: bisect_right(times, t) - 1。结果是 -1 表示所有记录都比 t 晚, 返回空字符串。

算法

  1. data = defaultdict(list), 每个 key 对应 [(timestamp, value), ...]。
  2. set: append。
  3. get: 在 key 的 list 上二分, 找最后一个 ≤ t 的, 返回它的 value。

手动走一遍

复杂度

set O(1), get O(log n)。Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
from bisect import bisect_rightfrom collections import defaultdictclass TimeMap: def __init__(self): # key -> [timestamp ...] 严格递增 (题目保证) self.times = defaultdict(list) # key -> [value ...] 和 times 同一个 index self.vals = defaultdict(list) def set(self, key, value, timestamp): # 时间只增不减 -> append 之后天然有序, 不用 sort self.times[key].append(timestamp) self.vals[key].append(value) def get(self, key, timestamp): # 用 .get: 避免 defaultdict 悄悄造一个空 list ts = self.times.get(key) if not ts: return "" # 最后一个 <= t 的 idx; 全更大 -> -1 i = bisect_right(ts, timestamp) - 1 return self.vals[key][i] if i >= 0 else ""

记:按时间 / 版本查"某时刻之前最新的": 按时间 append 的 list + bisect_right - 1。

4. Design Hit Counter / Logger Rate Limiter

题目在问什么

Hit Counter: hit(t) 记录时刻 t 的一次访问; getHits(t) 返回过去 300 秒 (t - 300, t] 里的访问次数。所有调用的 t 都是单调不减的。

Logger Rate Limiter: shouldPrintMessage(t, msg): 同一条 message 在 10 秒内只打印一次。

看例子

Brute force

把所有 hit 的时间存进 list, getHits 时扫一遍数有几个在窗口里。list 会越来越长, 每次 O(总访问数)。

Intuition: 窗口外的记录永远没用了, 从左边扔掉

时间是单调增加的。一条记录一旦滑出了 300 秒的窗口, 以后的查询只会更晚, 它再也不会回到窗口里。所以可以直接扔掉。

最老的记录在最左边, 用 deque: 新的 hit 从右边 append, 查询时把左边过期的 popleft 掉, 剩下的个数就是答案。和 03 里 sliding window 是同一个思路。

Logger 更简单: 只需要 dict 记每条 message 上次打印的时间, 距离现在 ≥ 10 秒才打印并更新。

算法

  1. hit(t): q.append(t)。
  2. getHits(t): 当 q[0] <= t - 300: popleft。返回 len(q)。

手动走一遍

复杂度

每个记录只进出一次, 平均 O(1)。Space 是窗口里的记录数。如果同一秒访问特别多, 可以存 (时间, 次数) 压缩。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
from collections import dequeclass HitCounter: def __init__(self): # 时间戳, 左 = 最旧, 右 = 最新 (题目保证 timestamp 不减) self.q = deque() def hit(self, timestamp): self.q.append(timestamp) # 新的永远在右边 # 窗口: (timestamp - 300, timestamp] def getHits(self, timestamp): while self.q and self.q[0] <= timestamp - 300: # 过期的一定在最左边: 从左边出队, 每个时间戳只出一次 self.q.popleft() return len(self.q) # 剩下的就是窗口内的
# Logger Rate Limiter: 不用 deque, 一个 dict 就够class Logger: def __init__(self): # message -> 最早什么时候又可以打印 self.next_ok = {} def shouldPrintMessage(self, timestamp, message): if timestamp < self.next_ok.get(message, 0): return False # 还在 10 秒冷却里 self.next_ok[message] = timestamp + 10 return True

记:时间窗口里的计数, 时间单调: deque, 右边进、左边出过期的。

5. Snapshot Array

题目在问什么

一个长度为 n 的数组, 初始全是 0。支持 set(index, val)、snap() (拍一张快照, 返回快照编号, 从 0 开始)、get(index, snap_id) (返回第 snap_id 张快照里 index 位置的值)。

看例子

Brute force

每次 snap 都把整个数组复制一份存起来。snap 是 O(n), 调用很多次时内存和时间都爆了。

浪费: 两次 snap 之间可能只改了一两个位置, 却把整个数组都复制了。

Intuition: 每个位置只记"什么时候改成了什么"

不复制整个数组。对每个 index, 只记录它的修改历史: [(snap_id, val), ...], 意思是"在第 snap_id 张快照的时候 (还没拍之前), 它被改成了 val"。

snap 只需要把当前的编号加 1, O(1)。

get(index, snap_id): 在 index 的修改历史里, 找 snap_id ≤ 要查的编号的最后一条记录。这和第 3 题一模一样, 用二分。

算法

  1. hist[i] = [(-1, 0)] (初始值 0), snap_id = 0。
  2. set: 如果 hist[index] 最后一条的编号就是当前 snap_id, 直接覆盖; 否则 append (snap_id, val)。
  3. snap: snap_id += 1, 返回 snap_id - 1。
  4. get: 在 hist[index] 上二分找最后一个编号 ≤ snap_id 的, 返回它的值。

手动走一遍

复杂度

set、snap O(1), get O(log 修改次数)。Space 和修改次数成正比。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
from bisect import bisect_rightclass SnapshotArray: def __init__(self, length): # hist[i] = [(snap_id, val), ...] 只记录 "index i 在哪个 snap_id 期间 # 被改成了 val" # 初值 (0, 0): bisect 不会落到 -1 self.hist = [[(0, 0)] for _ in range(length)] # 下一次 snap() 要返回的 id = 当前 "进行中" 的版本 self.snap_id = 0 def set(self, index, val): h = self.hist[index] # 本版本里已经改过: 覆盖, 不重复记 if h[-1][0] == self.snap_id: h[-1] = (self.snap_id, val) else: # snap_id 只增 -> h 天然按 snap_id 有序 h.append((self.snap_id, val)) def snap(self): self.snap_id += 1 # O(1): 不复制任何东西 return self.snap_id - 1 def get(self, index, snap_id): h = self.hist[index] # 最后一个 <= snap_id 的记录 i = bisect_right(h, (snap_id, float("inf"))) - 1 return h[i][1]

记:版本 / 快照: 不复制整体, 每个位置记 (版本, 值) 的历史, 查询时二分。

6. LFU Cache (只讲结构)

题目在问什么

和 LRU 一样有容量, get / put 都要 O(1)。区别是满了要踢掉使用次数最少的 key; 使用次数一样的, 踢最久没用的那个。

看例子

Intuition: 按使用次数分组, 每组内部就是一个 LRU

需要同时知道"次数最少的是哪一组", 以及"这一组里最久没用的是谁"。结构:

  • key → (value, freq): 按 key 查。
  • freq → OrderedDict: 每个使用次数对应一组 key, 组内按最近使用排序 (就是一个小的 LRU)。
  • min_freq: 当前最小的使用次数。

一个 key 被使用时: 从 freq 组里删掉, freq + 1, 加到新的组的末尾。如果旧组空了而且它是 min_freq, min_freq 加 1。新 key 进来时 freq = 1, min_freq 设成 1。踢人时从 min_freq 组的最前面踢。

复杂度

get、put 都是 O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
from collections import defaultdict, OrderedDictclass LFUCache: def __init__(self, capacity): self.cap = capacity self.val = {} # key -> value self.freq = {} # key -> 访问次数 # freq -> {key: None}, 左 = 最久没用 self.bucket = defaultdict(OrderedDict) # 当前最小的 freq: 踢人去 bucket[min_freq] 的最左边 self.min_freq = 0 # key 被用了一次: 从 bucket[f] 搬到 bucket[f + 1] def _touch(self, key): f = self.freq[key] del self.bucket[f][key] if not self.bucket[f]: del self.bucket[f] # 最低的桶空了 -> 最小频率一定正好 +1 if self.min_freq == f: self.min_freq += 1 self.freq[key] = f + 1 self.bucket[f + 1][key] = None # 接到右边 = 这个频率里最新的 def get(self, key): if key not in self.val: return -1 self._touch(key) return self.val[key] def put(self, key, value): if self.cap == 0: return if key in self.val: self.val[key] = value self._touch(key) return # 满了: 先踢 (频率最低里, 最久没用的) if len(self.val) >= self.cap: old, _ = self.bucket[self.min_freq].popitem(last=False) if not self.bucket[self.min_freq]: del self.bucket[self.min_freq] del self.val[old] del self.freq[old] self.val[key] = value self.freq[key] = 1 self.bucket[1][key] = None # 新 key freq = 1, 一定是最小的 self.min_freq = 1

记:LFU = 按使用次数分组的 LRU, 加一个 min_freq 指向最少的那组。

7. 识别信号: 看到什么, 就想到什么组合
