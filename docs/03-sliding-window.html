03 · Sliding Window

这篇讲什么

面试里有一大类题是这样问的: 给你一个数组或字符串, 在里面找一段连续的部分, 满足某个条件, 然后问"最长是多少""最短是多少"或者"一共有多少段"。

这里"连续的一段"有专门的叫法。在数组里叫 subarray, 在字符串里叫 substring。比如 "abcde" 里, "bcd" 是 substring, "ace" 不是, 因为它跳过了字符。跳着取的那种叫 subsequence, 不在这篇的范围里。

这类题最直接的做法是把所有"连续的一段"都列出来, 一段一段检查。长度为 n 的数组有大约 n²/2 段, 所以至少 O(n²)。Sliding Window 就是专门把这类题从 O(n²) 降到 O(n) 的方法。

名字的意思很形象: 想象数组上放了一个可以伸缩的框 (window), 框住的那一段就是当前在看的 subarray。框的右边 (right) 一格一格往右推, 框的左边 (left) 在需要的时候也往右收。两条边都只往右走, 不回头。整篇就是在讲: 为什么可以不回头, 以及什么时候不能用。

这篇的题都来自公司高频题统计。第 1 题 Longest Substring Without Repeating Characters 在 470 家公司的总榜排第 4, 有 95 家公司考过。后面 7 道题每一道都是在第 1 题上改一个条件:

#题目考过的公司数相比上一题多了什么
1Longest Substring Without Repeating Characters95模板题: 求最长, 条件是"没有重复"
2Max Consecutive Ones III21条件换成"0 的个数 ≤ k"
3Longest Repeating Character Replacement18条件要多想一步才能写出来
4Permutation in String16框的长度是固定的
5Minimum Size Subarray Sum15求最短, 方向反过来
6Minimum Window Substring32求最短 + 判断条件变复杂
7Subarray Product Less Than K21不求长度, 求个数
8Subarrays with K Different Integers15"恰好 k" 不能直接做, 要拆开

每道题都按同一个顺序讲: 题目在问什么 → 看例子 → brute force → 从 brute force 里找 intuition → 算法 → 手动走一遍 → 复杂度。代码放在最后, 默认折叠。理解了算法以后, 代码你自己就能写出来。

前置知识: 只需要会用 dict 计数 (见 01 · Hash Table)。

1. Longest Substring Without Repeating Characters

题目在问什么

给一个字符串 s。在里面找一段连续的 substring, 要求这一段里每个字符最多出现一次。问: 满足要求的 substring 最长有多长。

看例子

从例子里能看出两件事。第一, "连续"很重要: Example 3 里 "pwke" 虽然没有重复字符, 但它不连续, 不算。第二, 答案只要长度, 不要具体是哪一段。

Brute force: 每个起点都试一遍

最直接的想法: 对每一个起点 left, 从它开始一个字符一个字符往右加, 用一个 set 记住已经见过的字符。一旦遇到 set 里已经有的字符, 说明重复了, 这个起点就到头了, 记下长度, 换下一个起点。

一共有 n 个起点, 每个起点最多往右走 n 步, 所以是 O(n²)。

看橙色圈的格子。比如 left = 3 那一行: 它检查 k, e, w 有没有重复。但上一行 left = 2 已经确认过 "wkew" 前面的 "wke" 不重复了。一段不重复的字符串, 去掉开头一个字符, 剩下的当然也不重复。所以 k 和 e 根本不用再查一遍。

Intuition: 换起点的时候, 不要从头再来

把上面的观察说完整:

  1. 假设当前这一段 s[left..right] 没有重复。
  2. 现在想把 right 往右扩一格, 加进来一个新字符 ch。
  3. 如果 ch 在这一段里没出现过, 那新的一段也没有重复, 继续扩就行。
  4. 如果 ch 在这一段里已经出现过, 那么只要这一段还包含着旧的那个 ch, 它就一定有重复。这时候再往右扩是没用的, 只会继续重复。唯一的办法是把左边收进来, 直到把旧的 ch 扔出去。
  5. 收完之后, 这一段又没有重复了。接着扩 right。

关键在第 4 步: left 只会往右收, 从来不需要回到左边去。因为左边那些起点, 在它们自己那一轮已经"试过并且失败了"。这就是 brute force 里橙色那部分重复劳动被省掉的原因。

这个"右边扩、左边收、两边都不回头"的框, 就是 sliding window。

算法

用一个 dict cnt 记录 window 里每个字符出现了几次。

  1. left = 0, best = 0。
  2. right 从 0 走到 n-1。每一步把 ch = s[right] 放进 window: cnt[ch] += 1。
  3. 如果 cnt[ch] > 1, 说明 ch 重复了。不断把最左边的字符 s[left] 移出 window (cnt[s[left]] -= 1, left += 1), 直到 cnt[ch] 回到 1。
  4. 这时 window 一定没有重复。用它的长度 right - left + 1 更新 best。

为什么第 3 步只需要检查 ch: 在 ch 进来之前, window 是没有重复的。所以如果现在有重复, 一定是刚进来的 ch 造成的。

手动走一遍

还是用 "pwwkew"。每一行是 right 走的一步。第 2 列是 ch 刚放进来的样子, 第 3 列是收完 left 之后的样子, 最右边是算长度。

对比 brute force 的图: 这里 right 走了 6 步, left 一共只往右移了 3 次, 每个字符最多进一次、出一次。

复杂度

Time O(n)。right 走 n 步, left 加起来最多也只走 n 步。虽然代码里 while 写在 for 里面, 但 while 一共最多执行 n 次, 不是每一轮 n 次。Space O(Σ), Σ 是字符集大小, 因为 cnt 里最多存这么多种字符。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def length_of_longest_substring(s): cnt = defaultdict(int) # window 里每个字符出现几次 left = best = 0 for right, ch in enumerate(s): cnt[ch] += 1 # ch 进 window while cnt[ch] > 1: # 不合法: ch 重复 (进来之前合法, 所以只可能是 ch) cnt[s[left]] -= 1 # 最左边的字符出 window left += 1 best = max(best, right - left + 1) return best

记:求最长 + 不能重复: 右边一格一格加进来。一旦重复, 就收左边, 直到不重复。left 永远不回头, 所以是 O(n)。

把第 1 题抽象一下: Sliding Window 什么时候能用

第 1 题里, left 能"永远不回头", 是因为一条性质: 一段如果已经不合法 (有重复), 那把它再往右扩, 还是不合法。反过来, 一段如果合法, 把它从左边缩短一点, 还是合法。

下面这张图把所有可能的 (left, right) 画成一个表格。每个格子是一段 substring。绿色是合法的段, 红色是不合法的。因为上面那条性质, 合法区和不合法区之间是一条阶梯状的边界。brute force 把每个格子都看一遍; sliding window 只沿着边界走。

所以判断一道题能不能用 sliding window, 就问一个问题: 把 window 往右扩一格, "合法"只会往一个方向变吗?

  • 求最长的题: window 越大越容易不合法 (重复、0 太多、乘积太大)。做法是: 不合法了才收左边, 收完再记答案。
  • 求最短的题: window 越大越容易合法 (和够大、覆盖了所有字符)。做法是: 一合法就记答案, 然后收左边看看还能不能更短。第 5 题会讲。
  • 如果扩一格可能变好也可能变坏 (比如数组里有负数), 这条性质就没了, 不能用 sliding window。要改用 04 · Prefix Sum。

后面每道题都是同一个骨架, 只换两样东西: window 里要记什么 (state), 和什么叫合法。

通用模板 (最长 / 最短 两个版本)
def window_longest(arr): left = 0 state = ... # window 内的统计量 (计数 / 和 / 积 ...) best = 0 for right, x in enumerate(arr): # right 只增不减 # 1. x 进 window: 更新 state while window 不合法: # 2. 不合法 -> 缩 left, 直到重新合法 # 把 arr[left] 移出 state left += 1 # left 也只增不减 best = max(best, right - left + 1) # 3. 此刻 window 合法, 更新答案 return best
def window_shortest(arr): left = 0 best = inf for right, x in enumerate(arr): # x 进 window while window 合法: # 合法了: 先记答案, 再尽量缩短 best = min(best, right - left + 1) # 把 arr[left] 移出 state left += 1 return best

记:sliding window 能用的前提: 合法性随 window 变大只往一个方向变。两个指针都只往右走, 所以 O(n)。

2. Max Consecutive Ones III

题目在问什么

给一个只有 0 和 1 的数组 nums, 和一个整数 k。你最多可以把 k 个 0 改成 1。问: 改完之后, 最长能得到多长的一段连续的 1。

看例子

换个角度看例子 1: 答案那一段 [0,1,1,1,1,0] 本来不全是 1, 但里面只有 2 个 0, 正好够 k = 2 次修改。所以题目其实在问: 找最长的一段, 里面 0 的个数不超过 k。真的去改数组是不需要的。

Brute force

和第 1 题一样: 每个起点往右扩, 数 0 的个数, 超过 k 就停。O(n²)。浪费也一样: 换起点时把中间那段的 0 又数了一遍。

Intuition

和第 1 题是同一个结构。一段里 0 已经超过 k 个了, 再往右扩, 0 只会更多, 不会变少。所以合法性是单调的, 可以用 sliding window。

和第 1 题的区别只有两处: window 里要记的东西从"每个字符几次"变成了"有几个 0" (一个整数 zeros); 不合法的条件从"有字符重复"变成了 zeros > k。

算法

  1. right 往右走, 遇到 0 就 zeros += 1。
  2. 当 zeros > k 时, 收左边: 如果 nums[left] 是 0 就 zeros -= 1, 然后 left += 1。一直收到 zeros ≤ k。
  3. 用 right - left + 1 更新 best。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def longest_ones(nums, k): zeros = 0 # window 里 0 的个数 = 需要翻转的次数 left = best = 0 for right, x in enumerate(nums): if x == 0: zeros += 1 while zeros > k: # 不合法: 要翻的 0 超过预算 k if nums[left] == 0: zeros -= 1 left += 1 best = max(best, right - left + 1) return best

记:"最多改 / 删 / 翻 k 个" → 找最长的一段, 里面"需要改的"不超过 k 个。

3. Longest Repeating Character Replacement

题目在问什么

给一个只有大写字母的字符串 s, 和整数 k。你最多可以把 k 个字符改成任意字母。问: 改完之后, 最长能得到多长的一段全是同一个字母的 substring。

看例子

例子 2 里 "AABA" 可以, 因为只要改 1 个 B。"AABAB" 不行, 因为要改 2 个 B, 超过了 k = 1。

Brute force

每个起点往右扩, 每扩一格就重新算一遍"这一段要改几个字符"。O(n²) 段。

Intuition

先回答一个更小的问题: 给定一段, 最少要改几个字符才能变成全是同一个字母?

答案是: 保留出现次数最多的那个字母, 其他的全改掉。比如 "AABA" 里 A 出现 3 次, 最多, 那就把剩下的 1 个改成 A。所以要改的个数 = 这一段的长度 - 出现最多的字母的次数。

于是"合法"就是 长度 - 最多的次数 ≤ k。和第 2 题比, 这里的"违规数"不是直接数出来的, 而是从 cnt 算出来的。

它也是单调的: window 往右扩一格, 长度加 1, 最多的次数最多也只加 1, 所以"要改的个数"只会不变或变大。

算法

  1. 用 dict cnt 记 window 里每个字母的次数。right 往右走, cnt[ch] += 1。
  2. 当 (right - left + 1) - max(cnt.values()) > k 时, 收左边。
  3. 用当前长度更新 best。

手动走一遍

复杂度

Time O(26n) = O(n), 每次 max(cnt.values()) 最多看 26 个字母。Space O(26)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def character_replacement(s, k): cnt = defaultdict(int) left = best = 0 for right, ch in enumerate(s): cnt[ch] += 1 # window 长度 - 出现最多的字符数 = 需要替换的字符数 while (right - left + 1) - max(cnt.values()) > k: cnt[s[left]] -= 1 # 注意: 不 del, 值变 0 不影响 max left += 1 best = max(best, right - left + 1) return best

记:合法条件可以是从 state 算出来的量 (长度 - 最多的次数), 只要它随 window 变大只会变坏, 就能用同一个骨架。

4. Permutation in String

题目在问什么

给两个字符串 s1 和 s2。问: s2 里有没有一段连续的 substring, 它是 s1 的某种重新排列 (permutation)。也就是: 长度和 s1 一样, 每个字母出现的次数也和 s1 一样, 只是顺序可以不同。

看例子

这题和前面三题有一个明显的不同: 要找的那一段长度是固定的, 必须正好等于 len(s1)。

Brute force

s2 里每个长度为 m (m = len(s1)) 的段都拿出来, 排个序, 和排好序的 s1 比。一共 n 段, 每段排序 O(m log m)。

浪费在哪: 相邻两段只差两个字符, 左边出去一个、右边进来一个, 中间 m-2 个字符都一样, 却每次都重新排序。

Intuition

两个字符串互为 permutation, 等价于每个字母的出现次数都一样。所以不用排序, 比两个计数表就行。

框的长度固定为 m, 所以 left 不用"收到合法为止", 而是每次 right 进来一个, left 就跟着出去一个, 框一直保持 m 长。每滑一格只改两个计数, 是 O(1) 的。

算法

  1. need = s1 里每个字母的次数。win = 当前框里每个字母的次数。
  2. right 往右走, 把 s2[right] 加进 win。
  3. 如果框的长度超过了 m (也就是 right ≥ m), 把 s2[right - m] 从 win 里减掉。
  4. 如果 win == need, 返回 True。

手动走一遍

Find All Anagrams in a String 是同一题, 区别只是不在第一次找到时返回, 而是把所有起点都记下来。

复杂度

Time O(26n), 每步比较两个长度 26 的表。Space O(26)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def check_inclusion(s1, s2): m = len(s1) need = [0] * 26 # s1 里每个字母要几个 win = [0] * 26 # 当前 window 里每个字母有几个 for ch in s1: need[ord(ch) - 97] += 1 for right, ch in enumerate(s2): win[ord(ch) - 97] += 1 # 右边进一个 if right >= m: # window 变成 m + 1 了 win[ord(s2[right - m]) - 97] -= 1 # 左边出一个 (left = right - m) if win == need: # 长度恒为 m 且计数相同 = permutation return True return False
def find_anagrams(s, p): m = len(p) need, win, res = [0] * 26, [0] * 26, [] for ch in p: need[ord(ch) - 97] += 1 for right, ch in enumerate(s): win[ord(ch) - 97] += 1 if right >= m: win[ord(s[right - m]) - 97] -= 1 if win == need: res.append(right - m + 1) # 唯一区别: 不 return, 记下起点 return res

记:长度固定为 m 的连续段: 右边进一个, 左边出一个, 用计数表代替排序。

5. Minimum Size Subarray Sum

题目在问什么

给一个全是正整数的数组 nums 和一个 target。找一段连续的 subarray, 它的和 ≥ target, 而且越短越好。问最短长度。找不到就返回 0。

看例子

这次要的是最短。例子 1 里 [2,3,1,2] 的和也够大, 但它有 4 个数, 而 [4,3] 只要 2 个。

Brute force

每个起点往右加, 加到和 ≥ target 就停, 记下长度。O(n²)。

Intuition: 方向反过来了

前四题都是"window 越大越容易不合法"。这题因为全是正数, window 越大和越大, 所以是"window 越大越容易合法"。方向反过来了。

于是做法也反过来:

  1. right 往右扩, 直到和刚好 ≥ target。这时找到了一个候选答案, 记下长度。
  2. 既然已经合法了, 就试着从左边收: 收掉一个, 和变小了, 如果还 ≥ target, 说明更短的也行, 再记一次。
  3. 一直收到和 < target 为止, 然后继续扩 right。

和"求最长"的模板相比, 区别有两个: while 的条件反过来 (合法才收), 以及记答案的位置挪到了 while 里面 (每收一次之前都记一次)。

算法

  1. total = 框里的数加起来。right 往右走, total += nums[right]。
  2. 当 total ≥ target 时: 先用 right - left + 1 更新 best (取 min), 再 total -= nums[left], left += 1。
  3. 最后 best 还是无穷大就返回 0。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def min_subarray_len(target, nums): total = 0 # window 里所有数相加 (nums 全是正数) left = 0 best = inf for right, x in enumerate(nums): total += x while total >= target: # 合法 (够大了): 先记答案, 再试着缩短 best = min(best, right - left + 1) total -= nums[left] left += 1 return 0 if best == inf else best

记:求最短: 合法了就记答案, 然后收左边看看还能不能更短。记答案要写在 while 里面。

6. Minimum Window Substring

题目在问什么

给字符串 s 和 t。在 s 里找最短的一段 substring, 它要包含 t 里的每一个字符。t 里重复的字符要重复包含, 比如 t = "AAB", 那这一段里至少要有 2 个 A 和 1 个 B。找不到就返回空字符串。

看例子

Brute force

枚举每一段, 用两个 Counter 比较这一段是否覆盖了 t。O(n²) 段, 每段比较还要时间。

Intuition

和第 5 题同一个结构: 框越大越容易覆盖 t (越容易合法), 要求最短。所以还是"扩到合法, 然后收到不合法"。

难点只有一个: 怎么快速知道当前框是否覆盖了 t。每次都把两个计数表完整比一遍太慢。

办法是记一个总数: missing = 框里还缺几个 t 需要的字符。一开始 missing = len(t)。再用 need[c] 记字符 c 还缺几个。

  1. 一个字符进框时, 如果它正好是缺的 (need[c] > 0), missing 减 1。不管缺不缺, need[c] 都减 1。need[c] 变成负数表示框里这个字符多了。
  2. 一个字符出框时, need[c] 加 1。如果加完变成正数, 说明它从"够了"变成了"缺了", missing 加 1。
  3. missing == 0 就是合法。这样判断合不合法只要看一个数。

算法

  1. right 往右走, 按上面第 1 条更新 need 和 missing。
  2. 当 missing == 0: 用当前框更新答案 (记下起点和长度), 然后按第 2 条把 s[left] 移出去, left += 1。
  3. 最后返回记下的那一段。

手动走一遍

复杂度

Time O(|s| + |t|), Space O(Σ)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def min_window(s, t): need = Counter(t) # >0: 还缺; =0: 刚好; <0: window 里多了 missing = len(t) # 还缺的字符总个数 (重复的字符按个数算) left = 0 best_len, best_start = inf, 0 for right, ch in enumerate(s): if need[ch] > 0: # ch 是"缺的", 才让 missing 减 1 missing -= 1 need[ch] -= 1 while missing == 0: # 合法: window 覆盖了 t if right - left + 1 < best_len: best_len, best_start = right - left + 1, left need[s[left]] += 1 # s[left] 出 window if need[s[left]] > 0: # 出去之后变成"缺"了 -> 不合法 missing += 1 left += 1 return "" if best_len == inf else s[best_start:best_start + best_len]

记:"包含 t 的所有字符": 用 need 记每种字符还缺几个, 用 missing 记一共还缺几个。missing == 0 就是合法。

7. Subarray Product Less Than K

题目在问什么

给一个全是正整数的数组 nums 和整数 k。数一数: 有多少段连续的 subarray, 乘积 < k。

看例子

这题第一次问的是个数, 不是长度。同一个元素可以出现在很多段里, 每一段都要算一次。

Brute force

每个起点往右乘, 乘到 ≥ k 就停, 停之前每一段都计一次数。O(n²)。

Intuition: 每一段按它的右端点来数

全是正数, 所以框越大乘积越大, 和前四题一样是"越大越容易不合法", 可以按"最长"的方式维护框。

问题是怎么数个数。关键想法: 每一段都有唯一的右端点。按右端点分组来数, 就不会重复也不会漏。

固定 right。sliding window 收完之后, [left..right] 是以 right 结尾的最长合法段。那么从它里面任取一个起点 (left, left+1, ..., right), 得到的段都更短, 乘积更小, 所以也都合法。这样的起点有 right - left + 1 个。

所以和前面的唯一区别: 把 best = max(best, 长度) 换成 ans += right - left + 1。

算法

  1. prod = 框里的数乘起来。right 往右走, prod *= nums[right]。
  2. 当 prod ≥ k 时, 收左边: prod //= nums[left], left += 1。
  3. ans += right - left + 1。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def num_subarray_product_less_than_k(nums, k): if k <= 1: # 正整数的乘积 >= 1, 一个都不合法 return 0 prod = 1 # window 里所有数相乘 left = ans = 0 for right, x in enumerate(nums): prod *= x while prod >= k: # 不合法: 乘积太大 prod //= nums[left] left += 1 ans += right - left + 1 # 以 right 结尾的合法 subarray 数 (起点 left..right) return ans

记:求个数: 按右端点分组, 每个 right 贡献 right - left + 1 段。前提还是合法性单调 (这里靠"全是正数")。

8. Subarrays with K Different Integers

题目在问什么

给一个整数数组 nums 和整数 k。数一数: 有多少段连续的 subarray, 里面恰好有 k 种不同的数字。

看例子

Brute force

每个起点往右扩, 用 set 数种类, 种类恰好 k 就计数, 超过 k 就停。O(n²)。

Intuition: "恰好" 不单调, 但 "最多" 单调

先试试直接套第 7 题。问题出在"恰好 k 种"不是单调的: 一段只有 1 种 (少了), 往右扩可能变成 2 种 (刚好), 再扩可能变成 3 种 (多了)。扩大既可能让它变合法, 也可能让它变不合法, left 不知道该怎么动。

但是 "最多 k 种" 是单调的: 一段已经超过 k 种了, 再扩只会更多。所以"最多 k 种的段有几个"可以直接用第 7 题的方法数。

然后用一个减法: 恰好 k 种 = 最多 k 种 - 最多 (k-1) 种。最多 k 种的段, 去掉最多 k-1 种的段, 剩下的就是恰好 k 种的。

算法

  1. 写一个函数 at_most(k): 用第 7 题的方法数"种类 ≤ k 的段有几个"。window 里用 dict 计数, len(cnt) 就是种类数, 某个数的次数减到 0 时要把它从 dict 里删掉。
  2. 答案 = at_most(k) - at_most(k - 1)。

手动走一遍

复杂度

Time O(n) (扫两遍), Space O(k)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def subarrays_with_k_distinct(nums, k): def at_most(k): # 最多 k 种不同数字的 subarray 个数 cnt = defaultdict(int) left = total = 0 for right, x in enumerate(nums): cnt[x] += 1 while len(cnt) > k: # 不合法: 种类超过 k cnt[nums[left]] -= 1 if cnt[nums[left]] == 0: del cnt[nums[left]] # 必须 del: len(cnt) 就是种类数 left += 1 total += right - left + 1 # 以 right 结尾的合法 subarray 数 return total return at_most(k) - at_most(k - 1) # exactly k = (<= k) - (<= k-1)

记:"恰好 k" 不单调, 拆成 atMost(k) - atMost(k-1), 两个都能用 sliding window 数。

9. 识别信号: 看到什么, 就想到 sliding window

读完上面 8 题以后, 这张表用来做最后的整理。面试时看到左边的特征, 先试右边的做法。
