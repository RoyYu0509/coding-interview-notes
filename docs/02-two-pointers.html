02 · Two Pointers

这篇讲什么

很多数组题的 brute force 是两层循环: 把所有的 pair (i, j) 都试一遍, O(n²)。Two Pointers 是用两个下标同时在数组上走, 每走一步都能说明"有一大批 pair 不用再看了", 于是只走 O(n) 步。

两个下标怎么放, 有三种常见的形状:

  • 相向: 一个从最左边、一个从最右边, 往中间走。用于排好序的数组找 pair、左右对称的问题 (第 1–4、9 题)。
  • 同向: 两个都从左边出发, 一个快一个慢。一个负责读, 一个负责写, 用于原地删除、过滤 (第 5、6 题)。
  • 各管一块: 几个下标当作分界线, 把数组切成几个区, 或者两个数组各放一个下标 (第 7、8 题)。

1. Two Sum II (Input Array Is Sorted)

题目在问什么

和 Two Sum 一样: 找两个不同位置的数, 和等于 target。区别是这次数组已经从小到大排好了, 而且要求只用 O(1) 额外空间, 所以不能用 dict。

看例子

Brute force: 所有 pair 都试

两层循环, 每个 pair (i, j) 都加一下, O(n²)。

把所有 pair 画成一张表格: 第 l 行第 r 列表示 nums[l] + nums[r]。brute force 就是把整张表的格子一个一个看过去。问题在于, 它完全没用上"数组排好序"这个信息。

Intuition: 比一次, 能排除一整行

排好序意味着: 同一行从左往右, 和越来越大; 同一列从上往下, 和也越来越大。

  1. 从表格的右上角开始, 也就是 l = 0 (最小的数) 和 r = n - 1 (最大的数)。
  2. 如果 nums[l] + nums[r] < target: nums[l] 和最大的数配都不够, 和其他任何数配只会更小。所以 nums[l] 不可能在答案里, 整行都可以划掉, l += 1。
  3. 如果 nums[l] + nums[r] > target: 同理, nums[r] 和最小的数配都太大, 整列划掉, r -= 1。
  4. 等于 target, 就找到了。

每比较一次, 就划掉一整行或一整列, 所以最多 n - 1 步。下面这张图就是这个过程:

算法

  1. l = 0, r = n - 1。
  2. 当 l < r: 算 s = nums[l] + nums[r]。
  3. s == target 返回; s < target 则 l += 1; s > target 则 r -= 1。

手动走一遍

复杂度

Time O(n): 每一步 l 加 1 或 r 减 1, 最多 n - 1 步。Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def two_sum_sorted(nums, target): # nums 已排序 l, r = 0, len(nums) - 1 while l < r: s = nums[l] + nums[r] if s == target: return [l, r] # LeetCode 167 要求 1-indexed, 返回时各 +1 if s < target: l += 1 # nums[l] 配 r 以及 r 左边所有数, 和都 <= s < target -> l 没用了 else: r -= 1 # nums[r] 配 l 以及 l 右边所有数, 和都 >= s > target -> r 没用了 return []

记:排好序 + 找 pair: 两个下标站两头。太小就移左边, 太大就移右边。每一步都排除一整批候选。

把第 1 题抽象一下: 什么时候能用相向双指针

第 1 题能用双指针, 是因为每次比较之后, 都能证明其中一个下标再也不会出现在答案里, 可以放心丢掉。

所以判断能不能用相向双指针, 就问: 比较完 (l, r) 之后, 我能不能确定丢掉 l 或者丢掉 r 不会错过答案? 能, 就可以 O(n)。

第 2–4 题都是这个思路, 区别只在于"丢谁"的理由不同。

记:相向双指针的核心: 每一步都要能证明"丢掉这一边不会错过答案"。

2. 3Sum

题目在问什么

给一个整数数组 (没排序)。找出所有满足 a + b + c = 0 的三元组。每个三元组只能出现一次, 比如 [-1, 0, 1] 和 [0, -1, 1] 算同一个。

看例子

Example 1 里有两个 -1, 但 [-1, 0, 1] 只能输出一次。去重是这道题最容易错的地方。

Brute force

三层循环试所有三元组, 再用 set 去重。O(n³)。

浪费在哪: 固定了前两个数 a 和 b 之后, 第三个数必须是 -(a + b), 它是被确定的。但第三层循环还是一个一个去找它。

Intuition: 固定一个, 剩下的就是第 1 题

先把数组排序。外层循环固定第一个数 nums[i], 剩下的问题是: 在 i 右边找两个数, 和等于 -nums[i]。这正是第 1 题, 用相向双指针 O(n) 解决。

去重也因为排序变简单了: 相同的值挨在一起。同一层里, 如果这个值和前一个一样, 就跳过。需要跳的地方有两处:

  • 外层: nums[i] == nums[i-1] 时跳过。否则同一个第一个数会算两遍。
  • 找到一组答案后, l 和 r 各自要跳过和刚才相同的值, 再继续找。

算法

  1. 排序。
  2. i 从 0 走到 n - 3。如果 i > 0 且 nums[i] == nums[i-1], 跳过。
  3. l = i + 1, r = n - 1, 按第 1 题找和为 -nums[i] 的 pair。
  4. 找到一组: 记录, 然后 l 往右跳过所有相同的值, r 往左跳过所有相同的值。

手动走一遍

复杂度

Time O(n²): 排序 O(n log n), 外层 n 次, 每次里层 O(n)。Space O(1) (不算排序和输出)。

4Sum 是再套一层: 固定两个, 里层双指针, O(n³)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def three_sum(nums): nums.sort() # 排序 O(n log n), 换来 "能丢一批" res = [] for i in range(len(nums) - 2): if nums[i] > 0: break # 最小的数都 > 0, 和不可能 = 0 if i > 0 and nums[i] == nums[i - 1]: continue # 去重 1: 同一个值只当一次 i l, r = i + 1, len(nums) - 1 # 里层 = Two Sum II while l < r: s = nums[i] + nums[l] + nums[r] if s < 0: l += 1 elif s > 0: r -= 1 else: res.append([nums[i], nums[l], nums[r]]) l += 1 r -= 1 while l < r and nums[l] == nums[l - 1]: # 去重 2: l 跳过同值 l += 1 while l < r and nums[r] == nums[r + 1]: # 去重 2: r 跳过同值 r -= 1 return res

记:k 个数的和: 排序, 固定 k - 2 个, 最里层用相向双指针。去重: 同一层不连续用同一个值。

3. Container With Most Water

题目在问什么

height[i] 是第 i 根竖线的高度。选两根线, 和 x 轴围成一个容器。能装的水 = 宽度 × 高度, 宽度是两根线的下标差, 高度是两根里较矮的那根 (水会从矮的那边溢出)。求最大能装多少。

看例子

Example 1 说明: 两根最高的线不一定最好, 宽度也很重要。

Brute force

所有 pair 都算一遍面积, 取最大。O(n²)。

Intuition: 丢掉矮的那根

这题数组没排序, 也没有 target, 但还是可以"比一次丢一个"。

  1. 从最宽的开始: l = 0, r = n - 1。
  2. 假设 height[l] < height[r]。考虑所有"保留 l, 换掉 r"的选择: 宽度只会更小 (r 往里走); 高度不会超过 height[l], 因为 l 是矮的那根, 它把高度封顶了。
  3. 所以保留 l 的所有其他选择, 面积都不会比现在大。l 可以丢掉, l += 1。
  4. 反过来 height[r] 更矮就丢 r。

一句话: 矮的那根限制了结果, 留着它只会越来越差。

算法

  1. l = 0, r = n - 1, best = 0。
  2. 算面积 min(height[l], height[r]) × (r - l), 更新 best。
  3. 矮的那边往里移一格。重复直到 l 和 r 相遇。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def max_area(height): l, r = 0, len(height) - 1 best = 0 while l < r: h = min(height[l], height[r]) # 水位由矮的那面墙决定 best = max(best, h * (r - l)) # 面积 = 水位 x 宽度 if height[l] < height[r]: l += 1 # 矮墙 l: 宽度只会更小, 高度仍 <= height[l] -> l 不可能更好, 丢掉 else: r -= 1 # 矮墙 r (或一样高): 同理丢 r return best

记:求 f(l, r) 的最大值, 往里收的时候宽度变小: 从最宽开始, 每次丢掉"限制了结果"的那一边。

4. Trapping Rain Water

题目在问什么

height[i] 是第 i 根柱子的高度, 每根宽度为 1。下雨之后, 柱子之间的凹槽会存水。问一共能存多少水。

看例子

从例子里能看出一个规律: 每一格能存多少水, 只取决于它左边最高的柱子和右边最高的柱子。水面高度是这两个里较矮的那个, 减去这一格自己的高度。

Brute force

每一格 i: 往左扫一遍找最高, 往右扫一遍找最高, 算 min(左最高, 右最高) - height[i]。每格 O(n), 共 O(n²)。

浪费: 相邻两格的"左边最高"几乎一样, 却每次重新扫。

Intuition 1: 先把左最高、右最高都算好

用两个数组: lmax[i] = 0..i 里最高的, 从左往右一遍就能算; rmax[i] = i..n-1 里最高的, 从右往左一遍。然后每格直接套公式。O(n) 时间, O(n) 空间。

Intuition 2: 其实只需要知道哪边更矮

公式里用的是 min(lmax, rmax)。我们其实不需要两个值都精确知道, 只需要知道哪个更小。

  1. 用两个下标: l 从左走, r 从右走。lmax = l 左边 (含 l) 最高的, rmax = r 右边 (含 r) 最高的。
  2. 如果 lmax < rmax: 对 l 这一格来说, 它右边至少有一根 rmax 那么高的柱子, 比 lmax 高。所以 l 的"右边最高" ≥ rmax > lmax, min 一定是 lmax。l 的水位已经确定了: lmax - height[l]。算完 l 往右走。
  3. 反过来 rmax ≤ lmax, 就确定了 r 的水位, r 往左走。

这样只用两个变量, 空间降到 O(1)。

算法

  1. l = 0, r = n - 1, lmax = rmax = 0, water = 0。
  2. 每一步先更新 lmax = max(lmax, height[l]), rmax = max(rmax, height[r])。
  3. lmax < rmax: water += lmax - height[l], l += 1; 否则 water += rmax - height[r], r -= 1。

手动走一遍

复杂度

Time O(n), Space O(1)。另有 monotonic stack 的做法 (见 07)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def trap(height): l, r = 0, len(height) - 1 # lmax = height[0..l] 的最大值, rmax = height[r..n-1] 的最大值 lmax, rmax = height[l], height[r] water = 0 while l < r: if lmax < rmax: # 右边至少有 rmax 比 lmax 高 -> min(左最高, 右最高) 一定是 lmax l += 1 lmax = max(lmax, height[l]) water += lmax - height[l] # 这一格的水 = lmax - h (h 是新高则为 0) else: r -= 1 # 对称: 左边至少有 lmax >= rmax rmax = max(rmax, height[r]) water += rmax - height[r] return water

记:每个位置的值由"左边的某个最值"和"右边的某个最值"决定: 先写出公式; 如果只需要比较两边的大小, 就用双指针代替两个数组。

5. Move Zeroes

题目在问什么

给一个数组, 把所有的 0 移到最后。非零的数要保持原来的先后顺序。必须在原数组上改, 不能新开数组。

看例子

Brute force

开一个新数组, 先放所有非零的数, 再补 0。O(n) 时间, 但用了 O(n) 空间, 题目不允许。

另一种: 每遇到一个 0, 就把后面的数全往前挪一格, 再把 0 放到最后。每次挪 O(n), 共 O(n²)。浪费: 同一个数被挪了很多次。

Intuition: 换一种双指针, 一个读一个写

这题的两个下标不再相向, 而是同向, 都从左边出发:

  • r 负责读: 每一步都往右走, 看每一个数。
  • w 负责写: 指向下一个非零数应该放的位置。只有读到非零数时才往右走。

读到非零数, 就和 w 位置交换, 然后 w 加 1。因为 w 永远 ≤ r, 写的位置总是在已经读过的区域里, 不会盖掉还没读的数。

任何时候数组都分成三段: [0, w) 是已经排好的非零数, [w, r) 全是 0, [r, n) 还没读。

算法

  1. w = 0。
  2. r 从 0 走到 n - 1。如果 nums[r] != 0: 交换 nums[w] 和 nums[r], w += 1。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def move_zeroes(nums): w = 0 # w = 下一个要写入 "非零" 的位置 for r in range(len(nums)): # r = 读到哪了 if nums[r] != 0: # 非零放到 w; 原来在 w 的一定是 0 (或 w == r) nums[w], nums[r] = nums[r], nums[w] w += 1 # invariant: nums[:w] 全是非零 (相对顺序不变), nums[w:r] 全是 0

记:原地删除 / 过滤, 还要保持顺序: r 读, w 写。nums[:w] 永远是已读部分的答案。

6. Remove Duplicates from Sorted Array

题目在问什么

给一个排好序的数组, 原地删除重复的数, 每个值只留一个。返回留下了几个 (记为 k)。数组的前 k 格必须是结果, 后面是什么都可以。

看例子

Brute force

用 set 去重再写回去, 但要 O(n) 空间。或者每遇到重复就 list.pop 删掉, 每次删 O(n), 共 O(n²)。

Intuition: 和第 5 题一样, 只换"留不留"的条件

还是 r 读 w 写。第 5 题"留下"的条件是 != 0, 这题是和上一个留下的数不同。

因为数组排好序, 相同的数一定挨在一起。所以只需要和最后一个留下的数 nums[w-1] 比较: 不同就写, 相同就跳过。被跳过的数不需要保留, 所以直接覆盖, 不用交换。

算法

  1. w = 1 (第一个数一定留下)。
  2. r 从 1 走到 n - 1。如果 nums[r] != nums[w-1]: nums[w] = nums[r], w += 1。
  3. 返回 w。

手动走一遍

复杂度

Time O(n), Space O(1)。

变体 Remove Duplicates II (每个值最多留 2 个): 只改一处, 和 nums[w-2] 比。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def remove_duplicates(nums): if not nums: return 0 w = 1 # nums[:w] 是 "已读部分去重后的结果" for r in range(1, len(nums)): if nums[r] != nums[w - 1]: # 重复的一定挨着, 只和 "最后保留的" 比 nums[w] = nums[r] w += 1 return w # 新长度; nums[:w] 就是答案
def remove_duplicates_k(nums, k=2): # Remove Duplicates II: 每个值最多保留 k 个 w = 0 for x in nums: if w < k or x != nums[w - k]: # 只改这一行: 和 "倒数第 k 个保留的" 比 nums[w] = x w += 1 return w

记:同向双指针的题, 区别只在"留下"的条件: != 0、和 nums[w-1] 不同、和 nums[w-k] 不同。

7. Sort Colors

题目在问什么

数组里只有 0、1、2 三种数。原地把它排成所有 0 在前、1 在中间、2 在最后。不能用内置的 sort, 最好只扫一遍。

看例子

Brute force

直接排序是 O(n log n)。或者数一下 0、1、2 各有几个, 再按个数写回去, O(n) 但要扫两遍。

Intuition: 三个下标, 切出四个区

第 5 题是把数组分成两类 (非零 / 零)。这题是三类, 那就用三个下标当分界线:

  • [0, lo): 已经确定是 0
  • [lo, i): 已经确定是 1
  • [i, hi]: 还没看过
  • (hi, n): 已经确定是 2

i 是当前在看的数。看到 0, 就把它换到 lo 的位置, lo 和 i 都前进; 看到 1, 它本来就该在中间, i 前进; 看到 2, 把它换到 hi 的位置, hi 后退。

一个细节: 看到 2 换完之后, i 不前进。因为从 hi 换过来的数还没看过, 下一步要检查它。看到 0 换完 i 可以前进, 因为从 lo 换过来的一定是 1 (已经看过)。

算法

  1. lo = 0, i = 0, hi = n - 1。
  2. 当 i ≤ hi: 是 0, 交换 nums[lo] 和 nums[i], lo 和 i 都加 1; 是 1, i 加 1; 是 2, 交换 nums[i] 和 nums[hi], hi 减 1 (i 不动)。

手动走一遍

复杂度

Time O(n), 一遍。Space O(1)。这个分区的思路也是 quick sort 里 partition 的基础。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def sort_colors(nums): lo, i, hi = 0, 0, len(nums) - 1 # [0, lo) 全是 0 | [lo, i) 全是 1 | [i, hi] 未知 | (hi, n) 全是 2 while i <= hi: if nums[i] == 0: # 换过来的是 1 (在 [lo, i) 里), 已经看过, 所以 i 可以前进 nums[lo], nums[i] = nums[i], nums[lo] lo += 1 i += 1 elif nums[i] == 2: # 换过来的是 "未知" 区的数, 还没看过 -> i 不动 nums[i], nums[hi] = nums[hi], nums[i] hi -= 1 else: i += 1

记:值只有 2~3 种, 要原地分类: 用几个下标当分界线。交换之后 i 要不要前进, 看换过来的数有没有看过。

8. Merge Sorted Array

题目在问什么

两个排好序的数组。nums1 长度是 m + n, 前 m 个是有效的数, 后 n 格是空位; nums2 有 n 个数。把 nums2 合并进 nums1, 结果要有序, 直接写在 nums1 里。

看例子

Brute force

把 nums2 复制到 nums1 后面的空位, 再整个排序。O((m+n) log(m+n))。浪费: 两个数组本来就各自有序, 却当成乱序来排。

Intuition: 从后往前合并

合并两个有序数组的标准做法是: 两个数组各放一个下标, 每次取小的那个放进结果, 取走的那边下标前进。O(m+n)。

但这里结果要写在 nums1 里。如果从前往后写, 会把 nums1 里还没读的数盖掉。

解决办法是从后往前: 每次取两个数组末尾较大的那个, 写到 nums1 的最后。nums1 的最后是空位, 写在那里永远不会盖掉没读的数。

算法

  1. i = m - 1 (nums1 有效部分的末尾), j = n - 1 (nums2 的末尾), k = m + n - 1 (写的位置)。
  2. 当 j ≥ 0: 如果 i ≥ 0 且 nums1[i] > nums2[j], 写 nums1[i], i 减 1; 否则写 nums2[j], j 减 1。每写一次 k 减 1。
  3. nums2 用完就结束。nums1 剩下的数本来就在正确的位置。

手动走一遍

复杂度

Time O(m + n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def merge(nums1, m, nums2, n): # nums1 长度 m + n, 后 n 格是空位 # i: nums1 最后一个有效数, j: nums2 最后一个数, k: 写入位置 i, j, k = m - 1, n - 1, m + n - 1 while j >= 0: # nums2 用完就结束, nums1 剩下的本来就在原位 if i >= 0 and nums1[i] > nums2[j]: nums1[k] = nums1[i] i -= 1 else: nums1[k] = nums2[j] j -= 1 k -= 1 # k 永远 >= i, 不会盖掉没读的 nums1

记:两个有序数组合并, 其中一个后面有空位: 从后往前, 每次取大的。写的方向要保证不会盖掉没读的数。

9. Valid Palindrome I / II

题目在问什么

I: 给一个字符串, 只看字母和数字, 忽略大小写, 判断它正着读和反着读是不是一样 (palindrome, 回文)。

II: 给一个只有小写字母的字符串, 最多删掉一个字符, 能不能变成回文。

看例子

Brute force

I: 先把字符串过滤成只有小写字母和数字的新串 t, 再比较 t == t[::-1]。O(n) 时间, 但开了新字符串, O(n) 空间。

II: 每个位置都试着删一次, 再检查是不是回文。n 个位置, 每次检查 O(n), 共 O(n²)。

Intuition

I: 回文就是左右对称。用两个下标从两头往中间走, 遇到不是字母数字的就跳过, 比较 s[l] 和 s[r] (转小写)。不用开新字符串。

II: 还是从两头往中间比。前面都相等时照常走。第一次不相等时, 只有两种可能的删法: 删 s[l], 或者删 s[r]。删别的位置没用, 因为这一对还是不相等。所以分别检查 s[l+1..r] 和 s[l..r-1] 是不是回文, 有一个是就行。

只会分叉一次 (只能删一个), 所以不会指数爆炸。

算法

  1. I: l = 0, r = n - 1。l 跳过非字母数字, r 也跳过。比较小写后的 s[l] 和 s[r], 不同就返回 False, 相同就 l 加 1、r 减 1。
  2. II: 同样两头往中间比。第一次失配时, 返回 是回文(l+1, r) or 是回文(l, r-1)。

手动走一遍

复杂度

都是 Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def is_palindrome(s): l, r = 0, len(s) - 1 while l < r: if not s[l].isalnum(): l += 1 # 跳过标点/空格 elif not s[r].isalnum(): r -= 1 elif s[l].lower() != s[r].lower(): return False else: l += 1 r -= 1 return True
def valid_palindrome_ii(s): # 最多删掉一个字符 def ok(l, r): # s[l..r] 本身是不是回文 (就是上面那个循环) while l < r: if s[l] != s[r]: return False l += 1 r -= 1 return True l, r = 0, len(s) - 1 while l < r: if s[l] != s[r]: # 第一次失配: 只有两种删法, 删 s[l] 或删 s[r] return ok(l + 1, r) or ok(l, r - 1) l += 1 r -= 1 return True

记:回文 / 对称: 两头往中间走。允许失配一次: 失配时两种删法都试一下。

10. 识别信号: 看到什么, 就想到 Two Pointers

题目特征做法complexity
排好序的数组, 找 pair / 和满足条件相向: 太小移左边, 太大移右边O(n²) → O(n)

每个位置由左边最值和右边最值决定先写公式, 两个数组 → 双指针两个变量空间 O(n) → O(1)

值只有 2~3 种, 原地分类几个下标切分区 (lo, i, hi)O(n log n) → O(n)
