02 · Two Pointers

主线: Two Pointers 用两个下标把 O(n²) 的 pair / 区间枚举压成 O(n) 的一遍扫描 —— 每走一步, 就能证明"有一整批候选再也不用看了"。

概念链: Two Sum II (相向, 丢一个) → 3Sum (外面套一层 + 去重) → Container (没有 sorted, 靠 greedy 证明丢谁) → Trapping Rain Water (公式 → 只需要 lmax / rmax 的大小关系) → Move Zeroes → Remove Duplicates (同向 read / write) → Sort Colors (三个 pointer 切四个区) → Merge Sorted Array (两个数组各一个 pointer, 从后往前) → Valid Palindrome I / II (对称, 失配分叉)。

0. 第一性原理: brute force 在浪费什么

最简单的例子: 有序数组 nums 里找两个数, 和等于 target。brute force 枚举所有 pair:

for i in range(n): for j in range(i + 1, n): # n(n-1)/2 个 pair if nums[i] + nums[j] == target: return [i, j]

Time O(n^2), Space O(1)。浪费在哪: 每个 pair 都当成互相独立的问题, 完全没用上 "数组是有序的" 这条信息。有序意味着: 比较一对 (l, r) 得到的不止是这一对的答案, 还顺带回答了一大批 pair。

看图: 网格里一个格子是一个 pair。比较 (0, 6) 发现 1 + 14 = 15 < 16, 那么 0 号数配任何更靠左的搭档只会更小, 整行一次排除。pointer 每走一步 = 划掉一整行或一整列, 所以 O(n^2) 个 pair 只需要 O(n) 步。

这个思路有三种常见形状, 按"两个 pointer 怎么放"区分:

形状 A: 相向 (opposite ends)

l, r = 0, len(a) - 1while l < r: if 太小: l += 1 # 证明: a[l] 配剩下任何搭档都不够, 丢 l elif 太大: r -= 1 # 证明: a[r] 配剩下任何搭档都太多, 丢 r else: 记录答案并移动

信号: sorted / 左右对称 / 一个量随 pointer 单调变化。Two Sum II, 3Sum, Container, Trapping Rain Water, Valid Palindrome 属于这类。

形状 B: 同向 (read / write)

w = 0for r in range(len(a)): # r 读, w 写; 永远 w <= r if 要保留(a[r]): a[w] = a[r] w += 1 # invariant: a[:w] = 已读部分的答案

信号: 原地删除 / 过滤 / 去重, 要求 O(1) 额外空间。Move Zeroes, Remove Duplicates 属于这类。

形状 C: 各管一个区间 / 一个数组

# 多个 pointer 当作区间的分界线 (Sort Colors); 或两个数组各一个 pointer (Merge)lo, i, hi = 0, 0, len(a) - 1 # [0,lo) 0 | [lo,i) 1 | [i,hi] 未知 | (hi,n) 2

Sliding Window (同向, 但 pointer 之间是一个窗口) 和 linked list 的 fast / slow 另有专门的文档, 这里不写。

1. Two Sum II (sorted): 比一次, 丢一个

题目: 有序数组 nums, 找两个数的下标使和等于 target。例: nums = [1, 3, 4, 6, 9, 12, 14], target = 16, 答案是 4 + 12 (下标 2, 5)。

Brute force: 枚举所有 pair, O(n^2)。浪费: 见第 0 节 —— 每对独立判断, 没用有序。

关键观察: 有序 + 站在两头。nums[l] + nums[r] 比 target 小, 说明 nums[l] 即使配上最大的搭档 nums[r] 都不够, 配别的更不够, l 可以丢; 比 target 大同理丢 r。

def two_sum_sorted(nums, target): # nums 已排序 l, r = 0, len(nums) - 1 while l < r: s = nums[l] + nums[r] if s == target: return [l, r] # LeetCode 167 要求 1-indexed, 返回时各 +1 if s < target: l += 1 # nums[l] 配 r 以及 r 左边所有数, 和都 <= s < target -> l 没用了 else: r -= 1 # nums[r] 配 l 以及 l 右边所有数, 和都 >= s > target -> r 没用了 return []

Time O(n): 每一步 l 增加或 r 减少, 总共最多 n - 1 步。Space O(1)。

记:sorted + 找 pair -> 相向 pointer; 比一次就能丢掉一个 pointer 对应的所有候选。没排序的 Two Sum 用 Hash Table (另有文档)。

2. 3Sum: 外面固定一个, 里面就是 Two Sum II

题目: 找出数组里所有和为 0 的不重复三元组。例: [-2, -2, 0, 0, 2, 2] -> [[-2, 0, 2]]。

Brute force: 三层循环 O(n^3)。浪费: 固定前两个数 i, j 后, 第三个数是被"确定"的, 却还在线性找。

相比上一题多了什么: (1) 多一个数: 先 sort, 外层枚举 i, 里层对 nums[i+1:] 做 target = -nums[i] 的 Two Sum II, 总共 O(n^2)。(2) 要去重: 排序后相同的值挨在一起, 所以"跳过和前一个相同的位置"就够了, 有两处。

def three_sum(nums): nums.sort() # 排序 O(n log n), 换来 "能丢一批" res = [] for i in range(len(nums) - 2): if nums[i] > 0: break # 最小的数都 > 0, 和不可能 = 0 if i > 0 and nums[i] == nums[i - 1]: continue # 去重 1: 同一个值只当一次 i l, r = i + 1, len(nums) - 1 # 里层 = Two Sum II while l < r: s = nums[i] + nums[l] + nums[r] if s < 0: l += 1 elif s > 0: r -= 1 else: res.append([nums[i], nums[l], nums[r]]) l += 1 r -= 1 while l < r and nums[l] == nums[l - 1]: # 去重 2: l 跳过同值 l += 1 while l < r and nums[r] == nums[r + 1]: # 去重 2: r 跳过同值 r -= 1 return res

Time O(n^2): 排序 O(n log n), 外层 n 次, 里层 l, r 每次最多走 n 步。Space O(1) (不算排序和输出)。

4Sum 就是再套一层: 固定两个, 里层 Two Sum II, O(n^3)。k-Sum 都是这个套路。

记:找 k 个数的和: sort, 固定 k - 2 个, 最里层相向 pointer。去重 = 同一层不能连续两次用同一个值。

3. Container With Most Water: 没有 target, 但可以证明丢谁

题目: height[i] 是第 i 根竖线的高度, 选两根线和 x 轴围成容器, 求最大面积。例: [1, 8, 6, 2, 5, 4, 8, 3, 7] -> 49。

Brute force: 所有 pair 算面积, O(n^2)。

相比上一题: 数组不是有序的, 也没有 target。但仍然可以"比一次丢一个": 从最宽 (l = 0, r = n - 1) 开始, 面积 = 矮墙高度 x 宽度。丢较矮的那面墙: 留着它的话, 宽度只会更小, 高度又被它自己封顶, 面积不可能更大。

def max_area(height): l, r = 0, len(height) - 1 best = 0 while l < r: h = min(height[l], height[r]) # 水位由矮的那面墙决定 best = max(best, h * (r - l)) # 面积 = 水位 x 宽度 if height[l] < height[r]: l += 1 # 矮墙 l: 宽度只会更小, 高度仍 <= height[l] -> l 不可能更好, 丢掉 else: r -= 1 # 矮墙 r (或一样高): 同理丢 r return best

Time O(n), Space O(1)。

记:最大化 f(l, r), 宽度随收缩变小 -> 从最宽开始, 丢"限制了结果"的那一边。关键是会证明: 丢它之后的所有候选都不可能更好。

4. Trapping Rain Water: 从公式推出两个变量

题目: height 是柱子高度, 下雨后能接多少水? 例: [2, 0, 1, 3, 0, 1, 2] -> 6。

第一性原理: 先只看一格 i。水能涨到的高度, 受左边最高墙和右边最高墙里较矮的那个限制: water[i] = min(左边最高, 右边最高) - height[i]。

Brute force: 每格往两边扫一遍求最高, O(n^2)。浪费: 相邻两格的"左边最高"几乎一样, 却重新算。改进 1: 预处理 lmax[], rmax[] 两个数组, O(n) 时间 O(n) 空间 (见图的表格)。

改进 2 (双指针): 我们其实不需要 min 里两个数的具体值, 只需要知道哪个更小。lmax 是 l 左边最高, rmax 是 r 右边最高。如果 lmax < rmax, 那么 l 的右边至少存在一面 rmax 那么高的墙, 比 lmax 高, 所以 l 这一格的 min 一定是 lmax —— 水位已经确定, 现在就能算, 然后 l 前进。反过来对称。

def trap(height): l, r = 0, len(height) - 1 # lmax = height[0..l] 的最大值, rmax = height[r..n-1] 的最大值 lmax, rmax = height[l], height[r] water = 0 while l < r: if lmax < rmax: # 右边至少有 rmax 比 lmax 高 -> min(左最高, 右最高) 一定是 lmax l += 1 lmax = max(lmax, height[l]) water += lmax - height[l] # 这一格的水 = lmax - h (h 是新高则为 0) else: r -= 1 # 对称: 左边至少有 lmax >= rmax rmax = max(rmax, height[r]) water += rmax - height[r] return water

Time O(n): 每一步 l 或 r 前进一格。Space O(1): 两个 max 变量。

另有单调栈做法 (按层累加, 放在 Monotonic Stack 那份文档), 面试里双指针更短。

记:每个位置的值由"左边某统计量"和"右边某统计量"的 min / max 决定 -> 先写公式, 再问: 能不能只比较大小而不存数组? 能 -> 双指针。

5. Move Zeroes: 同向 read / write

题目: 把所有 0 移到末尾, 非零元素保持相对顺序, 必须原地。例: [0, 1, 0, 3, 12] -> [1, 3, 12, 0, 0]。

Brute force: 开新数组, 先放非零再补 0, O(n) 时间但 O(n) 空间; 或者每遇到 0 就把后面所有元素左移, O(n^2)。浪费: 移动同一个元素很多次 / 多开了空间。

相比上一题: 两个 pointer 不再相向, 而是同向。r 负责读, w 负责写, 速度不同: r 每步都走, w 只在遇到要保留的元素时走。因为 w <= r, 写入的位置总在读过的区域里, 不会盖掉没读的数据。

def move_zeroes(nums): w = 0 # w = 下一个要写入 "非零" 的位置 for r in range(len(nums)): # r = 读到哪了 if nums[r] != 0: # 非零放到 w; 原来在 w 的一定是 0 (或 w == r) nums[w], nums[r] = nums[r], nums[w] w += 1 # invariant: nums[:w] 全是非零 (相对顺序不变), nums[w:r] 全是 0

Time O(n), Space O(1)。把 swap 换成赋值再把剩下的补 0 也行 (Remove Element 就是那个形式)。

记:原地过滤 / 压缩, 保持相对顺序 -> r 读 w 写; invariant 是 nums[:w] = 已读部分的答案。

6. Remove Duplicates from Sorted Array: 比较的对象换成 nums[w-1]

题目: 有序数组原地去重, 返回新长度。例: [0, 0, 1, 1, 2, 2, 3] -> 4, 前 4 格是 [0, 1, 2, 3]。

Brute force: 用 set 去重再写回, 但 O(n) 空间; 或遇到重复就删除一个元素 (list.pop 是 O(n)), 总共 O(n^2)。

相比上一题: "要保留"的条件变了 —— 不是 != 0, 而是和最后一个保留的值不同。有序所以重复的挨着, 只需要和 nums[w-1] 比。也不需要 swap: 残留的值反正不要, 直接覆盖。

def remove_duplicates(nums): if not nums: return 0 w = 1 # nums[:w] 是 "已读部分去重后的结果" for r in range(1, len(nums)): if nums[r] != nums[w - 1]: # 重复的一定挨着, 只和 "最后保留的" 比 nums[w] = nums[r] w += 1 return w # 新长度; nums[:w] 就是答案

Time O(n), Space O(1)。

Remove Duplicates II (每个值最多留 2 个) 只改一行, 把比较位置换成 nums[w-k]:

def remove_duplicates_k(nums, k=2): # Remove Duplicates II: 每个值最多保留 k 个 w = 0 for x in nums: if w < k or x != nums[w - k]: # 只改这一行: 和 "倒数第 k 个保留的" 比 nums[w] = x w += 1 return w

记:同向 pointer 的差别只有"保留条件": 非零 / 和 nums[w-1] 不同 / 和 nums[w-k] 不同。套模板, 改条件。

7. Sort Colors: 三个 pointer, 切出四个区

题目: 只含 0, 1, 2 的数组, 原地排序。例: [2, 0, 2, 1, 1, 0] -> [0, 0, 1, 1, 2, 2]。

Brute force: 直接 sort, O(n log n)。或 counting 两遍扫描 O(n) 但要先数再写。浪费: 值域只有 3 个, 却用了通用排序。

相比上一题: 保留的不止一类。思路是 partition: 一边读 (i), 一边把读到的数放进它该去的区 —— 0 放左边 (lo), 2 放右边 (hi), 1 留在中间。难点是 invariant: 交换之后 i 要不要前进? 看换过来的数有没有被检查过。

def sort_colors(nums): lo, i, hi = 0, 0, len(nums) - 1 # [0, lo) 全是 0 | [lo, i) 全是 1 | [i, hi] 未知 | (hi, n) 全是 2 while i <= hi: if nums[i] == 0: # 换过来的是 1 (在 [lo, i) 里), 已经看过, 所以 i 可以前进 nums[lo], nums[i] = nums[i], nums[lo] lo += 1 i += 1 elif nums[i] == 2: # 换过来的是 "未知" 区的数, 还没看过 -> i 不动 nums[i], nums[hi] = nums[hi], nums[i] hi -= 1 else: i += 1

Time O(n) 一遍扫描 (每步 i 前进或 hi 后退), Space O(1)。

同样的 partition 思路是 quick sort 的 partition 和 Quickselect 的基础; 只有两类时 (0 / 1) 退化成 Move Zeroes。

记:值域很小 (2~3 种) 要原地分类 -> 三路 partition。交换完 i 是否前进, 取决于换来的数是不是已经看过。

8. Merge Sorted Array: 两个数组各一个 pointer, 从后往前

题目: nums1 前 m 个有效, 后 n 格是空位; nums2 有 n 个; 两个都有序, 合并到 nums1 里。例: [1, 2, 3, _, _, _] + [2, 5, 6]。

Brute force: 把 nums2 复制进后 n 格再 sort, O((m+n) log(m+n))。浪费: 两个数组本来各自有序, 却当成乱序。

标准 merge 是 "各一个 pointer, 取小的", O(m+n)。但这里 nums1 要原地写: 从前往后写会盖掉 nums1 还没读的数。从后往前: 取大的写到末尾, 末尾是空位, 永远安全。

def merge(nums1, m, nums2, n): # nums1 长度 m + n, 后 n 格是空位 # i: nums1 最后一个有效数, j: nums2 最后一个数, k: 写入位置 i, j, k = m - 1, n - 1, m + n - 1 while j >= 0: # nums2 用完就结束, nums1 剩下的本来就在原位 if i >= 0 and nums1[i] > nums2[j]: nums1[k] = nums1[i] i -= 1 else: nums1[k] = nums2[j] j -= 1 k -= 1 # k 永远 >= i, 不会盖掉没读的 nums1

Time O(m + n), Space O(1)。循环条件是 j >= 0: nums2 用完时 nums1 剩下的数已经在原位。

记:两个有序序列合并 + 其中一个后面有空位 -> 从后往前。写的方向要保证不会覆盖还没读的数据。

9. Valid Palindrome I / II: 向中间配对, 失配时最多分叉一次

Valid Palindrome: 忽略非字母数字和大小写, 判断是不是回文。例: "A,bxB;a" -> True。

Brute force: 先过滤并转小写得到新字符串 t, 比较 t == t[::-1], O(n) 时间 O(n) 空间。浪费: 开了新字符串。双指针直接在原串上跳过标点, 空间 O(1)。

def is_palindrome(s): l, r = 0, len(s) - 1 while l < r: if not s[l].isalnum(): l += 1 # 跳过标点/空格 elif not s[r].isalnum(): r -= 1 elif s[l].lower() != s[r].lower(): return False else: l += 1 r -= 1 return True

Time O(n), Space O(1)。

II (最多删一个字符): 相比 I, 失配时不再直接返回 False, 而是两种删法都试: 删 s[l] 或删 s[r], 之后剩下的必须是普通回文。为什么只有两种: 删别的位置, 这一对 (s[l], s[r]) 还是不相等。为什么不会指数爆炸: 分叉只发生一次 (删除额度只有 1), 之后是线性检查。

def valid_palindrome_ii(s): # 最多删掉一个字符 def ok(l, r): # s[l..r] 本身是不是回文 (就是上面那个循环) while l < r: if s[l] != s[r]: return False l += 1 r -= 1 return True l, r = 0, len(s) - 1 while l < r: if s[l] != s[r]: # 第一次失配: 只有两种删法, 删 s[l] 或删 s[r] return ok(l + 1, r) or ok(l, r - 1) l += 1 r -= 1 return True

Time O(n) (主循环一次 + 最多 2 次检查), Space O(1)。"最多删 k 个" 的版本要换成 DP 或 recursion, 不是双指针了。

记:对称 / 回文 -> 两端向中间; 先写 "相等就两边各走一步", 再考虑跳过规则和失配怎么处理。

10. 识别信号: 看到什么 → 试什么

特征做法complexity
sorted array, 找 pair / 满足 "和" 的条件相向 l, r; 太小 l++, 太大 r--O(n^2) → O(n)
找 k 个数的和 (3Sum, 4Sum)sort, 固定 k-2 个, 最内层相向; 同层跳过同值去重O(n^k) → O(n^{k-1})
最大化 f(l, r), 向内收缩时某个量只会变差从最宽开始, 丢"限制结果"的一边 (Container)O(n^2) → O(n)
每个位置的值由左边统计量和右边统计量的 min / max 决定先写公式, lmax[] / rmax[] 数组 → 双指针只留两个变量 (Trapping Rain Water)时间 O(n), 空间 O(n) → O(1)
原地删除 / 过滤 / 去重, 保持相对顺序同向 r 读 w 写; 保留条件是唯一要改的地方O(n^2) (逐个删除) 或 O(n) 空间 → O(n) 时间 O(1) 空间
值域只有 2~3 种, 要原地分类三路 partition: lo, i, hi 切四个区O(n log n) → O(n) 一遍
两个有序序列合并, 一个有空位各一个 pointer, 从后往前写O((m+n) log (m+n)) → O(m+n)
回文 / 对称结构, 或者 reversel, r 从两端向中间; 失配最多分叉一次 (II)O(n) 空间 → O(1) 空间

先问两件事: 数组是不是有序 (或能不能先排序)? 要不要保持原地 / 相对顺序? 这两个答案基本决定了用哪种形状。
