08 · Linked List

这篇讲什么

linked list (链表) 是一串 node, 每个 node 有一个值 val 和一个指向下一个 node 的 next。最后一个 node 的 next 是 None。手里通常只有第一个 node, 叫 head。

和数组比, 它有一个根本的限制: 不能按下标直接访问, 只能从 head 开始顺着 next 一个一个往后走。好处是只要手里有某个 node, 在它后面插入或删除都是 O(1), 改一下 next 就行。

所以 linked list 的题, 本质上都是在改 next 指针。容易出错的地方也都在这里: 改了某个 node 的 next 之后, 原来它后面的那些 node 就找不到了。所有技巧都是为了避免这个问题:

  • 改 next 之前, 先把以后要用的 node 存进变量。
  • dummy node: 在 head 前面放一个假的 node, 这样 head 也有"前一个", 删除或替换 head 时不用特判。最后返回 dummy.next。
  • 快慢指针: 两个指针用不同的速度走, 用来找中点、找倒数第 n 个、判断有没有环。
ListNode 的定义
class ListNode: def __init__(self, val=0, next=None): self.val = val self.next = next

1. Reverse Linked List

题目在问什么

给一条 linked list 的 head, 把它反转, 返回新的 head。

看例子

Brute force

把所有值读进一个数组, 反过来再建一条新 list。O(n) 时间, 但用了 O(n) 额外空间, 而且没有真正"反转"原来的 list。

Intuition: 每个箭头掉头

反转就是让每个 node 的 next 指向它前面的那个 node。从左往右走, 每到一个 node (叫 curr), 把它的 next 改成指向前一个 (叫 prev)。

问题是: 改完 curr.next = prev 之后, curr 原来后面的 node 就找不到了 (上面那张图的情况)。所以改之前, 先用 nxt 把它存下来。

每一步四个动作, 顺序不能乱: 存下一个 → 掉头 → prev 前进 → curr 前进。

算法

  1. prev = None, curr = head。
  2. 当 curr 不是 None: nxt = curr.next; curr.next = prev; prev = curr; curr = nxt。
  3. 返回 prev (curr 走出末尾时, prev 是原来的最后一个, 也就是新的 head)。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def reverseList(head): prev, curr = None, head while curr: nxt = curr.next # 1. 先存下一个, 否则改完 next 就找不到了 curr.next = prev # 2. 把箭头掉头, 指向前一个 prev = curr # 3. prev 前进 curr = nxt # 4. curr 前进 return prev # curr 走到 None 时, prev 是新的 head

记:改 next 之前, 先存下以后还要用的 node。反转: nxt = curr.next → curr.next = prev → prev = curr → curr = nxt。

2. Merge Two Sorted Lists

题目在问什么

两条排好序的 linked list, 合并成一条排好序的 linked list。直接把原来的 node 接起来, 不新建 node。

看例子

Brute force

把所有值读出来排序, 再建新 list。O((m+n) log(m+n)), 没用上"已经排好序"。

Intuition: 每次取两个头里小的那个

和 02 里合并两个有序数组一样: 两条 list 当前的头里, 小的那个一定是剩下所有 node 里最小的, 把它接到结果后面, 那条 list 往后走一步。

两个技巧:

  • dummy: 结果 list 一开始是空的, 第一次接的时候要特判 "结果的 head 是谁"。放一个假的 dummy 当头, 永远往它后面接, 最后返回 dummy.next。
  • tail: 一直指向结果的最后一个 node, 接的时候直接 tail.next = ..., 不用每次从头走。

一条走完之后, 另一条剩下的部分本来就是排好序的, 直接接上。

算法

  1. dummy = tail = ListNode()。
  2. 当两条都没走完: 小的那个接到 tail 后面, 它那条 list 往后走; tail = tail.next。
  3. tail.next = l1 or l2。返回 dummy.next。

手动走一遍

复杂度

Time O(m + n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def mergeTwoLists(l1, l2): dummy = tail = ListNode() # dummy: 假的头, 省掉 "结果为空" 的特判 while l1 and l2: if l1.val <= l2.val: tail.next, l1 = l1, l1.next else: tail.next, l2 = l2, l2.next tail = tail.next # tail 永远是结果的最后一个 node tail.next = l1 or l2 # 剩下的一条直接接上 return dummy.next

记:要建一条新的结果 list: dummy 当头 + tail 指向末尾, 最后返回 dummy.next。

3. Middle of the Linked List / Linked List Cycle

题目在问什么

Middle: 返回中间的 node, 偶数个时返回第二个中间的。Cycle: 判断 list 里有没有环 (顺着 next 走会不会走回来)。

看例子

Brute force

Middle: 先走一遍数出长度 n, 再走 n/2 步。要走两遍。

Cycle: 用一个 set 记下走过的 node, 走到已经在 set 里的就是有环。O(n) 空间。

Intuition: 两个指针, 一个快一个慢

让 slow 每次走 1 步, fast 每次走 2 步, 同时从 head 出发。

  • 找中点: fast 走的距离永远是 slow 的两倍。所以 fast 走到末尾时, slow 正好走了一半, 就在中间。只要一遍。
  • 判断环: 如果没有环, fast 会先走到 None。如果有环, 两个指针最后都会进入环里一直转圈; 在环里, fast 每一轮比 slow 多走 1 步, 两者之间的距离每轮缩小 1, 所以一定会在某一轮正好相遇。相遇就说明有环, 不需要 set。

算法

  1. slow = fast = head。
  2. 当 fast and fast.next: slow 走 1 步, fast 走 2 步。Cycle 版本里, 每走一次检查 slow is fast。
  3. Middle 返回 slow; Cycle 循环正常结束就返回 False。

手动走一遍

复杂度

Time O(n), Space O(1)。进阶 (Linked List Cycle II, 找环的入口): 相遇后让一个指针回到 head, 两个都每次走 1 步, 再次相遇的地方就是入口。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def middleNode(head): slow = fast = head while fast and fast.next: slow = slow.next fast = fast.next.next return slow # fast 走完时, slow 正好在中间
def hasCycle(head): slow = fast = head while fast and fast.next: slow = slow.next # 一次走 1 步 fast = fast.next.next # 一次走 2 步 if slow is fast: # 有环: fast 一定会从后面追上 slow return True return False # fast 走到了尽头: 没有环

记:快慢指针: slow 1 步, fast 2 步。fast 到末尾时 slow 在中间; 有环则一定相遇。

4. Remove Nth Node From End of List

题目在问什么

删掉 linked list 的倒数第 n 个 node, 返回 head。要求只遍历一遍。

看例子

Example 2 里删掉的是 head 本身, 用 dummy 可以避免特判。

Brute force

先走一遍数出长度 L, 倒数第 n 个就是正数第 L - n + 1 个, 再走一遍找到它前面那个, 删掉。两遍。

Intuition: 让两个指针隔开固定的距离

要删一个 node, 得停在它前面那个 node 上, 才能改 next 跳过它。

让 fast 先走 n + 1 步, 然后 fast 和 slow 一起走。两者之间的距离一直是 n + 1。当 fast 走出末尾 (变成 None) 时, slow 离末尾正好 n + 1 步, 也就是停在倒数第 n 个的前一个。

从 dummy 出发 (不是 head), 这样要删 head 时, slow 正好停在 dummy 上, 不用特判。

算法

  1. dummy = ListNode(0, head), fast = slow = dummy。
  2. fast 先走 n + 1 步。
  3. 当 fast 不是 None: 两个一起走一步。
  4. slow.next = slow.next.next。返回 dummy.next。

手动走一遍

复杂度

Time O(L), 一遍。Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def removeNthFromEnd(head, n): dummy = ListNode(0, head) fast = slow = dummy # fast 先走 n + 1 步, 和 slow 拉开 n + 1 的距离 for _ in range(n + 1): fast = fast.next while fast: # 一起走, 直到 fast 走出末尾 fast, slow = fast.next, slow.next slow.next = slow.next.next # slow 停在要删的 node 的前一个 return dummy.next

记:倒数第 n 个: fast 先走 n (+1) 步, 再一起走; 从 dummy 出发, 删 head 不用特判。

5. Add Two Numbers

题目在问什么

两个非负整数, 每一位存在一个 node 里, 而且是倒着存的 (个位在第一个 node)。把两数之和用同样的格式返回。

看例子

Brute force

把两条 list 转成整数, 相加, 再转回 list。在 Python 里能做 (整数没有上限), 但在其他语言里会溢出, 面试官想看的是逐位相加。

Intuition: 就是竖式加法

倒着存的好处是: 从 head 开始走, 正好是从个位开始, 和手算竖式加法的顺序一样。

每一位: s = carry + l1 这一位 + l2 这一位 (哪条走完了就当 0)。新的这一位是 s % 10, 进位 carry = s // 10。建一个新 node 接到结果后面 (用第 2 题的 dummy + tail)。

循环条件是 l1 or l2 or carry: 两条都走完了但还有进位时, 还要再加一个 node, 比如 5 + 5 = 10。

算法

  1. dummy = tail = ListNode(), carry = 0。
  2. 当 l1 或 l2 或 carry: 加起来, carry, digit = divmod(s, 10), 新建 node(digit) 接到 tail 后面。
  3. 返回 dummy.next。

手动走一遍

复杂度

Time O(max(m, n)), Space O(max(m, n)) (结果)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def addTwoNumbers(l1, l2): dummy = tail = ListNode() carry = 0 while l1 or l2 or carry: s = carry if l1: s, l1 = s + l1.val, l1.next if l2: s, l2 = s + l2.val, l2.next carry, digit = divmod(s, 10) # 进位, 当前位 tail.next = ListNode(digit) tail = tail.next return dummy.next

记:逐位相加: 边走边建新 node, 处理进位; 循环条件里别忘了 carry。

6. Reverse Nodes in k-Group

题目在问什么

每 k 个 node 一组, 每组内部反转。最后剩下的不够 k 个, 保持原样。只能改 next, 不能改 val。

看例子

Brute force

把值读进数组, 每 k 个反转一次, 再写回去。但题目不允许改 val, 而且要 O(1) 空间。

Intuition: 第 1 题的局部版本, 反转完再接回去

对每一组, 做三件事:

  1. 确认够 k 个: 从上一组的最后一个 (group_prev) 往后数 k 个, 找到这一组的第 k 个 (kth)。不够就结束。
  2. 组内反转: 和第 1 题完全一样, 只是 prev 一开始不是 None, 而是这一组后面的那个 node (group_next)。这样反转完, 这一组原来的第一个 node 自然就指向了后面。
  3. 接回前面: 上一组的最后一个 (group_prev) 原来指向这一组的第一个, 现在要改成指向 kth (这一组新的头)。原来的第一个变成了这一组的最后一个, 它就是下一组的 group_prev。

用 dummy 当第一个 group_prev, 这样第一组也不用特判。

算法

  1. dummy = ListNode(0, head), group_prev = dummy。
  2. 循环: 找 kth, 找不到就返回 dummy.next。
  3. group_next = kth.next; 用 prev = group_next 反转这一组。
  4. first = group_prev.next; group_prev.next = kth; group_prev = first。

手动走一遍

复杂度

Time O(n), Space O(1)。Reverse Linked List II (反转第 left 到 right 个) 是同样的"局部反转 + 接回"。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def reverseKGroup(head, k): dummy = ListNode(0, head) group_prev = dummy # 上一组的最后一个 node while True: kth = group_prev for _ in range(k): # 往后数 k 个, 不够 k 个就结束 kth = kth.next if not kth: return dummy.next group_next = kth.next # 和 reverseList 一样, 只是 prev 从 group_next 开始 prev, curr = group_next, group_prev.next while curr is not group_next: nxt = curr.next curr.next = prev prev, curr = curr, nxt # 反转前的第一个, 现在是这一组的最后一个 first = group_prev.next # 上一组接到这一组的新头 (原来的第 k 个) group_prev.next = kth group_prev = first

记:反转一段: 记住这一段前面的 node 和后面的 node, 段内照第 1 题反转, 再把前后接上。

7. Copy List with Random Pointer

题目在问什么

每个 node 除了 next, 还有一个 random 指针, 可以指向 list 里任意一个 node 或者 None。返回这条 list 的深拷贝: 每个 node 都新建, 新 list 的 next 和 random 都要指向新的 node。

看例子

Brute force

先按 next 复制出新 list。然后对每个新 node, 要找它的 random 应该指向哪个新 node: 从原 list 的 head 开始数, 原 node 的 random 是第几个, 再在新 list 里数到第几个。每个都要 O(n), 共 O(n²)。

Intuition: 用 dict 从"原 node"直接找到"对应的新 node"

难点就是: 知道原 node 的 random 是 X, 怎么快速找到 X 对应的新 node? 用一个 dict old2new 记下每个原 node 对应的新 node。

分两遍: 第一遍只新建 node, 填好 old2new; 第二遍再连 next 和 random: new.next = old2new[old.next], new.random = old2new[old.random]。必须分两遍, 因为 random 可能指向后面还没建的 node。

这和 12 里的 Clone Graph 是同一个思路。

算法

  1. old2new = {None: None}。第一遍: 每个 node 新建一个, 放进 old2new。
  2. 第二遍: 按 old2new 连每个新 node 的 next 和 random。
  3. 返回 old2new[head]。

手动走一遍

复杂度

Time O(n), Space O(n)。另有 O(1) 空间的做法: 把每个新 node 插在原 node 后面, 利用相对位置找 random, 最后再拆开。面试里 dict 写法就够了。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
class Node: def __init__(self, x, next=None, random=None): self.val, self.next, self.random = x, next, randomdef copyRandomList(head): old2new = {None: None} # 原 node -> 新 node cur = head while cur: # 第 1 遍: 只建新 node old2new[cur] = Node(cur.val) cur = cur.next cur = head while cur: # 第 2 遍: 连 next 和 random old2new[cur].next = old2new[cur.next] old2new[cur].random = old2new[cur.random] cur = cur.next return old2new[head]

记:复制带额外指针的结构: dict old → new, 第一遍建 node, 第二遍连指针。

8. Palindrome Linked List

题目在问什么

判断 linked list 的值正着读和反着读是不是一样。最好 O(n) 时间、O(1) 额外空间。

看例子

Brute force

把值读进数组, 判断数组是不是回文。O(n) 空间。

Intuition: 把前面学过的两招组合起来

回文要"从两头往中间比", 但 singly linked list 不能从后往前走。办法是把后半段反转, 这样就可以从两头同时往中间走了。

  1. 用第 3 题的快慢指针找到中点。
  2. 用第 1 题把后半段反转。
  3. 一个指针从 head、一个从反转后的后半段开头, 一起往中间走, 逐个比较。

算法

  1. 快慢指针: 结束时 slow 在中间。
  2. 从 slow 开始反转, 得到后半段的新头 prev。
  3. left = head, right = prev, 当 right 不是 None: 值不同就返回 False, 否则都往后走。
  4. 返回 True。

手动走一遍

复杂度

Time O(n), Space O(1)。面试时可以提一句: 这样会修改原 list, 如果需要, 最后再把后半段反转回去。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def isPalindrome(head): slow = fast = head # 1. 快慢指针找中点 while fast and fast.next: slow, fast = slow.next, fast.next.next prev = None # 2. 反转后半段 (就是 reverseList) while slow: slow.next, prev, slow = prev, slow, slow.next left, right = head, prev # 3. 两头往中间比 while right: if left.val != right.val: return False left, right = left.next, right.next return True

记:linked list 上要"从后往前": 反转后半段。很多难题就是 快慢指针 + 反转 + 合并 的组合 (比如 Reorder List)。
