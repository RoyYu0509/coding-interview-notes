12 · Graph: BFS / DFS / Topological Sort / Union-Find / Dijkstra

这篇讲什么

graph (图) 由 node (点) 和 edge (边) 组成。tree 是一种特殊的 graph (没有环)。面试里的 graph 很多时候是藏起来的:

  • grid: 每个格子是一个 node, 上下左右相邻的格子之间有边。
  • 隐式图: 比如单词, 改一个字母能变成的另一个单词就是邻居。
  • 依赖关系: 课程 a 依赖课程 b, 就是一条 b → a 的边。

所有 graph 题的基础都是遍历: 从某个点出发, 把能到达的点都走一遍。和 tree 最大的不同是: graph 里可能有环, 或者多条路走到同一个点。所以必须记录 visited, 保证每个点只处理一次。这样总共是 O(V + E) (点数 + 边数)。

遍历有两种方式, 用途不同:

  • DFS (depth-first, 深度优先): 一条路走到底再回头, 用 recursion 写。适合"把连在一起的都找出来"。
  • BFS (breadth-first, 广度优先): 一层一层往外扩, 用 queue 写。BFS 的层数就是最短距离 (每条边长度都是 1 时)。适合"最少几步"。
BFS / DFS / grid 邻居 的模板代码
from collections import deque# ---- BFS: 从 start 一层一层往外扩 (无权图最短路) ----def bfs(start, neighbors): # 入队时就标记 (不是出队时), 否则同一点会重复入队 visited = {start} q = deque([start]) while q: u = q.popleft() # neighbors(u): 邻接表 / grid 四个方向 / 改一个字母 for v in neighbors(u): if v not in visited: visited.add(v) # 每个点只会入队一次 → 总工作量 O(V + E) q.append(v)# ---- DFS: 沿一条路走到底, 走不动再回头 ----def dfs(u, neighbors, visited): visited.add(u) # 进来就标记 for v in neighbors(u): if v not in visited: dfs(v, neighbors, visited)# ---- grid 是隐式 graph: 格子 = 点, 上下左右 = 边, 不用建邻接表 ----DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))def grid_neighbors(r, c, m, n): for dr, dc in DIRS: nr, nc = r + dr, c + dc if 0 <= nr < m and 0 <= nc < n: # 出界 = 没有这条边 yield nr, nc

1. Number of Islands

题目在问什么

一个 grid, '1' 是陆地, '0' 是水。上下左右相连的陆地属于同一个 island (斜着挨着不算)。问一共有几个 island。

看例子

Brute force

这题本身就没有比 O(m·n) 更好的做法, 每个格子至少要看一次。难点不是优化, 而是"怎么知道哪些 1 是连在一起的"。

Intuition: 找到一块陆地, 就把整个 island 淹掉

从左上到右下扫每个格子。遇到一个 '1', 说明发现了一个新 island, count 加 1。

然后从这个格子出发做 DFS: 往上下左右四个方向走, 只要是 '1' 就继续走, 把这个 island 上所有的格子都走一遍, 并且把走过的格子改成 '0' (淹掉)。

淹掉有两个作用: 一是当作 visited, 防止走回头路; 二是之后继续扫描时, 这个 island 的其他格子已经是 0 了, 不会被重复计数。

算法

  1. 遍历每个格子 (r, c)。如果是 '1': count += 1, 调用 dfs(r, c)。
  2. dfs(r, c): 越界、或者不是 '1', 直接返回。否则把它改成 '0', 再对上下左右四个邻居调用 dfs。

手动走一遍

复杂度

Time O(m·n): 每个格子最多被淹一次。Space O(m·n): 最坏 recursion 深度 (全是陆地)。

变体 Max Area of Island: dfs 返回这一块的格子数 (1 + 四个方向的和), 取最大值。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
# grid[r][c] 是 "1" (陆) 或 "0" (水)def numIslands(grid): m, n = len(grid), len(grid[0]) def dfs(r, c): if r < 0 or r >= m or c < 0 or c >= n or grid[r][c] != "1": # 出界 / 水 / 已经 sink 过, 都不用再走 return # 进来先 sink: 这一行就是 visited 标记 grid[r][c] = "0" for dr, dc in DIRS: # 4 个方向 = 4 条边 dfs(r + dr, c + dc) count = 0 for r in range(m): for c in range(n): # 遇到还没处理的陆地 = 发现一个新 island if grid[r][c] == "1": # 每个 island 只会在它的第一个格子触发一次 count += 1 # 把整块 island sink 掉, 之后扫描不会再碰到它 dfs(r, c) return count
def maxAreaOfIsland(grid): m, n = len(grid), len(grid[0]) def dfs(r, c): # 返回: 从 (r, c) 能走到的陆地格数 if r < 0 or r >= m or c < 0 or c >= n or grid[r][c] != 1: return 0 grid[r][c] = 0 # 改动: 返回面积 return 1 + sum(dfs(r + dr, c + dc) for dr, dc in DIRS) return max(dfs(r, c) for r in range(m) for c in range(n))

记:数连通块: 扫一遍, 遇到没访问过的就 count += 1, 再 DFS 把整块标记掉。grid 上可以直接改格子当 visited。

2. Rotting Oranges

题目在问什么

grid 里 0 是空格, 1 是新鲜橘子, 2 是烂橘子。每过一分钟, 每个烂橘子会让它上下左右的新鲜橘子也烂掉。问: 最少几分钟后所有橘子都烂了? 如果有橘子永远烂不到, 返回 -1。

看例子

Brute force

模拟: 每一分钟扫一遍整个 grid, 把所有烂橘子旁边的新鲜橘子标成烂的, 直到没有变化。每分钟 O(m·n), 最多 m·n 分钟, O((m·n)²)。

浪费: 每一分钟都重新扫整个 grid, 但真正会变化的只有"刚烂掉的那一批"的邻居。

Intuition: BFS 的一层就是一分钟

BFS 是一层一层往外扩的。第 0 层是起点, 第 1 层是离起点 1 步的点, 第 2 层是 2 步的……这和"每分钟往外烂一格"完全一样。

特别的是, 这题有好几个起点 (一开始就烂的橘子都是起点), 它们同时开始扩散。做法很简单: 一开始把所有烂橘子一起放进 queue, 当作第 0 层。这叫 multi-source BFS。

然后每一轮处理一整层 (和 11 里 level order 一样, 先记下 len(q)), 每处理完一层, 分钟数加 1。

同时数一下新鲜橘子的个数 fresh。每烂一个就减 1。最后 fresh 还大于 0, 说明有烂不到的, 返回 -1。

算法

  1. 扫一遍 grid: 所有 2 放进 queue, 数出 fresh。
  2. 当 queue 不空且 fresh > 0: 处理一整层。对每个烂橘子, 看四个邻居, 是 1 就改成 2、fresh 减 1、放进 queue。这一层处理完, minutes += 1。
  3. 返回 minutes if fresh == 0 else -1。

手动走一遍

复杂度

Time O(m·n), Space O(m·n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def orangesRotting(grid): # 0 空, 1 新鲜, 2 烂 m, n = len(grid), len(grid[0]) q, fresh = deque(), 0 for r in range(m): for c in range(n): if grid[r][c] == 2: # 所有初始烂橘子一起入队 = 第 0 层 (multi-source) q.append((r, c)) elif grid[r][c] == 1: fresh += 1 minutes = 0 while q and fresh: # 只处理"当前这一层", 新入队的留给下一分钟 for _ in range(len(q)): r, c = q.popleft() for dr, dc in DIRS: nr, nc = r + dr, c + dc if 0 <= nr < m and 0 <= nc < n and grid[nr][nc] == 1: grid[nr][nc] = 2 # 变烂 = 标记 visited fresh -= 1 q.append((nr, nc)) minutes += 1 # 一层 = 一分钟 # 还有新鲜的 = 被墙/空格隔开, 永远烂不到 return -1 if fresh else minutes

记:从多个地方同时扩散、问几步 / 几分钟: multi-source BFS, 所有起点一起放进 queue 当第 0 层。

3. Word Ladder

题目在问什么

从 beginWord 变到 endWord, 每一步只能改一个字母, 而且每一步变出来的词必须在 wordList 里。求最短的变换序列有几个词 (包括头和尾)。变不到返回 0。

看例子

Brute force

DFS 枚举所有变换路径, 取最短的。路径数量是指数级的。

Intuition: 这是一个图, 求最短路就用 BFS

把每个单词看成一个 node。两个单词只差一个字母, 它们之间就有一条边。问题就变成: 在这个图上, 从 beginWord 到 endWord 的最短路径。

每条边的长度都是 1 (改一个字母算一步), 所以 BFS 第一次到达 endWord 时的层数, 就是答案。

这个图不用提前建出来。要找一个词的邻居, 就把它的每个位置换成 a 到 z, 看换出来的词在不在 wordList 里 (用 set, O(1))。

visited 的处理: 一个词一旦被放进 queue, 就从 set 里删掉, 这样它不会再被访问。

算法

  1. words = set(wordList)。queue 放进 (beginWord, 1)。
  2. 每次取出 (word, level)。是 endWord 就返回 level。
  3. 对 word 的每个位置、每个字母 a–z: 换出来的 new 在 words 里, 就从 words 删掉, 放进 queue (level + 1)。
  4. queue 空了还没找到, 返回 0。

手动走一遍

复杂度

Time O(N·L·26), N 是单词数, L 是单词长度 (每个词有 L × 26 个候选, 每个候选拼字符串还要 O(L))。Space O(N·L)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def ladderLength(beginWord, endWord, wordList): words = set(wordList) # 同时充当 "没访问过的点集合" if endWord not in words: return 0 q, level = deque([beginWord]), 1 # level = 路径上的单词个数 while q: # 一层一层: 同层的单词离 beginWord 一样远 for _ in range(len(q)): w = q.popleft() if w == endWord: return level # BFS 第一次碰到 endWord 就是最短 # 邻居 = 改一个字母后还在词典里的词 for i in range(len(w)): for ch in "abcdefghijklmnopqrstuvwxyz": nw = w[:i] + ch + w[i + 1:] if nw in words: # remove = 标记 visited, 之后不会再入队 words.remove(nw) q.append(nw) level += 1 return 0

记:"最少几步" + 每一步代价相同: BFS。图可以是隐式的, 需要时再生成邻居。

4. Course Schedule

题目在问什么

一共 n 门课, 编号 0 到 n-1。prerequisites[i] = [a, b] 表示: 上 a 之前必须先上完 b。问能不能把所有课都上完。

看例子

把每门课看成一个 node, "b 是 a 的前置课"画成一条 b → a 的有向边。上不完的唯一原因是有环: 几门课互相等对方。

Brute force

从每个点出发做 DFS, 看能不能走回自己。每个点 O(V + E), 共 O(V·(V + E))。

Intuition: 先上没有前置课的, 上完就把它从图里去掉

想想现实里你会怎么排课: 先上那些没有前置课的。上完一门, 依赖它的那些课就少了一个前置要求。如果某门课的前置要求全部满足了, 它就可以上了。一直这样, 直到没有可以上的课。

如果最后所有课都上了, 就没有环; 如果还有课剩下, 剩下的那些一定是在互相等, 有环。

用一个数组 indegree[v] 记录 v 还有几门前置课没上。indegree 为 0 的课放进 queue。每上完一门 u, 把它所有的后继 v 的 indegree 减 1, 减到 0 就放进 queue。这个方法叫 Kahn 算法, 得到的顺序叫拓扑排序 (topological sort)。

算法

  1. 建图: 每个 [a, b], 加边 b → a, indegree[a] += 1。
  2. 所有 indegree 为 0 的课放进 queue。
  3. 每次取出 u, 计数 taken += 1。对 u 的每个后继 v: indegree[v] -= 1, 变成 0 就放进 queue。
  4. 返回 taken == n。

手动走一遍

复杂度

Time O(V + E), Space O(V + E)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def canFinish(numCourses, prerequisites): # [course, pre]: 先 pre 后 course graph = [[] for _ in range(numCourses)] # indegree[v] = v 还有几门前置课没上完 indegree = [0] * numCourses for course, pre in prerequisites: graph[pre].append(course) # 边 pre → course indegree[course] += 1 # 没有前置的先上 q = deque(i for i in range(numCourses) if indegree[i] == 0) done = 0 while q: u = q.popleft() done += 1 # u 上完了 for v in graph[u]: indegree[v] -= 1 # v 少了一门前置 if indegree[v] == 0: # 前置全上完 → v 可以上了 q.append(v) # 有环 → 环上的点 indegree 永远 > 0 → 不够 n return done == numCourses

记:有依赖关系 / 先后顺序 / 判断有向图有没有环: 拓扑排序 (Kahn)。indegree 为 0 的先处理。

5. Course Schedule II

题目在问什么

和第 4 题一样, 但要返回一个可行的上课顺序。上不完就返回空数组。

看例子

Intuition: 记下取出的顺序

第 4 题里, 课从 queue 里被取出的顺序, 就是一个合法的上课顺序: 每门课被取出时, 它的前置课都已经被取出过了。所以只要把 taken 计数换成一个 list, 记下顺序。

最后 order 的长度不等于 n, 说明有环, 返回 []。

算法

  1. 和第 4 题一样, 每取出一个 u, 加到 order 里。
  2. 返回 order if len(order) == n else []。

手动走一遍

复杂度

Time O(V + E), Space O(V + E)。

Alien Dictionary 是同一个模板: 从相邻两个单词的第一个不同字母得到一条边 (哪个字母在前), 再做拓扑排序。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def findOrder(numCourses, prerequisites): graph = [[] for _ in range(numCourses)] indegree = [0] * numCourses for course, pre in prerequisites: graph[pre].append(course) indegree[course] += 1 q = deque(i for i in range(numCourses) if indegree[i] == 0) # 改动 1: done 计数 → 记录 pop 的顺序 order = [] while q: u = q.popleft() order.append(u) for v in graph[u]: indegree[v] -= 1 if indegree[v] == 0: q.append(v) # 改动 2: 有环就没有合法顺序 return order if len(order) == numCourses else []

记:要输出顺序: Kahn 算法里取出的顺序就是拓扑序。长度不够 n 就是有环。

6. Clone Graph

题目在问什么

给一个连通的无向图里的一个 node, 返回整个图的深拷贝 (deep copy): 每个 node 都要新建, 新图的连接关系和原图完全一样, 但新图里不能有任何一个原来的 node 对象。

看例子

Brute force

先遍历一遍, 为每个旧 node 新建一个副本; 再遍历一遍, 把边连上。需要两遍, 而且第二遍要能从旧 node 找到对应的新 node, 所以还是要一个 dict。

Intuition: 用 dict 记住"这个 node 已经复制过了"

用一个 dict old2new: key 是旧 node, value 是它的副本。它同时有两个作用: 从旧 node 找到副本, 以及当作 visited。

DFS 复制一个 node: 如果它已经在 old2new 里, 直接返回副本 (这一步切断了环, 否则会无限递归)。否则新建副本, 先登记进 old2new, 再递归复制它的每个邻居, 把邻居的副本加进副本的邻居列表。

"先登记再递归"的顺序很重要: 图里有环, 递归可能会绕回来找自己。如果还没登记, 就会再建一个副本, 无限循环。

算法

  1. old2new = {}。dfs(node): 在 old2new 里就返回 old2new[node]。
  2. copy = Node(node.val), old2new[node] = copy。
  3. 对每个邻居 nb: copy.neighbors.append(dfs(nb))。返回 copy。

手动走一遍

复杂度

Time O(V + E), Space O(V)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
# Node 有 .val 和 .neighbors (list[Node])def cloneGraph(node): if not node: return None # Hash Table: 原节点 → 副本 (兼 visited) old2new = {} def dfs(old): # 已经复制过 → 直接返回副本, 不再递归 if old in old2new: return old2new[old] copy = Node(old.val) # 必须在递归 neighbor 之前登记, 否则环会无限递归 old2new[old] = copy for nb in old.neighbors: copy.neighbors.append(dfs(nb)) # 副本的 neighbor 也必须是副本 return copy return dfs(node)

记:复制带环的结构 (图、带 random 指针的 list): dict 记 old → new, 先登记再递归。

7. Number of Provinces (Union-Find)

题目在问什么

n 个城市, isConnected[i][j] = 1 表示城市 i 和 j 直接相连。直接或间接相连的城市属于同一个 province。问一共有几个 province。

看例子

Brute force

这题用第 1 题的 DFS 数连通块就能做, O(n²)。这里借它介绍另一个工具: Union-Find。它在"边一条一条给出来, 随时问两个点是否相连"的场景下特别好用。

Intuition: 每个集合选一个"代表"

Union-Find (也叫 DSU) 维护一堆不相交的集合。每个集合用一棵树表示, 树根就是这个集合的代表。parent[x] 是 x 的父节点, 根的 parent 是自己。

  • find(x): 顺着 parent 一直往上走, 找到根。两个点的根相同, 就在同一个集合。
  • union(a, b): 找到两个根, 如果不同, 把一个根接到另一个根下面, 两个集合就合并了。

不优化的话, 树可能变成一条长链, find 是 O(n)。两个优化:

  • union by size: 合并时把小的树接到大的树下面, 树不会变得太高。
  • path compression: find 的时候, 把一路经过的点直接接到根上, 下次就一步到位。

两个优化一起用, 每次操作几乎是 O(1)。

这道题: 一开始每个城市自己一个集合, count = n。每条相连的边做一次 union, 真的合并了 (两个根不同) 就 count 减 1。

算法

  1. parent = list(range(n)), size = [1] * n, count = n。
  2. 对每个 isConnected[i][j] == 1 (i < j): union(i, j), 合并成功就 count -= 1。
  3. 返回 count。

手动走一遍

复杂度

Time O(n² · α(n)), α 是一个增长极慢的函数, 可以当成常数。Space O(n)。

变体 Accounts Merge: 同一个邮箱出现在两个账户里, 就 union 这两个账户, 最后按根分组输出。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
class DSU: def __init__(self, n): # parent[x] == x 表示 x 是所在集合的 root self.parent = list(range(n)) # size[root] = 集合大小 (只对 root 有意义) self.size = [1] * n def find(self, x): while self.parent[x] != x: # path compression: 跳到爷爷 self.parent[x] = self.parent[self.parent[x]] x = self.parent[x] return x def union(self, a, b): ra, rb = self.find(a), self.find(b) if ra == rb: # 已经在同一集合 → 这条边没有合并任何东西 return False # union by size: 小树挂到大树的 root 下 if self.size[ra] < self.size[rb]: ra, rb = rb, ra self.parent[rb] = ra self.size[ra] += self.size[rb] return True
# isConnected[i][j] == 1: i 和 j 直接相连def findCircleNum(isConnected): n = len(isConnected) dsu = DSU(n) count = n # 开始: 每个人自己一个 province for i in range(n): for j in range(i + 1, n): if isConnected[i][j] and dsu.union(i, j): count -= 1 # 每成功合并一次, 集合数少 1 return count
# accounts[i] = [name, email1, email2, ...]def accountsMerge(accounts): dsu = DSU(len(accounts)) # email → 第一次见到它的 account 下标 owner = {} for i, acc in enumerate(accounts): for email in acc[1:]: if email in owner: dsu.union(i, owner[email]) # 共用 email → 同一个人 else: owner[email] = i groups = defaultdict(set) for email, i in owner.items(): groups[dsu.find(i)].add(email) # 按 root 归并 email return [[accounts[r][0]] + sorted(es) for r, es in groups.items()]

记:动态地合并集合、问两个元素是否在同一组: Union-Find, 加上 union by size 和 path compression。

8. Network Delay Time (Dijkstra)

题目在问什么

n 个节点, 有向边 (u, v, w) 表示信号从 u 到 v 要 w 的时间。从节点 k 发出信号, 多久之后所有节点都收到? 有节点收不到就返回 -1。

换句话说: 求 k 到每个节点的最短路径, 再取其中最大的。

看例子

Brute force

BFS 不能直接用了: BFS 的层数是"经过几条边", 但这里每条边的长度不一样, 边少的路径不一定短。

最直接的做法是反复"放松": 对所有边, 如果 dist[u] + w < dist[v] 就更新 dist[v], 重复 V - 1 轮 (Bellman-Ford)。O(V·E)。

Intuition: 每次确定"目前离起点最近"的那个点

Dijkstra 的想法: 维护一个"已确定"区域, 里面每个点的最短距离都已经算好了。每一步, 在所有还没确定的点里, 选当前距离最小的那个, 它的距离就确定了。

为什么它的距离一定是最终的? 因为所有边的长度都 ≥ 0。任何其他路径要到达它, 都得先走出已确定区域, 而走出去的那一步就已经 ≥ 它当前的距离了, 后面只会更长。

"选当前距离最小的" 正是 heap 擅长的 (见 09)。heap 里放 (距离, 节点)。确定一个点 u 之后, 用它更新它的邻居: dist[u] + w < dist[v] 就把新的 (dist[v], v) 放进 heap。

同一个点可能被放进 heap 好几次 (距离被更新过)。取出来时如果它已经确定过了, 就跳过这个过期的记录。

算法

  1. 建邻接表。dist = {}, heap = [(0, k)]。
  2. 当 heap 不空: 取出 (d, u)。u 已经在 dist 里就跳过。否则 dist[u] = d。
  3. 对 u 的每条边 (v, w): v 不在 dist 里就 push (d + w, v)。
  4. dist 的个数 < n 返回 -1, 否则返回 max(dist.values())。

手动走一遍

复杂度

Time O(E log V), Space O(V + E)。

变体 Cheapest Flights Within K Stops: 限制最多经过 k 站, Dijkstra 不好处理, 用 Bellman-Ford 只跑 k + 1 轮。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
# times[i] = [u, v, w]: u → v 耗时 wdef networkDelayTime(times, n, k): graph = defaultdict(list) for u, v, w in times: graph[u].append((v, w)) INF = float("inf") # dist[v] = 目前已知从 k 到 v 的最短时间 dist = [INF] * (n + 1) dist[k] = 0 # min-heap, 按 (dist, node) 排: 先拿"当前最近"的 heap = [(0, k)] while heap: d, u = heapq.heappop(heap) # 这是个过期记录: u 之后找到了更短的路 if d > dist[u]: continue for v, w in graph[u]: # relax: 经过 u 到 v 会不会更短? nd = d + w if nd < dist[v]: dist[v] = nd # 不删旧记录, 只加新的 (lazy deletion) heapq.heappush(heap, (nd, v)) ans = max(dist[1:]) return -1 if ans == INF else ans # 有点到不了 → -1
# 最多 k 次中转 = 最多 k+1 条边def findCheapestPrice(n, flights, src, dst, k): dist = [float("inf")] * n dist[src] = 0 # Bellman-Ford: 一轮 = 多允许走 1 条边 for _ in range(k + 1): # 用上一轮的 dist 算, 防止一轮里连走多条边 nxt = dist[:] for u, v, w in flights: if dist[u] + w < nxt[v]: nxt[v] = dist[u] + w dist = nxt return -1 if dist[dst] == float("inf") else dist[dst]

记:边有长度 (非负) 的最短路: Dijkstra, heap 存 (距离, 节点), 取出时已确定的就跳过。
