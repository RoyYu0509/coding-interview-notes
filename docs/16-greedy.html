16 · Greedy

这篇讲什么

Greedy (贪心) 的意思是: 每一步都做当前看起来最好的选择, 不回头, 不考虑以后。

它很快 (通常扫一遍 O(n), 或者排序后扫一遍 O(n log n)), 但不一定对。greedy 题的难点从来不是代码, 而是说明为什么"每步选最好的"不会错过全局最优。

先看一个反例, 理解什么时候 greedy 会错:

证明 greedy 正确的常用方法叫 exchange argument (交换论证): 假设有一个最优解, 它在某一步没有按 greedy 选; 把那一步换成 greedy 的选择, 证明结果不会变差。那么 greedy 的结果也是最优的。

面试里不需要写严格的证明, 但要能用一两句话说出"为什么这样选不会吃亏"。说不出来, 或者能找到反例, 就换成 DP (14)。

代码: Coin Change 的 DP 解法, 以及 greedy 的一般形式
def coin_change_dp(coins, amount): INF = float("inf") dp = [0] + [INF] * amount # dp[a] = 凑出 a 的最少枚数 for a in range(1, amount + 1): for c in coins: # 试每一种最后一枚, 而不是只赌最大的 if c <= a: dp[a] = min(dp[a], dp[a - c] + 1) return dp[amount] if dp[amount] < INF else -1
def greedy(items): # 1) 有些题需要先排序 (Largest Number / interval 按 end) items.sort(key=...) state = 初始值 # 2) 一个(或两个)汇总量: max_reach / tank / end ... for x in items: # 3) 一遍扫描, 每步只看 x 和 state, 不回头 做局部最优的选择, 更新 state return 答案

1. Jump Game

题目在问什么

nums[i] 表示在位置 i 时最多能往前跳几格 (可以跳 1 到 nums[i] 格中的任意一个)。从 index 0 出发, 能不能到达最后一格?

看例子

Brute force

recursion: 从位置 i 出发, 试每一种跳法。指数级。加 memo 变成 DP: can[i] = 从 i 能不能到终点, 每个 i 要看 nums[i] 个后继, O(n²)。

Intuition: 只记"最远能到哪"

关键观察: 如果能到达位置 x, 那 0 到 x 之间的每个位置都能到达 (跳的时候可以少跳几格)。所以"能到达的位置"永远是一个从 0 开始的连续区间 [0, max_reach]。

不需要知道具体怎么跳的, 只要维护 max_reach 这一个数: 从左往右扫, 每到一个能到达的位置 i, 就更新 max_reach = max(max_reach, i + nums[i])。

如果扫到的 i 已经超过了 max_reach, 说明 i 根本到不了, 后面也到不了, 返回 False。

算法

  1. max_reach = 0。
  2. i 从 0 到 n-1: 如果 i > max_reach, 返回 False。否则 max_reach = max(max_reach, i + nums[i])。
  3. 返回 True。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def can_jump(nums): max_reach = 0 # invariant: 0..max_reach 全部可达 for i, step in enumerate(nums): if i > max_reach: # 连 i 都够不到 -> 后面全都够不到 return False max_reach = max(max_reach, i + step) # 从 i 起跳最远到 i + step return True

记:能到达的位置是一个连续区间时, 只维护它的右端点 max_reach。

2. Jump Game II

题目在问什么

和第 1 题一样的规则, 这次保证一定能到最后一格。问最少跳几次。

看例子

Brute force

DP: dp[i] = 到达 i 最少几步, 每个 i 往前看所有能跳到它的位置, O(n²)。或者把它当图, 用 BFS (12) 求最少步数。

Intuition: 按"跳几次能到"分层, 和 BFS 一样

想象 BFS: 第 0 层是 index 0; 第 1 层是跳 1 次能到的所有位置; 第 2 层是跳 2 次能到的……由第 1 题的观察, 每一层都是一段连续的区间。

所以不需要真的用 queue, 只要两个数:

  • cur_end: 当前这一层的右端点。
  • farthest: 扫描当前这一层时, 能跳到的最远位置, 也就是下一层的右端点。

从左往右扫, 每个位置都更新 farthest。扫到 i == cur_end 时, 当前这一层结束了, 必须再跳一次: jumps += 1, cur_end = farthest。

算法

  1. jumps = cur_end = farthest = 0。
  2. i 从 0 到 n-2 (到了最后一格就不用再跳): farthest = max(farthest, i + nums[i])。如果 i == cur_end: jumps += 1, cur_end = farthest。
  3. 返回 jumps。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def jump(nums): jumps = 0 cur_end = 0 # 当前层 (跳 jumps 步能到的区间) 的右边界 farthest = 0 # 扫完当前层后, 下一层的右边界 for i in range(len(nums) - 1): # 最后一格不用再跳, 所以到 n-2 farthest = max(farthest, i + nums[i]) if i == cur_end: # 当前层扫完 -> 必须再跳一次 jumps += 1 cur_end = farthest # 下一层边界 = 这一层能到的最远处 return jumps # 题目保证一定能到终点

记:最少几步 + 每一层是连续区间: 用 cur_end 和 farthest 模拟 BFS 分层, 不需要 queue。

3. Gas Station

题目在问什么

环形公路上有 n 个加油站。在站 i 可以加 gas[i] 升油, 从站 i 开到站 i+1 要花 cost[i] 升。油箱一开始是空的, 容量无限。从哪一站出发能绕一整圈回来? 有解的话答案唯一, 没有就返回 -1。

看例子

每一站的净收益是 gas[i] - cost[i]。从某站出发, 一路累加净收益, 中途任何时候都不能变成负数。

Brute force

每一站都试一次当起点, 模拟绕一圈。O(n²)。

Intuition: 在哪里失败, 就从下一站重新开始

两个观察:

  1. 有没有解: 如果所有站的净收益加起来 total < 0, 油总量不够, 从哪里出发都不行。反过来, total ≥ 0 就一定有解。
  2. 从哪里出发: 假设从 start 出发, 开到站 i 时油箱变负了。那么 start 到 i 之间的任何一站当起点, 也都到不了 i+1。

为什么第 2 点成立? 从 start 出发, 到达中间某站 k 时油箱是 ≥ 0 的 (还没失败)。如果直接从 k 出发, 油箱是 0, 只会比"从 start 出发到达 k"更少。连多带了油的都过不去, 空着油箱的更过不去。

所以一失败, 直接把起点跳到 i + 1, 油箱清零。扫一遍就够了。

算法

  1. total = tank = start = 0。
  2. i 从 0 到 n-1: diff = gas[i] - cost[i], total 和 tank 都加上 diff。如果 tank < 0: start = i + 1, tank = 0。
  3. 返回 start if total >= 0 else -1。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def can_complete_circuit(gas, cost): total = 0 # 全局 sum(gas - cost), 决定有没有解 tank = 0 # 从 start 出发到现在的油量 start = 0 for i in range(len(gas)): net = gas[i] - cost[i] total += net tank += net if tank < 0: # start..i 任何起点都到不了 i+1 start = i + 1 # 下一个候选: 失败点的下一站 tank = 0 return start if total >= 0 else -1 # total >= 0 保证最后留下的 start 可行

记:累计量变负就重置起点: 失败点之前的任何一个起点都不会更好。

4. Best Time to Buy and Sell Stock II

题目在问什么

prices[i] 是第 i 天的股价。可以交易任意多次, 但手里最多只能有一股 (买之前必须先卖掉)。最大总利润是多少?

看例子

Brute force

枚举所有买卖方案, 指数级。或者用 14 里的 hold / cash 状态机 DP, O(n)。

Intuition: 每一段上涨都吃掉

把价格曲线画出来, 它是一段一段的上涨和下跌。

任何一次"第 i 天买、第 j 天卖"的利润 prices[j] - prices[i], 都等于中间每一天的涨跌加起来。其中下跌的那几天只会减少利润。

既然可以交易任意多次, 就只在上涨的那几天持有: 每一个 prices[i] > prices[i-1] 的地方, 都把这个差价赚到。这等价于在每段上涨的底部买、顶部卖。

算法

  1. profit = 0。
  2. i 从 1 到 n-1: profit += max(0, prices[i] - prices[i-1])。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def max_profit(prices): profit = 0 for i in range(1, len(prices)): diff = prices[i] - prices[i - 1] if diff > 0: # 每一段上涨都吃掉; 下跌段 = 空仓 profit += diff return profit

记:可以交易任意多次: 所有正的相邻差价加起来。

5. Candy

题目在问什么

一排孩子, ratings[i] 是第 i 个孩子的评分。分糖果: 每个孩子至少 1 颗; 评分比相邻孩子高的, 必须比那个孩子拿得多。最少要准备几颗糖?

看例子

Brute force

先每人 1 颗, 然后反复扫, 发现不满足条件的就加 1, 直到所有条件都满足。最坏 O(n²)。

Intuition: 左右两个约束, 分开处理

每个孩子有两个约束: 和左边比, 和右边比。同时考虑两边很乱, 那就分开:

  1. 从左往右扫一遍, 只管左边的约束: 比左边评分高, 就 left[i] = left[i-1] + 1, 否则 1。
  2. 从右往左扫一遍, 只管右边的约束: 比右边评分高, 就 right[i] = right[i+1] + 1, 否则 1。
  3. 每个孩子要同时满足两个约束, 取 max(left[i], right[i])。

为什么取 max 就够了, 而且是最少的? 每个值都是满足那一侧约束的最小值, 取 max 刚好两边都满足, 没有多给。

算法

  1. left 从左往右填, right 从右往左填。
  2. 返回 sum(max(left[i], right[i]))。

手动走一遍

复杂度

Time O(n), Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def candy(ratings): n = len(ratings) # left[i]: 只管左约束的最少糖 left = [1] * n for i in range(1, n): if ratings[i] > ratings[i - 1]: left[i] = left[i - 1] + 1 # right[i]: 只管右约束的最少糖 right = [1] * n for i in range(n - 2, -1, -1): if ratings[i] > ratings[i + 1]: right[i] = right[i + 1] + 1 return sum(max(l, r) for l, r in zip(left, right)) # 两条约束同时满足

记:每个元素同时受左右两边约束: 从左扫一遍、从右扫一遍, 再合并 (取 max)。

6. Largest Number

题目在问什么

给一组非负整数, 把它们重新排列后拼接成一个字符串, 让这个数最大。返回字符串。

看例子

Brute force

试所有排列, 拼起来比大小。O(n! · n)。

Intuition: 两个数谁放前面, 拼一下比一比

直觉是"大的放前面", 但按数值排不对 (10 和 2, 应该是 2 在前); 按字符串字典序排也不对 (3 和 30, 字典序是 30 > 3, 但 "330" > "303", 应该 3 在前)。

正确的比较方法: 对两个数 a 和 b, 直接比较 a + b 和 b + a (字符串拼接)。a + b 更大, a 就放前面。

为什么这样排出来的就是最优? 用交换论证: 如果最优解里有相邻的两个 x, y 满足 y + x > x + y, 交换它们, 拼出来的数会更大, 矛盾。所以最优解里每一对相邻的都满足这个顺序, 也就是按这个规则排好序的结果。

Python 里用 functools.cmp_to_key 把比较函数变成排序的 key。最后注意全是 0 的情况, 要返回 "0" 而不是 "000"。

算法

  1. 转成字符串。
  2. 按比较规则排序: a + b > b + a 的 a 排前面。
  3. 拼接; 如果第一个是 "0", 返回 "0"。

手动走一遍

复杂度

Time O(n log n · L), L 是数字的位数。Space O(n · L)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
from functools import cmp_to_keydef largest_number(nums): strs = [str(x) for x in nums] # a 排在 b 前面 <=> a+b > b+a (字符串拼接, 不是字典序) strs.sort(key=cmp_to_key(lambda a, b: -1 if a + b > b + a else 1)) res = "".join(strs) return "0" if res[0] == "0" else res # [0, 0] 这类全零要返回 "0"

记:"排列成最优": 找出两个元素之间的比较规则 (常用 a+b vs b+a), 自定义排序。

7. Partition Labels

题目在问什么

把字符串 s 切成尽量多的段, 要求每个字母只出现在其中一段里。返回每一段的长度。

看例子

Brute force

试所有切法, 检查每个字母是否只在一段里。指数级。

Intuition: 一段至少要延伸到它里面每个字母最后出现的位置

第一段从 index 0 开始。第一个字母是 a, 那 a 所有出现的地方都必须在这一段里, 所以这一段至少要到 a 最后一次出现的位置。

但在这个范围里, 又出现了别的字母 (比如 b), b 最后出现的位置可能更远, 那这一段就要延伸到那里。一直这样延伸, 直到扫到的位置 i 正好等于当前要求的右边界 end, 说明这一段里所有字母都不会再出现了, 在这里切一刀, 段数最多。

所以先扫一遍, 记下每个字母最后出现的位置 last[c]。

算法

  1. last = {c: i for i, c in enumerate(s)}。
  2. start = end = 0。i 从 0 到 n-1: end = max(end, last[s[i]])。如果 i == end: 记录长度 end - start + 1, start = i + 1。

手动走一遍

复杂度

Time O(n), Space O(26)。这和 10 里的 Merge Intervals 是一回事: 每个字母对应一个区间 [第一次出现, 最后一次出现], 合并重叠的区间。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def partition_labels(s): last = {c: i for i, c in enumerate(s)} # 每个字母最后一次出现的位置 res = [] start = end = 0 for i, c in enumerate(s): end = max(end, last[c]) # 这段至少要延伸到 c 的最后一次出现 # 段内所有字母都已最后一次出现 -> 可以切 if i == end: res.append(i - start + 1) start = i + 1 return res

记:每个元素必须在同一段: 记下最后出现的位置, 边扫边延伸右边界, 追上了就切。

8. 识别信号: 看到什么, 就想到 greedy

题目特征做法complexity
能不能到达 / 能到达的范围是连续的只维护 max_reachO(n²) → O(n)
最少几步, 每一层是连续区间cur_end + farthest 模拟 BFS 分层O(n²) → O(n)
环形, 累计量不能为负变负就把起点重置到下一个; total 判断有没有解O(n²) → O(n)
可以交易任意多次所有正的差价加起来O(n)
每个元素受左右两边约束左扫一遍、右扫一遍, 再合并O(n²) → O(n)
"排列成最大 / 最小"找两两比较的规则, 自定义排序O(n!) → O(n log n)
切成尽量多的段, 某种元素不能跨段记 last, 边扫边延伸右边界O(n)
区间: 最多保留几个不重叠按 end 排序 → 10O(n log n)
每一步选"当前最优", 候选会变化greedy + heap → 09O(n log n)

用 greedy 之前, 先试着找反例。找不到反例, 并且能说出一句"为什么这样选不会吃亏", 才用。否则用 DP。
