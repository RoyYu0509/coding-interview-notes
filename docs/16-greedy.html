16 · Greedy

主线: greedy = 每一步只做当前看起来最好的选择, 永不回头; 前提是你能证明'最优解里一定可以含这个选择' (exchange argument)。题型上基本只有三种手法: 维护一个汇总量一遍扫 (max_reach / tank / end), 两遍扫描满足左右约束, 自定义排序。

概念链: Jump Game (max_reach) → Jump Game II (BFS 分层: cur_end / farthest) → Gas Station (tank < 0 就重置起点) → Stock II (所有上涨都吃) → Candy (两遍扫描) → Largest Number (自定义比较 a+b vs b+a) → Partition Labels (last occurrence 当边界)。

0. 第一性原理: greedy 在省什么, 什么时候不能用

Brute force 是'每一步试所有选择, 再看哪条路最好'。以 Jump Game 为例: 从 i 可以跳 1..nums[i] 步, DFS 把每个选择都走一遍, O(2^n); 加 memo 后 O(n^2)。它在浪费的是: 明明有些选择一定不会比另一个选择差, 却还要把它们都走完。

Greedy 的做法: 每一步只留下那个'一定不会更差'的选择, 其余直接丢掉, 于是不用分叉, 也不用记 dp 表, 往往 O(n) 或 O(n log n) (多出来的 log 来自排序)。关键不在于'选最大/最小', 而在于能说清楚为什么这一步选择不会错过全局最优。证明套路叫 exchange argument:

假设有一个最优解没用我这步选择。把它里面的某一部分换成我的选择, 如果换完不比原来差, 就说明'含我这步选择'的最优解一定存在, greedy 这一步安全。下图左边 (硬币 1/5/10/25) 换得动, 右边 (coins=[1,3,4]) 换不动, 这就是 greedy 和 DP 的分界线。

反例要用 DP 解 (试每一种最后一枚硬币, 不赌最大的):

def coin_change_dp(coins, amount): INF = float("inf") dp = [0] + [INF] * amount # dp[a] = 凑出 a 的最少枚数 for a in range(1, amount + 1): for c in coins: # 试每一种最后一枚, 而不是只赌最大的 if c <= a: dp[a] = min(dp[a], dp[a - c] + 1) return dp[amount] if dp[amount] < INF else -1

所以遇到'求最少/最多'的题: 先试着说一句 '最优解里一定可以含我这步选择, 因为换掉别的东西不会变差'。说得出来 → greedy; 举得出反例 → DP。面试里最稳的做法是: 先写 2-3 个小例子手算, 看 greedy 有没有被打脸。

通用模板 (本文每道题都是它的变体):

def greedy(items): items.sort(key=...) # 1) 有些题需要先排序 (Largest Number / interval 按 end) state = 初始值 # 2) 一个(或两个)汇总量: max_reach / tank / end ... for x in items: # 3) 一遍扫描, 每步只看 x 和 state, 不回头 做局部最优的选择, 更新 state return 答案

顺带: 区间题 (最多不重叠区间 / 射气球 / 合并) 的 greedy 是'按 end 排序再扫', 见 10 doc; 需要反复取当前最大/最小再做决定的 greedy (Task Scheduler, Reorganize String) 要配 heap, 见 09 doc。本文只讲不需要这两样的 greedy。

1. Jump Game: 只维护一个数 max_reach

题目: nums[i] 是在 i 最多能往前跳几步, 从 0 出发, 能否到最后一格? 例: [2,3,1,1,4] 可以, [3,2,1,0,4] 不行 (卡在下标 3 的 0)。

Brute force: DFS 或 DP, 对每个 i 试 1..nums[i] 种跳法, O(n^2)。浪费在: 能到 i 之后, 从 i 起跳的所有落点都要单独记一遍, 但其实只有'最远能到哪'才重要。

关键观察: 若 i 可达, 那么从 i 起跳能落到 i+1 ... i+nums[i] 任意一格, 没有洞。所以可达集合永远是前缀 [0, max_reach], 一个数就描述了全部状态。

def can_jump(nums): max_reach = 0 # invariant: 0..max_reach 全部可达 for i, step in enumerate(nums): if i > max_reach: # 连 i 都够不到 -> 后面全都够不到 return False max_reach = max(max_reach, i + step) # 从 i 起跳最远到 i + step return True

Time O(n) (一遍扫); Space O(1) (只有 max_reach)。

记:Jump Game = 扫描 + max_reach = max(max_reach, i + nums[i]);i > max_reach 就失败。

2. Jump Game II: 同一个 max_reach, 加上 BFS 分层

题目: 保证能到终点, 问最少跳几次。例: [2,3,1,1,4] → 2。相比上一题: 多出来的条件是'要数层数', 所以把 max_reach 拆成两个量: 当前层的边界 cur_end 和下一层的边界 farthest。

Brute force: BFS (每个下标是节点, i → i+1..i+nums[i] 是边), O(n^2) 条边。浪费在: 同一层里的下标跳出去的区间是连续、互相重叠的, 不需要逐个节点入队, 只要知道这一层最右能到哪。

关键观察: BFS 第 j 层 = 跳 j 步能到的下标区间 (连续)。扫当前层时用 farthest 收集'下一层最右到哪'; 扫到当前层末尾 (i == cur_end) 就是 BFS 换层, jumps += 1。

def jump(nums): jumps = 0 cur_end = 0 # 当前层 (跳 jumps 步能到的区间) 的右边界 farthest = 0 # 扫完当前层后, 下一层的右边界 for i in range(len(nums) - 1): # 最后一格不用再跳, 所以到 n-2 farthest = max(farthest, i + nums[i]) if i == cur_end: # 当前层扫完 -> 必须再跳一次 jumps += 1 cur_end = farthest # 下一层边界 = 这一层能到的最远处 return jumps # 题目保证一定能到终点

Time O(n); Space O(1)。和上一题相比只多了 cur_end 和 jumps 两个变量, 循环范围到 n-2 (最后一格不用再跳)。

记:Jump Game II = max_reach 拆成 cur_end (本层边界) + farthest (下一层边界);i == cur_end 时 jumps += 1。

3. Gas Station: 累计量变负, 就把起点重置到下一站

题目: 环形路, 站 i 加油 gas[i], 开到下一站耗 cost[i], 找出发点让你能绕一圈, 无解返回 -1。例: gas=[2,1,1,5,1,2], cost=[1,3,2,2,2,2] → 3。

Brute force: 每个起点模拟一圈, O(n^2)。浪费在: 起点 s 在 j 失败, 但我们对 s+1, s+2, ... 又重新模拟了一遍同样的路段。

关键观察 (两句话): (1) 从 s 出发在 j 失败, 则 s+1..j 作起点全部也失败: 从 s 走到那些站时 tank 都 ≥ 0 (否则早就在那之前失败了), 那笔'剩余油'相当于补贴, 换成从中途出发就没有这笔补贴, 只会更差。所以下一个候选直接跳到 j+1。(2) 如果 sum(gas) ≥ sum(cost), 一定有解, 且就是最后留下的 start。

def can_complete_circuit(gas, cost): total = 0 # 全局 sum(gas - cost), 决定有没有解 tank = 0 # 从 start 出发到现在的油量 start = 0 for i in range(len(gas)): net = gas[i] - cost[i] total += net tank += net if tank < 0: # start..i 任何起点都到不了 i+1 start = i + 1 # 下一个候选: 失败点的下一站 tank = 0 return start if total >= 0 else -1 # total >= 0 保证最后留下的 start 可行

Time O(n) (每个站只看一次); Space O(1)。注意 tank 会清零而 total 不会: tank 回答'从 start 出发能不能走到 i', total 回答'整圈够不够'。

记:Gas Station = 两个累计量:tank < 0 就 start = i+1 并清零;total ≥ 0 才有解。

4. Best Time to Buy and Sell Stock II: 所有上涨段都吃掉

题目: 可以买卖任意多次 (同一时刻最多持有一股), 求最大利润。例: [7,1,5,3,6,4] → 7 (买 1 卖 5, 买 3 卖 6)。

Brute force: 枚举所有买卖组合, 指数级 (DP 记录'持有/不持有'是 O(n), 但 greedy 更短)。浪费在: 想去找'真正的买点和卖点', 其实不用找。

关键观察: 任何一段上涨 a → b 都可以拆成逐日上涨的和 (b - a = (p1 - a) + (p2 - p1) + ...), 逐日上涨的收益和一次性买卖相同; 下跌的日子不碰就好。所以答案 = 所有正的 diff 之和。

def max_profit(prices): profit = 0 for i in range(1, len(prices)): diff = prices[i] - prices[i - 1] if diff > 0: # 每一段上涨都吃掉; 下跌段 = 空仓 profit += diff return profit

Time O(n); Space O(1)。对比 Stock I (只能买卖一次): 那题要维护 min_price, 不能把每段上涨都加起来。

记:Stock II = 相邻差为正就加进 profit,不需要找买卖点。

5. Candy: 两个方向的约束, 拆成两遍扫描

题目: 孩子排成一行, 每人至少 1 颗糖, rating 比邻居高的孩子要比该邻居多糖, 求最少总糖数。例: ratings=[1,0,2,3,1] → 9。

Brute force: 反复修补直到没有违反 (像 brute_candy 那样循环), 最坏 O(n^2)。一遍扫不行: 扫到 rating=0 的孩子, 它比左邻居低, 可是它要几颗糖取决于右边还没看到的孩子。

关键观察: 约束分成两种, 各自只依赖一边。'比左邻居高'只需要从左往右看一遍; '比右邻居高'只需要从右往左看一遍。每遍各自给出满足这类约束的最少糖数, 最后每个人取两者的 max, 两个约束就同时满足, 而且 max 已经是最小值。

def candy(ratings): n = len(ratings) left = [1] * n # left[i]: 只管左约束的最少糖 for i in range(1, n): if ratings[i] > ratings[i - 1]: left[i] = left[i - 1] + 1 right = [1] * n # right[i]: 只管右约束的最少糖 for i in range(n - 2, -1, -1): if ratings[i] > ratings[i + 1]: right[i] = right[i + 1] + 1 return sum(max(l, r) for l, r in zip(left, right)) # 两条约束同时满足

Time O(n) (三次线性扫描); Space O(n) (left 和 right)。另有 O(1) 空间的'上坡/下坡'写法, 面试用这个两遍版本即可。

记:Candy = 约束有左右两个方向:从左扫一遍、从右扫一遍,每格取 max。

6. Largest Number: 自定义排序, 比较 a+b 和 b+a

题目: 把非负整数列表拼成最大的数, 返回字符串。例: [3,30,34,5,9] → "9534330"。

Brute force: 枚举所有排列取最大, O(n! · n)。浪费在: 排列的好坏其实只由相邻两个谁在前决定, 不需要看整体。

关键观察: 对任意两个数 a, b, 只有两种拼法 a+b 和 b+a (字符串拼接), 谁大谁在前。这个比较关系可以传递, 所以直接用它当 comparator 排序即可。普通字典序会错: "3" 和 "30" 里 "30" 更大, 但 330 > 303。

from functools import cmp_to_keydef largest_number(nums): strs = [str(x) for x in nums] # a 排在 b 前面 <=> a+b > b+a (字符串拼接, 不是字典序) strs.sort(key=cmp_to_key(lambda a, b: -1 if a + b > b + a else 1)) res = "".join(strs) return "0" if res[0] == "0" else res # [0, 0] 这类全零要返回 "0"

Time O(n log n · L) (L 是数字位数, 每次比较拼接要 O(L)); Space O(n)。

记:Largest Number = 自定义 comparator:a 在前 ⇔ a+b > b+a;全零要返回 "0"。

7. Partition Labels: 用 last occurrence 当边界

题目: 把字符串切成尽量多的段, 使每个字母只出现在一段里, 返回每段长度。例: "abacbdefe" → [5,1,3]。

Brute force: 对每个切点检查'左右两边有没有共同字母', O(n^2) 或更差。浪费在: 每次都重新查集合, 其实一个字母'必须延伸到哪'是固定的, 就是它的最后一次出现。

关键观察: 当前这段里出现过的每个字母 c, 这段至少要延伸到 last[c]。所以 end = 段内所有字母 last 的最大值 (随扫描只增不减)。当 i == end 时, 段内所有字母都已出现完, 此刻切最早, 段数最多。这和 Jump Game II 是同一个形状: 一个只增不减的边界, 扫到边界就切。

def partition_labels(s): last = {c: i for i, c in enumerate(s)} # 每个字母最后一次出现的位置 res = [] start = end = 0 for i, c in enumerate(s): end = max(end, last[c]) # 这段至少要延伸到 c 的最后一次出现 if i == end: # 段内所有字母都已最后一次出现 -> 可以切 res.append(i - start + 1) start = i + 1 return res

Time O(n) (建 last 一遍, 扫描一遍); Space O(1) (字母表大小固定)。

记:Partition Labels = 先记每个字母的 last,再扫描 end = max(end, last[c]),i == end 就切。
