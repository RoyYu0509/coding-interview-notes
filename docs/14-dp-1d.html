14 · Dynamic Programming (1): 1D DP / Knapsack

这篇讲什么

DP (dynamic programming, 动态规划) 用来解决这样的问题: 一个大问题可以拆成几个更小的同类问题, 而且这些小问题会被反复用到。

最直接的写法是 recursion: 大问题调用小问题, 小问题再调用更小的。问题是同一个小问题会被算很多很多遍, 时间是指数级的。DP 的想法很简单: 每个小问题只算一次, 把答案存起来, 下次直接用。

所有 DP 题都按同样的四步来想:

  1. state: dp[i] 表示什么? (一定要用一句话说清楚)
  2. transition: dp[i] 怎么由更小的 dp 算出来? 通常是想"最后一步做了什么"。
  3. base case: 最小的那几个 dp 是多少?
  4. 计算顺序: 从小往大填, 保证用到的值都已经算好。

这篇讲 1D DP: state 只需要一个下标 (第 i 个位置、金额 a、容量 c)。需要两个下标的 (两个字符串、grid) 在 15。

1. Climbing Stairs

题目在问什么

要爬 n 级台阶, 每次可以爬 1 级或者 2 级。问: 爬到顶一共有多少种不同的方法? 顺序不同算不同的方法。

看例子

Brute force: recursion

想"最后一步": 到达第 n 级, 最后一步要么是从第 n-1 级爬 1 级上来, 要么是从第 n-2 级爬 2 级上来。所以 ways(n) = ways(n-1) + ways(n-2)。

直接写成 recursion 是对的, 但是很慢。画出 recursion tree 就能看到原因:

ways(3) 被算了 2 次, ways(2) 被算了 3 次……n 越大, 重复越多, 时间是 O(2ⁿ)。

Intuition: 每个子问题只算一次

有两种办法消掉重复:

  • memoization (top-down): recursion 不变, 只是第一次算完 ways(i) 就存进 dict, 下次直接返回。Python 里加一行 @cache。
  • tabulation (bottom-up): 不用 recursion, 直接从小到大填一个数组: dp[0], dp[1], dp[2], ..., 每一格只用到前面已经填好的格子。

再进一步: 填 dp[i] 只需要前两格, 更早的格子再也用不到了。所以不需要整个数组, 两个变量滚动就够了, 空间从 O(n) 降到 O(1)。

用四步来说: state dp[i] = 爬到第 i 级的方法数; transition dp[i] = dp[i-1] + dp[i-2]; base case dp[0] = 1, dp[1] = 1; 顺序是 i 从小到大。

算法

  1. a, b = 1, 1 (分别是 dp[i-2] 和 dp[i-1])。
  2. 循环 n - 1 次: a, b = b, a + b。
  3. 返回 b。

复杂度

Time O(n), Space O(1)。

记:DP = recursion + 不重复算。先写出"最后一步"的 recursion, 再加 memo 或改成从小到大填表; 只依赖前几格就用变量滚动。

把第 1 题抽象一下: 怎么想 DP

第 1 题的思路可以用在所有 DP 题上:

  1. 先写出 brute force 的 recursion, 想清楚"最后一步有哪几种选择"。每种选择会留下一个更小的问题。
  2. 看 recursion 的参数: 有几个参数在变, dp 就是几维的。这篇都是一个参数。
  3. 把 recursion 改成从小到大填表。

state 常见的三种形状: 前 i 个 (第 1、2、10 题)、以 i 结尾 (第 4、5、11 题)、金额 / 容量 (第 7、8、9 题)。看到一道新题, 先试这三种。

记:DP 四步: state (dp[i] 是什么) / transition (最后一步) / base case / 计算顺序。

2. House Robber

题目在问什么

一排房子, nums[i] 是第 i 间里的钱。不能偷相邻的两间 (会触发警报)。问最多能偷多少钱。

看例子

Example 2 说明, 每次挑最大的 (贪心) 是不对的。

Brute force

每间房子偷或不偷, 枚举所有不相邻的组合, O(2ⁿ)。

Intuition: 最后一间偷不偷

看前 i 间房子 (0 到 i), 只考虑最后一间 i:

  • 不偷 i: 那就是前 i-1 间能偷的最多, 也就是 dp[i-1]。
  • 偷 i: 那 i-1 就不能偷, 只能加上前 i-2 间的最多: dp[i-2] + nums[i]。

两个里取大的: dp[i] = max(dp[i-1], dp[i-2] + nums[i])。

这就是 DP 里最常见的"选 / 不选"结构。又是只依赖前两格, 可以两个变量滚动。

算法

  1. prev2 = prev1 = 0。
  2. 对每个 x: prev2, prev1 = prev1, max(prev1, prev2 + x)。
  3. 返回 prev1。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def rob(nums): # dp[i] = 只看 nums[0..i] 时能偷到的最大金额 # dp[i] = max(dp[i-1], 不偷 i: 直接继承 # dp[i-2] + nums[i]) 偷 i: i-1 不能偷, 接在 dp[i-2] 后面 # dp[i-2], dp[i-1]; 把 dp[-2] = dp[-1] = 0 当 base prev2, prev1 = 0, 0 for x in nums: prev2, prev1 = prev1, max(prev1, prev2 + x) return prev1

记:每个元素"选 / 不选", 而且选了会影响邻居: dp[i] = max(不选, 选 + 前面能接上的)。

3. House Robber II

题目在问什么

和第 2 题一样, 但房子围成一圈: 第一间和最后一间也算相邻。

看例子

Intuition: 把环拆成两条线

首尾不能同时偷。那就分两种情况: 不偷最后一间 (只看 nums[0..n-2]), 或者不偷第一间 (只看 nums[1..n-1])。每种情况都是一条线, 直接用第 2 题。答案是两者里大的。

只有一间房子时要特判, 直接返回 nums[0]。

算法

  1. n == 1 返回 nums[0]。

4. Maximum Subarray (Kadane)

题目在问什么

找一段连续的 subarray (至少包含一个数), 让它的和最大。

看例子

Brute force

枚举所有 (起点, 终点), 用 prefix sum 算和, O(n²)。

Intuition: state 换成"以 i 结尾"

如果用"前 i 个数里的最大 subarray"当 state, 很难写 transition: 不知道最好的那段在哪, 新加的 nums[i] 能不能接上去。

换一个 state: cur[i] = 必须以 i 结尾的 subarray 里, 最大的和。这样 transition 就很清楚了。以 i 结尾的 subarray 只有两种:

  • 接在前面: 以 i-1 结尾的最好的那段, 再加上 nums[i]: cur[i-1] + nums[i]。
  • 从 i 重新开始: 只有 nums[i] 自己。

cur[i] = max(cur[i-1] + nums[i], nums[i])。直觉: 前面那段的和如果是负的, 接上它只会拖后腿, 不如重新开始。

最终答案是所有 cur[i] 里最大的, 因为最好的那段总要在某个位置结尾。

算法

  1. cur = best = nums[0]。
  2. 对后面每个 x: cur = max(cur + x, x), best = max(best, cur)。
  3. 返回 best。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def maxSubArray(nums): # cur = 以 nums[i] 结尾 的最大 subarray sum cur = best = nums[0] for x in nums[1:]: # 重新开始 (只取 x), 或接在 cur 后面; cur < 0 时重开更好 cur = max(x, cur + x) # 最优 subarray 一定在某个 i 结束 -> 答案是所有 cur 的最大值 best = max(best, cur) return best

记:连续 subarray 的最值: state 用"以 i 结尾", 选择是"接上前面"还是"从这里重新开始"。答案是所有 i 里最大的。

5. Maximum Product Subarray

题目在问什么

找一段连续的 subarray, 让它的乘积最大。

看例子

Brute force

枚举所有 (起点, 终点), O(n²)。

Intuition: 负数会把最小的变成最大的

先试试照搬第 4 题: mx[i] = max(mx[i-1] × nums[i], nums[i])。在 Example 2 里会出错: 到 -4 时, 前面最好的是 3, 3 × (-4) = -12, 可是真正的答案是 (-2) × 3 × (-4) = 24。

问题在于, 乘一个负数会让大小颠倒: 前面最小的那个 (-6, 一个很负的数), 乘上 -4 反而变成最大。

所以要同时记住以 i 结尾的最大乘积 mx 和最小乘积 mn。新的 mx 和 mn 都从这三个候选里选: nums[i]、mx × nums[i]、mn × nums[i]。

算法

  1. mx = mn = best = nums[0]。
  2. 对后面每个 x: 三个候选 (x, mx·x, mn·x), mx = max(...), mn = min(...) (要用更新前的 mx 和 mn)。best = max(best, mx)。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def maxProduct(nums): # mx / mn = 以 nums[i] 结尾的最大 / 最小 product mx = mn = best = nums[0] for x in nums[1:]: # 重开, 接在 max 后, 接在 min 后 (x < 0 时 min 乘 x 会变 max) cands = (x, mx * x, mn * x) # 两个都用 旧的 mx, mn 算, 所以先算 cands mx, mn = max(cands), min(cands) best = max(best, mx) return best

记:乘法 / 符号会翻转的问题: 同时记最大和最小两个 state。

6. Best Time to Buy and Sell Stock

题目在问什么

prices[i] 是第 i 天的股价。选某一天买, 之后的某一天卖, 只交易一次。最大利润是多少? 赚不到钱就返回 0。

看例子

Brute force

枚举所有 (买入日, 卖出日), 买入在前。O(n²)。

Intuition: 固定卖出日, 最好的买入日就是之前的最低价

假设第 i 天卖。要让利润最大, 买入价越低越好, 而且必须在 i 之前。所以最好的买入价就是 prices[0..i-1] 里的最小值。

从左往右扫, 一边走一边记录"到目前为止的最低价" lo。每一天算一下"今天卖能赚多少" (prices[i] - lo), 取最大值。

也可以看成一个两状态的 DP: 每天结束时, 要么手里有股票 (hold), 要么没有 (cash)。hold = max(hold, -price) (继续拿着, 或者今天买); cash = max(cash, hold + price) (继续空仓, 或者今天卖)。这个写法能推广到可以交易多次、有冷却期、有手续费的变体。

算法

  1. lo = inf, best = 0。
  2. 每个 p: lo = min(lo, p), best = max(best, p - lo)。

手动走一遍

复杂度

Time O(n), Space O(1)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def maxProfit(prices): # lo = 到目前为止的最低价, best = 到目前为止的最大利润 lo, best = prices[0], 0 for p in prices[1:]: # 今天卖: 最佳买入日 = 之前的最低价, 不用再扫描 best = max(best, p - lo) lo = min(lo, p) return best
def maxProfit_sm(prices): # hold: 手上有股票时的最大利润; cash: 没有股票时的最大利润 hold, cash = -prices[0], 0 for p in prices[1:]: # 继续拿着, 或今天买入 (只能买一次, 所以是 -p) hold = max(hold, -p) cash = max(cash, hold + p) # 继续空仓, 或今天卖出 return cash

记:"之前的某一个" + "现在": 边扫边维护之前的最优 (最小值), 每一步 O(1) 更新答案。股票变体用 hold / cash 状态机。

7. Coin Change

题目在问什么

coins 是几种硬币的面额, 每种都有无限多个。要凑出总金额 amount, 最少要用几枚硬币? 凑不出来返回 -1。

看例子

Example 3 说明贪心 (每次拿最大的面额) 不一定对。

Brute force

recursion: 凑 amount, 最后一枚可以是任何一种硬币 c, 剩下要凑 amount - c。试所有 c, 取最少的。没有 memo 的话, 同一个剩余金额会被算很多次, 指数级。

Intuition: state 是金额

recursion 里唯一在变的参数是"还要凑多少钱", 所以 state 就是金额: dp[a] = 凑出金额 a 最少要几枚。

transition 还是想最后一枚: 最后一枚是 c, 那之前要凑出 a - c, 最少 dp[a - c] 枚。dp[a] = min(dp[a - c] + 1), 对所有 c ≤ a 取最小。

base case: dp[0] = 0 (凑 0 元不用硬币)。其他先设成无穷大, 表示还凑不出。从 a = 1 往上填。

这类"每种东西可以用无限次, 凑出某个总量"的问题, 叫 unbounded knapsack (完全背包)。

算法

  1. dp = [0] + [inf] * amount。
  2. a 从 1 到 amount: 对每个 c ≤ a: dp[a] = min(dp[a], dp[a - c] + 1)。
  3. 返回 dp[amount], 如果是 inf 就返回 -1。

手动走一遍

复杂度

Time O(amount × 硬币种类), Space O(amount)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def coinChange(coins, amount): INF = float("inf") # dp[a] = 凑出 a 最少要几枚; dp[0] = 0, 其余先当不可达 dp = [0] + [INF] * amount for a in range(1, amount + 1): # 计算顺序: a 从小到大 for c in coins: # 枚举 "最后一枚" 是哪种 coin if c <= a: dp[a] = min(dp[a], dp[a - c] + 1) return dp[amount] if dp[amount] != INF else -1

记:凑出某个总量, 每种可用无限次, 求最少 / 最多: dp[a] = 最优 (dp[a - c] + 1)。贪心不一定对时就想 DP。

8. Coin Change II

题目在问什么

同样每种硬币无限多个。这次问: 凑出 amount 一共有多少种组合? 组合不看顺序, 1+2 和 2+1 算同一种。

看例子

Brute force

recursion 枚举所有组合。和 13 的 Combination Sum 一样, 用 start index 防止重复。

Intuition: 外层循环硬币, 内层循环金额

先试试照搬第 7 题: dp[a] = sum(dp[a - c]), 外层循环 a, 内层循环 c。这样算出来的是排列的个数, 1+2 和 2+1 被算成两种: 填 dp[3] 时, "最后一枚是 2" 包含了 1+2, "最后一枚是 1" 包含了 2+1。

要算组合, 就要规定硬币的使用顺序, 比如"先决定用几个 1, 再决定用几个 2, ……"。写成循环就是: 外层循环硬币, 内层循环金额。处理硬币 c 的时候, dp 里只包含用前面那些硬币的组合, 所以 2 永远出现在 1 之后, 不会有 2+1 这种顺序。

dp[a] = 用目前处理过的硬币, 凑出 a 的组合数。处理硬币 c 时: dp[a] += dp[a - c]。base case dp[0] = 1 (凑 0 元有一种: 什么都不拿)。

算法

  1. dp = [1] + [0] * amount。
  2. 对每个 c (外层): a 从 c 到 amount (内层, 正序): dp[a] += dp[a - c]。
  3. 返回 dp[amount]。

手动走一遍

复杂度

Time O(amount × 硬币种类), Space O(amount)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def change(amount, coins): # dp[a] = 凑出 a 的组合数; dp[0] = 1 (什么都不拿算 1 种) dp = [1] + [0] * amount # 外层 coin: 每种 coin 只 "加入" 一次 -> 组合不分顺序 for c in coins: # 内层 正序: 同一种 coin 可以重复用 (unbounded) for a in range(c, amount + 1): # 凑 a = (不用 c 的旧 dp[a]) + (至少用一枚 c: dp[a-c]) dp[a] += dp[a - c] return dp[amount]

记:数组合 (不看顺序): 外层循环物品, 内层循环金额。数排列 (看顺序): 外层金额, 内层物品。

9. Partition Equal Subset Sum

题目在问什么

给一个正整数数组。能不能把它分成两组, 让两组的和相等? 每个数只能放进其中一组。

看例子

Brute force

每个数放第一组或第二组, O(2ⁿ)。

Intuition: 变成"能不能凑出 total / 2"

两组的和相等, 每组都是 total / 2。所以问题等价于: 能不能从数组里选一些数, 和正好是 target = total / 2? (total 是奇数就直接 False。)

这和第 7、8 题很像, 区别是每个数只能用一次。这叫 0/1 knapsack。

dp[c] = 用目前处理过的数, 能不能凑出 c。处理数 x 时: dp[c] = dp[c] or dp[c - x] (不用 x, 或者用 x)。

关键细节: 内层循环 c 要从大到小。为什么? 如果从小到大, 算 dp[c] 时读的 dp[c - x] 可能已经是这一轮刚更新过的, 也就是"已经用过 x 了", 再用一次就成了同一个数用两次。从大到小的话, dp[c - x] 一定还是上一轮的值 (没用 x)。

对比第 8 题: 那里每种硬币可以用无限次, 所以正好要从小到大 (允许重复用)。

算法

  1. total 是奇数返回 False。target = total // 2, dp = [True] + [False] * target。
  2. 对每个 x: c 从 target 倒着到 x: dp[c] = dp[c] or dp[c - x]。
  3. 返回 dp[target]。

手动走一遍

复杂度

Time O(n × target), Space O(target)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def canPartition(nums): total = sum(nums) if total % 2: # 总和是奇数, 不可能平分 return False # 问题变成: 能不能挑出一些数, 和恰好 = target target = total // 2 dp = [True] + [False] * target # dp[c] = 当前处理过的数里, 能不能凑出和 c for x in nums: # 外层 每个数; 每个数只能用一次 (0/1) # 倒序! dp[c - x] 还是 "没用 x" 的旧值 for c in range(target, x - 1, -1): dp[c] = dp[c] or dp[c - x] return dp[target]

记:每个物品只能用一次 (0/1 knapsack): 一维 dp 时容量要倒序遍历。能用无限次 (unbounded): 正序。

10. Word Break

题目在问什么

给一个字符串 s 和一个字典 wordDict。能不能把 s 切成若干段, 每一段都是字典里的词? 字典里的词可以重复使用。

看例子

Brute force

recursion: 试所有可能的第一段 (是字典里的词), 对剩下的部分递归。没有 memo 时, 同一个后缀会被反复检查, 最坏指数级。

Intuition: dp[i] = 前 i 个字符能不能切

state: dp[i] = s[:i] (前 i 个字符) 能不能被完整地切分。

transition 想最后一段: 如果最后一段是 s[j:i], 那它必须在字典里, 并且前面的 s[:j] 也必须能切, 也就是 dp[j] 为 True。试所有 j, 有一个满足就行。

base case: dp[0] = True (空字符串什么都不用切)。

算法

  1. words = set(wordDict), dp = [True] + [False] * n。
  2. i 从 1 到 n: 对每个 j < i: 如果 dp[j] 并且 s[j:i] in words, dp[i] = True, break。
  3. 返回 dp[n]。

手动走一遍

复杂度

Time O(n² · L) (切字符串和查表要 O(L)), 可以只试长度不超过最长单词的 j 来加速。Space O(n)。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def wordBreak(s, wordDict): # set: 查 s[j:i] 在不在词典里是 O(1) (hash 要 O(长度)) words = set(wordDict) n = len(s) # dp[i] = s 的前 i 个字符 s[:i] 能不能切成词典里的词; dp[0] = 空串 = True dp = [True] + [False] * n for i in range(1, n + 1): for j in range(i): # 枚举 "最后一个词" s[j:i] 从哪里开始 # 前面 s[:j] 能切, 最后一块也是词 if dp[j] and s[j:i] in words: dp[i] = True break # 一种切法就够了 return dp[n]

记:字符串能不能切成合法的段: dp[i] = 前 i 个能不能切, 试最后一段 s[j:i]。

11. Longest Increasing Subsequence

题目在问什么

找最长的严格递增 subsequence 的长度。subsequence (子序列) 可以跳着选元素, 但不能改变它们的先后顺序。

看例子

Brute force

枚举所有子序列 (每个元素选或不选), 检查是否递增。O(2ⁿ · n)。

Intuition: 以 i 结尾, 往回看所有能接上的 j

和第 4 题一样, 用"以 i 结尾"当 state: dp[i] = 以 nums[i] 结尾的最长递增子序列的长度。

以 nums[i] 结尾的递增子序列, 它前一个元素可以是 i 前面任何一个比 nums[i] 小的 nums[j]。接在它后面, 长度是 dp[j] + 1。所以 dp[i] = 1 + max(dp[j]), 对所有 j < i 且 nums[j] < nums[i]。没有这样的 j 就是 1。

和第 4 题的区别: Kadane 只看前一个 (因为要连续), 这里要看前面所有的 j (因为可以跳着选), 所以是 O(n²)。

答案是所有 dp[i] 里最大的。

算法

  1. dp = [1] * n。
  2. i 从 0 到 n-1, j 从 0 到 i-1: 如果 nums[j] < nums[i], dp[i] = max(dp[i], dp[j] + 1)。
  3. 返回 max(dp)。

手动走一遍

复杂度

Time O(n²), Space O(n)。另有 O(n log n) 的做法 (维护一个 tails 数组 + 二分), 代码里附上了, 面试能说出 O(n²) 的 DP 一般就够了。

参考代码 (先自己按上面的算法步骤写, 写不出来再展开)
def lengthOfLIS(nums): # dp[i] = 以 nums[i] 结尾 的最长递增子序列长度; 至少是它自己 dp = [1] * len(nums) for i in range(len(nums)): for j in range(i): # 往回看所有 j < i if nums[j] < nums[i]: # nums[i] 可以接在 nums[j] 后面 dp[i] = max(dp[i], dp[j] + 1) # 不一定以最后一个结尾 -> 取所有 dp 的最大值 return max(dp)
from bisect import bisect_leftdef lengthOfLIS_fast(nums): # tails[k] = 长度为 k+1 的递增子序列里, 最小的结尾值 (tails 恒递增) tails = [] for x in nums: # 第一个 >= x 的位置: x 能接在 tails[k-1] 后面, 同时把 tails[k] 压得更 # 小 k = bisect_left(tails, x) if k == len(tails): tails.append(x) else: tails[k] = x return len(tails)

记:子序列 (可以跳着选) 的最优: 以 i 结尾, 往回看所有能接上的 j, O(n²)。

12. 识别信号: 看到什么, 就想到 DP

题目特征statetransition
"有多少种方法" 走到第 n 步dp[i] = 到 i 的方法数dp[i-1] + dp[i-2] (最后一步的几种选择)
每个元素选或不选, 选了影响邻居dp[i] = 前 i 个的最优max(dp[i-1], dp[i-2] + x)
环形拆成两条线两次线性 DP
连续 subarray 的最大和 / 积以 i 结尾接上前面, 或重新开始; 乘法要同时记 max 和 min
买卖股票到目前的最小值, 或 hold / cash每天更新
凑总量, 无限次使用, 求最少dp[a] = 凑出 a 的最少个数min(dp[a - c] + 1)
凑总量, 求组合个数dp[a]外层物品, 内层金额 (正序)
每个物品只能用一次, 能不能凑出dp[c]容量倒序: dp[c] or dp[c - x]
字符串能不能切成合法的段dp[i] = 前 i 个试最后一段 s[j:i]
最长递增子序列 (可以跳着选)以 i 结尾往回看所有 j < i

什么时候想到 DP: 题目问最多 / 最少 / 有多少种 / 能不能, 而 brute force 的 recursion 里有重复的子问题。如果题目要的是"列出所有方案", 那是 backtracking (13), 不是 DP。

贪心看起来可以但不确定时, 找一个反例 (比如 Coin Change 的 [1,3,4], amount = 6), 贪心错了就用 DP。
